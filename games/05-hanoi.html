Game 05 · Tower of Hanoi

河內塔

三根柱子、n 個盤子，大的不能壓在小的上面。這一題同時出現兩種堆疊 —— 柱子本身就是堆疊（只能動最上面那個），而解法靠的是呼叫堆疊。先自己動手玩，再看它為什麼一定要 2ⁿ−1 步。

01

怎麼玩・你會學到什麼

先自己玩到會，再看電腦怎麼想。順序不要顛倒。

怎麼玩

  1. 選盤子數（先從 3 開始）。
  2. 點一下某根柱子 → 拿起它最上面的盤子。
  3. 再點另一根柱子 → 放下去。放不下會告訴你為什麼。
  4. 目標：把所有盤子搬到右柱。
  5. 卡住了按 提示，它會告訴你最佳解的下一步是什麼。
  6. 玩過一輪之後，按 自動示範 看電腦用遞迴算出來的解，並對照自己走的路。
先別看提示 3 個盤子請務必自己解一次。你會親身經歷「要把最大的搬過去，得先把上面全部挪開」這個卡點 —— 這個卡點就是第 03 段三步法的全部內容。先體驗，再看解釋，效果差很多。

你會學到什麼

  • 柱子就是堆疊 —— 「只能拿最上面的」這句規則，就是 LIFO 的定義。
  • 遞迴的三步法 —— 不要想第一步搬哪個，要想「假設 n−1 個已經會搬」。
  • 數學歸納法 = 遞迴 —— 你只負責定義這一層怎麼拆，剩下交給更小的自己。
  • 為什麼三步法一定合法 —— 搬最大盤子時，目標柱必定是空的。
  • 2ⁿ−1 怎麼推出來 —— 從遞迴式 T(n) = 2T(n−1) + 1 展開。
  • 指數成長有多可怕 —— 64 個金盤要 5850 億年。
  • 最佳解無法再優化 —— 因為答案本身就有 2ⁿ−1 步，這不是演算法慢，是題目大。

    整份程式逐行白話說明（寫給完全沒學過程式的你）
      規則 ① 一次只能搬一個盤子。② 只能搬每根柱子最上面的盤子。③ 任何時候都不能把大盤壓在小盤上。④ 目標是用 2ⁿ−1 步完成。

      這個遊戲跑的程式（完整版）

      #include <cstdio>

void hanoi(int n, char a = 'A', char c = 'C', char b = 'B') {
    if (n == 0) return;                    // 基底條件：沒有盤子要搬
    hanoi(n - 1, a, b, c);                 // 上面 n-1 個先搬去中繼柱
    printf("盤子 %d: %c → %c\n", n, a, c);  // 最大的搬過去
    hanoi(n - 1, b, c, a);                 // 中繼柱那疊再搬回來蓋上
}

int main() { hanoi(3); }
// 盤子 1: A → C
// 盤子 2: A → B
// 盤子 1: C → B
// 盤子 3: A → C
// 盤子 1: B → A
// 盤子 2: B → C
// 盤子 1: A → C

      演算法本體只有五行。這一頁其餘幾百行全部都是為了「讓你看得見、摸得到」。

      03

      這個功能是怎麼做到的

      從「不要想第一步」開始。

      問題定義

      三根柱子 A、B、C，n 個大小不同的盤子一開始由大到小疊在 A 上。把它們全部搬到 C，規則如上。求一個合法的搬法，最好是步數最少的。

      先注意這件事 規則第 ② 條「只能搬最上面的盤子」，其實就是在說：每根柱子都是一個堆疊。你只能 push 和 pop，不能伸手去中間抽一個。整題的限制就是這個限制。

      為什麼直覺會卡住

      大部分人第一個念頭是「第一步該搬哪個盤子？」—— 然後就卡死了，因為第一步的選擇看起來完全沒有理由。

      換個問法就通了：「最大的那個盤子，什麼時候才能搬？」

      • 它要從 A 搬到 C，所以它上面必須沒有任何東西。
      • 而且 C 必須是空的（不然它會壓到別人）。
      • 所以在那一刻，其他 n−1 個盤子全部都得在 B 上。
      於是 整個問題被逼出了唯一的形狀：先把 n−1 個搬到 B，再搬最大的到 C，再把 n−1 個從 B 搬到 C。

      三步法

      不要試著想細節。假設 hanoi(n−1) 已經有人幫你做好了，那 n 個盤子的解法必然是這三步：

      1. 把上面 n−1 個從 A 搬到中繼柱 B（借 C 當中繼）→ hanoi(n−1, A, B, C)
      2. 把最大的第 n 個從 A 直接搬到 C → 一步，這是唯一真正搬盤子的地方
      3. 把 B 上的 n−1 個搬到 C（借 A 當中繼）→ hanoi(n−1, B, C, A)
      void hanoi(int n, char a, char c, char b) {  // 把 n 個盤子從 a 移到 c，b 當中繼
    if (n == 0) return;          // 基底條件
    hanoi(n - 1, a, b, c);       // 第一步
    printf("盤子 %d: %c → %c\n", n, a, c);   // 第二步
    hanoi(n - 1, b, c, a);       // 第三步
}

      整個解法就是這四行。沒有任何「判斷該搬哪個」的邏輯 —— 因為根本不需要判斷。

      兩個為什麼

      為什麼一定合法？

      第 2 步搬的是最大的盤子。此時 C 是空的（n−1 個都在 B），A 上除了它也沒別的。既然它最大，放到空柱子上不可能壓到誰 —— 不可能違反規則。

      為什麼可以假設 n−1 個已經會搬？

      這就是數學歸納法，也是遞迴的本質：n=0 顯然會（什麼都不用做），而如果 n−1 會，上面三步就證明了 n 也會。你只負責定義這一層怎麼拆。

      手算一次 n = 3 的七步

      步搬什麼屬於三步法的哪一步ABC
      —初始—3 2 1——
      1盤1 A→C把 2 個搬到 B 的過程3 2—1
      2盤2 A→B把 2 個搬到 B 的過程321
      3盤1 C→B把 2 個搬到 B　完成32 1—
      4盤3 A→C第二步：搬最大的—2 13
      5盤1 B→A把 2 個搬到 C 的過程123
      6盤2 B→C把 2 個搬到 C 的過程1—3 2
      7盤1 A→C把 2 個搬到 C　完成——3 2 1

      注意第 4 步剛好卡在正中間，把七步切成 3 + 1 + 3。這個對稱結構在任何 n 都成立：(2ⁿ⁻¹−1) + 1 + (2ⁿ⁻¹−1) = 2ⁿ−1。

      最少步數怎麼推

      # 三步法裡只有第 2 步真的搬一片盤子
T(n) = 2·T(n-1) + 1       # 兩次 n-1 的搬移，加上中間那一步
T(0) = 0

# 展開：
T(n) = 2·T(n-1) + 1
     = 4·T(n-2) + 2 + 1
     = 8·T(n-3) + 4 + 2 + 1
     = 2^k·T(n-k) + (2^k - 1)
     = 2^n·T(0) + 2^n - 1  =  2^n - 1   # 令 k = n
      n最少步數 2ⁿ−1一秒搬一個要多久
      377 秒
      101,02317 分鐘
      201,048,57512 天
      30約 10.7 億34 年
      64約 1.8 × 10¹⁹5850 億年

      傳說中梵天廟裡的 64 個金盤搬完世界就會毀滅 —— 從這張表看，暫時不用擔心。

      一個關於複雜度的重要區別

      別搞混 河內塔是 O(2ⁿ)，但這不代表演算法很爛。

      答案本身就有 2ⁿ−1 步 —— 你光是把答案印出來就要 2ⁿ−1 行。這叫輸出敏感：再聰明的演算法也不可能更快，因為它至少得把每一步講出來。

      這跟 04 的費氏數列完全不同。費氏的 O(2ⁿ) 是白費力氣（重複算同樣的東西），加個 memo 就降到 O(n)。河內塔的 O(2ⁿ) 是必要的，無法優化。

      看到指數複雜度時，先問一句：是演算法笨，還是答案本來就這麼大？

      最佳解的另一個看法：不用遞迴也能走

      最佳解其實有一個機械式的走法，完全不用想：

      • 奇數步永遠搬最小的盤子，而且方向固定 —— n 是奇數時循環 A→C→B→A，n 是偶數時循環 A→B→C→A。
      • 偶數步只有一個合法的搬法（不動最小盤的那個），照做就對了。

      照這個規則走出來的，就是那 2ⁿ−1 步的最佳解。你可以在上面的遊戲裡驗證：最小的盤子每兩步就動一次，而且一直往同一個方向繞。

      這是遞迴解的另一面 —— 同一個答案，一個從「怎麼拆問題」看，一個從「觀察結果的規律」看。

      常見誤解

      • 「要想清楚第一步搬哪個」 —— 反了。想「最大的那個什麼時候才能搬」，答案自己會浮出來。
      • 「遞迴只是把問題丟給別人，沒有真的解決」 —— 它真的解決了，因為每次都更小，最後一定碰到 n=0 這個不用做事的基底。
      • 「這題可以用貪心法」 —— 不行。任何「每一步選看起來最好的」策略都會卡死，因為有些步驟看起來是在倒退（把盤子搬回 A）卻是必要的。
      • 「O(2ⁿ) 就是爛演算法」 —— 這題不是。答案本身就有 2ⁿ−1 步，這是下限，不是缺點。
      • 「四根柱子也是 2ⁿ−1」 —— 不是。四根柱子的最少步數（Frame–Stewart 問題）少很多，而且到今天都還沒有被完整證明。
      04

      程式架構與說明

      只講流程與分工，不逐行拆解。

      整體設計：玩家模式與示範模式共用同一個狀態

      這一頁跟前面幾頁不一樣 —— 它同時是遊戲也是演示。兩種模式都改動同一份資料：

      玩家點兩下柱子　／　自動示範的計時器
      tryMove(from, to) 唯一能改動盤子的入口，規則檢查也在這裡
      towers[3] 三個陣列，就是三個堆疊
      render()
      為什麼共用 自動示範不是播放預錄的動畫，它是真的一步一步呼叫 tryMove() —— 跟玩家點滑鼠走的是同一條路。所以如果遞迴算出了不合法的一步，畫面會當場出錯。這等於是演算法的即時驗證。

      三個柱子就是三個堆疊

      towers = [[3,2,1], [], []]   # 每個陣列的「最後一個元素」就是最上面的盤子

# 拿起最上面的：
disk = towers[from].pop()          # ← 這就是 pop

# 放下去：
towers[to].push(disk)              # ← 這就是 push

      整個遊戲的資料結構就這樣。「只能動最上面」這條規則不需要另外寫程式碼強制 —— 只要規定自己只能用 pop() 和 push()，規則就自動被遵守了。

      選對結構的價值 這是「選對資料結構，一半的規則就免費了」最直接的例子。剩下要自己檢查的只有一條：大不能壓小。

      模組分工

      層主要函式負責什麼
      狀態towers / moves / picked三個堆疊、步數、目前拿起的是哪一柱。
      規則tryMove(from, to)唯一的改動入口。檢查來源非空、目標頂端比較大，然後 pop + push。
      互動clickTower(i)第一下記住來源，第二下呼叫 tryMove。再點同一柱等於放棄。
      最佳解solve(n,a,c,b)用遞迴算出完整的最佳步驟清單。提示和自動示範都吃它。
      畫面render()把三個陣列畫成三疊盤子，寬度由盤子大小決定。

      「提示」是怎麼做到的

      提示功能有一個看似簡單、實際很關鍵的問題：玩家亂走之後，最佳解的清單就對不上了，不能只是報第 k 步。

      本頁的做法很直接：從目前這個盤面重新算一次。因為河內塔的最佳解只跟「盤面長什麼樣」有關，跟你怎麼走到這裡無關 —— 這叫無記憶性。

      # 從任意合法盤面求下一步：由大到小逐一決定每個盤子「該去哪」
nextMove(towers, n):              # 虛擬碼
    # 目標：把第 n 個盤子搬到 target 柱
    # 若它已經在 target → 問題縮小成 n-1，繼續往下看
    # 若不在 → 先把上面 n-1 個清到「第三根柱子」，所以
    #          真正的下一步藏在「搬 n-1 個到 other」這個子問題裡

      這段程式碼比遞迴解本身還難寫一點，因為它要處理「任意盤面」而不只是初始盤面 —— 但它讓提示在玩家走錯之後仍然有用，這對教學很重要。

      畫面：盤子的寬度就是它的大小

      盤子的寬度用 基準寬 + 編號 × 級距 算出來，而不是寫死五種尺寸。好處是盤子數改成 6、7 也不用改 CSS，顏色同理（用色相環均勻取樣）。

      柱子中間那根桿子是 ::before 畫的一條長方形，用 z-index 壓在盤子後面。盤子用 flex-direction: column-reverse 由下往上堆 —— 跟這個站上所有堆疊的畫法一致。

      你可以怎麼改

      想做的事改哪裡
      放寬盤子數上限HTML 的 <select> 加選項。7 個以上會需要 127 步，畫面還撐得住
      加「上一步」功能把每次 tryMove 的 (from, to) 存進一個陣列，倒著執行即可
      加計時器 / 排行榜用 localStorage 存最佳成績
      做成四根柱子資料改成 towers[4] 很容易，但最佳解演算法完全不同（Frame–Stewart）
