先搞懂：堆積排序（Heap Sort）到底是什麼

定義：堆積排序（Heap Sort）

DEFINITION · 堆積排序 Heap Sort
堆積排序是一種排序方法：先把整個陣列整理成最大堆積（Max-Heap），然後一直重複「把堆頂（目前最大值）跟堆積區的最後一格交換、堆積區縮小一格、把新的堆頂下沉」，直到堆積區只剩一個數。

做完之後，陣列會由小到大排好。整個過程都在同一個陣列裡完成，不用另外準備第二個陣列。

同一個定義，換個說法內容
白話每一輪找出「還沒排的數字裡最大的那個」，把它放到最右邊還空著的位置。找最大值靠 Max-Heap，所以很快。
兩個階段① 建堆：整包數字整理成 Max-Heap（第 13 關的 buildHeap）。② 一直取最大：堆頂換到後面 → 堆積區縮小 → 下沉，做 n−1 輪。
陣列的樣子陣列中間有一條分界線：左邊是堆積區（還是 Max-Heap，還在整理），右邊是已排序區（已經是最終位置，不會再動）。分界線每輪往左移一格。
目的 把一堆數字由小到大排好，而且不管資料長怎樣都保證夠快（O(n log n)），又不佔額外空間。比喻：老師要把一疊考卷由低分排到高分，桌上只有一排位子。每次抽出剩下考卷裡最高分的那張，放到最右邊還空著的位子；因為剩下的考卷一直維持「最高分在最上面」的疊法，下一張最高分馬上就找得到。
先備 這一關完全建立在第 13 關「堆積上浮下沉」上：Max-Heap、完全二元樹、下沉、buildHeap。還沒玩過的話，先去看第 13 關的 00 段。

先認識這些詞（照順序讀，後面的詞會用到前面的）

排序 sorting
把一堆資料重新排列，讓每一個都 ≤ 它後面那一個（由小到大，也叫遞增）。資料本身不能多也不能少，只是換位置。
把全班考卷由低分到高分疊好。
陣列 / 索引 array / index
一排有編號的格子，編號（索引）從 0 開始。n 個數就用第 0～n−1 格。
一排有號碼的座位。
交換 swap
兩個格子裡的數字對調。堆積排序從頭到尾只用「比大小」和「交換」兩種動作。
兩個同學換座位。
最大堆積 Max-Heap
一棵完全二元樹，每個爸爸都 ≥ 自己的孩子，所以最大值一定在根。存在陣列裡時，第 i 格的孩子在 2i+1、2i+2。（第 13 關的主角）
每個主管都不輸給自己的下屬，總經理一定最強。
堆頂 top / root
Max-Heap 的根，也就是陣列第 0 格。它永遠是堆積區裡的最大值。
疊考卷時最上面那張，永遠是最高分。
下沉 sift-down
某一格的數字太小、站錯位置時，讓它跟較大的孩子交換，一路往下，直到它比孩子都大或沒有孩子為止。
不夠格的主管一路降職，直到位置配得上他。
建堆 buildHeap
把一整包亂放的數字整理成 Max-Heap：從最後一個有孩子的格子（第 n÷2−1 格）往前，每一格做一次下沉。只要 O(n)。
新公司成立，從基層主管開始往上一層一層調整人事。
堆積區 / 已排序區 heap area / sorted area
排序進行中，陣列分成兩段：左邊第 0～hs−1 格是堆積區（還是 Max-Heap），右邊是已排序區（已經在最終位置）。hs 是堆積區的大小，每輪減 1。
桌上左邊是還沒排的考卷疊，右邊是已經排好位置的考卷。
原地排序 in-place
排序時只用原本那個陣列，頂多再用幾個變數，不需要再開一個跟資料一樣大的陣列。堆積排序是原地排序。
只在自己的座位區換位子，不用另外借一間教室。
穩定排序 stable
兩筆資料一樣大時，排完之後還保持原本的先後順序，就叫穩定。堆積排序不穩定：一樣大的資料可能被換到前後顛倒（第 5 關親眼看）。
兩個人都考 80 分，小明本來在小華前面，排完不一定還在前面。
O(n log n) 時間複雜度
資料有 n 個時，大約要做 n × log₂ n 步。n = 1,024 時約 1 萬步；比起 O(n²) 的約 100 萬步快很多。（log₂ n 的意思見第 13 關）
每一輪找最大只要「翻字典」那麼快，翻 n 輪。

容易搞混的幾件事

常被搞混的東西跟堆積排序一樣嗎？差在哪
第 13 關的「heapsort 雛形」不一樣第 13 關是一直 pop、把取出的值放到另一排，要多一個陣列，出來的是由大到小。這一關是原地做：取出的最大值直接放進堆積區空出來的最後一格，排完是由小到大。
選擇排序（第 14 關）想法相同兩個都是「每輪找出最大（或最小），放到該去的位置」。差別是怎麼找：選擇排序整排看一遍，一輪 O(n)；堆積排序靠 Max-Heap，一輪只要 O(log n)。所以整體從 O(n²) 變成 O(n log n)。
「用 Max-Heap 應該排出由大到小吧？」相反最大值每輪被換到最後面，所以最大的在最右邊，結果是由小到大。想要由大到小，就改用 Min-Heap。
「資料本來就排好，會比較快嗎？」不會堆積排序不管資料長怎樣都要先建堆、再做 n−1 輪下沉，最好、最壞都是 O(n log n)。第 3 關可以親眼看：排好的資料一樣要做一大堆交換。
穩定排序不穩定堆頂常常跟很遠的格子交換，一樣大的數字可能前後顛倒。需要穩定時改用合併排序。

自我檢查（先自己想，再點開看答案）

[4, 10, 3, 5, 1] 建成 Max-Heap 之後長怎樣？
[10, 5, 3, 4, 1]。n = 5，從第 5÷2−1 = 1 格往前：第 1 格的 10 比孩子 5、1 都大，不動；第 0 格的 4 跟較大的孩子 10 換，再跟較大的孩子 5 換，停在第 3 格。
接著第 1 輪：10 換到最後之後，陣列是什麼？下沉完又是什麼？
交換後 [1, 5, 3, 4 | 10]，10 進入已排序區。1 在根太小，要下沉，但範圍只到第 3 格：1 跟較大的孩子 5 換 → 再跟孩子 4 換（第 4 格的 10 已經排好，不算孩子）→ [5, 4, 3, 1 | 10]。
n 個數字，第二階段要做幾輪？為什麼不是 n 輪？
n − 1 輪。每輪把一個數送進已排序區。送完 n−1 個之後，堆積區只剩第 0 格一個數——它一定是最小的，而且已經在正確位置，不用再做。
為什麼下沉時要「範圍只到堆積區」，不能看整個陣列？
因為右邊已排序區的數字都比堆積區大。如果把它們也當成孩子，根會跟它們比、被換回堆積區，辛苦排好的最大值就被拉回來了，結果會錯。所以程式的 siftDown 多傳一個參數 n，告訴它「只看前 n 格」。

你會學到什麼

  • 堆積排序的兩個階段 —— 先建堆 O(n)，再做 n−1 輪「交換 + 下沉」，每輪 O(log n)。
  • 為什麼 Max-Heap 排出由小到大 —— 最大值每輪被放到堆積區最後一格，已排序區從右邊長出來。
  • 下沉範圍會縮小 —— siftDown 只看堆積區，已排序區的數字不算孩子。這是最容易寫錯的地方。
  • 原地排序 —— 從頭到尾只用同一個陣列，額外空間 O(1)。
  • 保證 O(n log n) —— 資料亂的、排好的、反過來的，都一樣要做那麼多事。
  • 不穩定 —— 一樣大的數字會被換到前後顛倒，第 5 關親眼看。

    整份程式逐行白話說明（寫給完全沒學過程式的你）

      這個遊戲跑的程式（完整版）

      把視覺化全部拿掉，堆積排序就這麼短。跟第 13 關比，siftDown 只多了一個參數 n（堆積區有幾格）：

      #include <vector>
#include <utility>     // swap
using namespace std;

// 把第 i 格往下沉；只看前 n 格（堆積區），後面的已排序區不算
void siftDown(vector<int>& a, int i, int n) {
    while (true) {
        int L = 2*i + 1, R = 2*i + 2, b = i;
        if (L < n && a[L] > a[b]) b = L;
        if (R < n && a[R] > a[b]) b = R;
        if (b == i) break;                  // 自己最大 → 停
        swap(a[i], a[b]);
        i = b;
    }
}

void heapSort(vector<int>& a) {
    int n = a.size();
    for (int i = n/2 - 1; i >= 0; i--)      // 第一階段：建堆 O(n)
        siftDown(a, i, n);
    for (int end = n - 1; end > 0; end--) { // 第二階段：n−1 輪
        swap(a[0], a[end]);                 // 最大值換到堆積區最後一格
        siftDown(a, 0, end);                // 堆積區變成前 end 格，新堆頂下沉
    }
}

int main() {
    vector<int> a = {4, 10, 3, 5, 1};
    heapSort(a);                            // a 變成 {1, 3, 4, 5, 10}
}

      03

      這個功能是怎麼做到的

      從選擇排序出發，把「找最大值」換成 Max-Heap。

      問題定義

      給一個有 n 個數字的陣列，把它原地排成由小到大，而且要求：不管資料長怎樣，最慢也要在 O(n log n) 內做完。

      第 14 關的幾位選手各有缺點：氣泡、選擇、插入排序最壞 O(n²)；合併排序保證 O(n log n)，但要多一個跟資料一樣大的陣列；快速排序平均很快，但運氣差時退化成 O(n²)。堆積排序剛好把兩個要求都做到。

      從選擇排序出發

      選擇排序的想法非常直覺：每一輪找出還沒排的數字裡最大的，放到最後面。它慢，不是想法錯，而是「找最大」的方法太笨——每輪都要整排看完：

      做法每輪怎麼找最大每輪花費n 輪合計
      選擇排序剩下的數字從頭看到尾O(n)O(n²)
      堆積排序剩下的數字維持成 Max-Heap，最大的就在第 0 格；拿走後下沉補好O(log n)O(n log n)
      一句話 堆積排序 ＝ 選擇排序 ＋ 用 Max-Heap 加速「找最大值」。

      為什麼可以原地做：堆積區縮小的那一格剛好空出來

      每一輪 Max-Heap 少一個人（最大值被拿走），堆積區就少一格。被空出來的，正好是堆積區最後一格——而那一格，就是剛被拿走的最大值該去的最終位置。所以「拿走最大值」和「放到正確位置」用一次交換就同時完成了：

      1. 交換 a[0] 和 a[end] —— 最大值到了 a[end]（它的最終位置），原本最後一格的數字跑到根。
      2. 堆積區縮小 —— 堆積區從 end+1 格變成 end 格，a[end] 進入已排序區，從此不動。
      3. 下沉 a[0] —— 跑到根的那個數字通常很小，往下沉，範圍只到前 end 格，堆積區恢復成 Max-Heap。
      最常錯 下沉時忘了把範圍縮小，還用整個陣列的長度判斷孩子存不存在。這樣根會去跟已排序區的大數字比、把它們換回來，排序結果就錯了。程式裡 siftDown(a, 0, end) 的第三個參數就是為了這件事。

      複雜度：為什麼永遠是 O(n log n)

      • 建堆 O(n) —— 第 13 關證明過：大多數人在底層，幾乎不用沉。
      • 第二階段 O(n log n) —— 做 n−1 輪，每輪下沉最多走樹高 log₂ n 層。
      • 合計 O(n log n)，而且最好、平均、最壞都一樣：不管資料原本長怎樣，每輪換到根的都是堆積區最後一格那個小數字，它幾乎都得一路沉到底。
      • 額外空間 O(1) —— 只有 i、end、L、R、b 幾個變數。
      nO(n²)（選擇排序）O(n log₂ n)（堆積排序）

      1,048,576（≈ 106）約 1 兆約 2,000 萬

      不穩定：一樣大的數字會前後顛倒

      用 [5ᴬ, 5ᴮ, 3]（兩個 5，用 A、B 分辨誰原本在前面）跑一次，就是遊戲第 5 關：

      步驟發生什麼陣列
      建堆5ᴬ 的孩子 5ᴮ、3 都沒有比它大（一樣大不換），已經是 Max-Heap[5ᴬ, 5ᴮ, 3]
      第 1 輪堆頂 5ᴬ ↔ 最後一格 3，5ᴬ 先進已排序區；3 下沉，跟 5ᴮ 換[5ᴮ, 3 | 5ᴬ]
      第 2 輪5ᴮ ↔ 3[3 | 5ᴮ, 5ᴬ]

      原本 A 在 B 前面，排完變成 B 在 A 前面——不穩定。原因是最先被拿走的 5ᴬ 被送到最後面，同樣大的數字裡，越早被拿走的排越後面。只排數字時沒差；排「學生資料依分數排」這種要保留原順序的情況，就要改用穩定的合併排序。

      跟其他 O(n log n) 排序比一比

      排序法最壞時間額外空間穩定實務上
      堆積排序O(n log n)O(1)否保證不會變慢、不佔空間；但跳來跳去存取陣列，實際速度通常比快速排序慢一些。
      合併排序O(n log n)O(n)是需要穩定時的首選。
      快速排序O(n²)O(log n)否平均最快，但運氣差會退化。
      實際用途 C++ 的 std::sort 平常用快速排序，但如果發現快速排序切得太深、快要退化成 O(n²)，就自動改用堆積排序收尾（這種組合叫 introsort）。堆積排序就是那個「保證不會出事」的備胎。標準庫也直接提供 std::make_heap（建堆）和 std::sort_heap（第二階段）。

      常見誤解

      • 「堆積排序要先把資料搬到另一個 heap 裡」 —— 不用。陣列本身就是 heap（完全二元樹存在陣列裡），建堆和排序都在原陣列上做。
      • 「建好 Max-Heap 就排好了」 —— 不是。Max-Heap 只保證最大值在第 0 格，其他人只是「不輸給自己的孩子」，例如 [10, 5, 3, 4, 1] 就沒排好。還要第二階段。
      • 「每輪 pop 完要重新建堆」 —— 不用，也不可以（每輪 O(n) 會讓總時間變 O(n²)）。只有新的堆頂站錯位置，下沉一次 O(log n) 就修好。
      • 「最後一輪要做到 end = 0」 —— 迴圈條件是 end > 0。堆積區剩一格時它自己就是最小值，不用再交換。

      程式架構與說明

      只講流程與分工，不逐行拆解。看懂這一段，你就能自己改這個遊戲。

      整體設計：先算完，再播放

      跟第 13 關一樣：使用者按「下一步」之前，整個排序過程就已經全部算好了。buildSteps 把建堆和每一輪都跑完，每一步存一份陣列快照和堆積區大小 hs；畫面只負責把第 N 步畫出來。

      關卡 arr：要排序的數字（可帶 A、B 標籤）
      buildSteps(level) 建堆 + n−1 輪，整個跑完一次
      steps[] 每一格：陣列快照 + hs + 比較/交換計數 + 說明 + 闖關題
      畫面只負責把 steps[目前步數] 畫出來
      • 前進後退變成加減一 —— 不必寫「反交換」這種容易錯的邏輯。
      • 分界線不用另外算 —— 每一步都存了 hs，樹和陣列都看它決定誰是綠色。

      自己動手：給 AI 的 Prompt

      用 C++ 實作原地堆積排序（heap sort），不可以用 std::sort、std::make_heap。

需要的函式：
- void siftDown(vector<int>& a, int i, int n)   // 只看前 n 格
- void heapSort(vector<int>& a)

要求：
1. 索引從 0 開始：left=2i+1、right=2i+2
2. 先從 n/2-1 往前建堆，再做 n-1 輪「a[0] 和 a[end] 交換 → siftDown(a, 0, end)」
3. 每一輪印出陣列，用 | 標出堆積區和已排序區的分界
4. 用 [4, 10, 3, 5, 1] 測試，並說明如果 siftDown 的範圍寫成 a.size() 會出什麼錯
5. 加一個計數器，比較 n = 1000 時「已排序」「反序」「亂序」三種資料的比較次數

      延伸題 1：由大到小

      只改比較方向，讓同一份程式排出由大到小。解釋為什麼要用 Min-Heap。

      延伸題 2：只要前 k 大

      一百萬個數字只要找出最大的 10 個並排好。
