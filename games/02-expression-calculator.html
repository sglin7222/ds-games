運算式計算機

電腦其實看不懂 3+4*2。它得先把式子翻譯成另一種寫法，才有辦法從左讀到右一次算完。這個翻譯過程叫調度場演算法，是課本上最經典、期中考出現率最高的堆疊應用。

核心結構堆疊 Stack ×2
難度中階
時間O(n)
空間O(n)

01

怎麼玩・你會學到什麼

兩個階段，兩個堆疊，裝的東西完全不同。

怎麼玩

  1. 輸入一個算式，或直接點下面的範例。支援 + − * / ^ 和括號。
  2. 按 下一步 一格一格走，或按 開始 自動播放。
  3. 畫面會走完兩個階段：
    ① 中序 → 後序（堆疊裡裝的是運算子，橘色）
    ② 後序求值（堆疊裡裝的是數字，綠色）
  4. 每一步都會說明「為什麼現在要 push、為什麼現在要 pop」。看不懂就按 上一步 倒回去。
必玩的三題 3+4*2 看優先級怎麼被堆疊自動處理；2^3^2 看右結合（答案是 512 不是 64）；10-2-3 看左結合（答案是 5 不是 11）。這三題是同一條規則的三種面貌。

鍵盤 → 下一步、← 上一步。算式打錯會即時顯示錯在哪。

你會學到什麼

  • 堆疊不是拿來存東西，是拿來記住「還沒輪到的事」 —— 這是整個資料結構課最重要的一句話之一。
  • 把難問題拆成兩趟簡單問題 —— 一次同時處理優先級、括號、計算太難；拆開之後兩趟都只有十幾行。
  • 調度場演算法的四條規則 —— 數字、左括號、右括號、運算子，只有四種情況。
  • 優先級與結合律 —— 為什麼 2^3^2 是 512，程式碼裡哪一行決定了這件事。
  • 後序表示法為什麼好算 —— 沒有括號、不用優先級、從左到右永不回頭。
  • 攤還分析 —— 為什麼裡面有 while 迴圈卻仍然是 O(n)。
  • 五個最常見的實作錯誤 —— 尤其是 a = pop() 和 b = pop() 的順序。
先備 建議先玩過 01 括號堆疊闖關。這一關的「左括號像一道牆」用的就是那一關的觀念。

這個遊戲跑的程式（完整版）

上面兩個階段各自就是一段十幾行的程式。你按「下一步」時畫面走到哪，對應的就是哪一行：

// ① 中序 → 後序（調度場演算法）
#include <stack>
#include <vector>
#include <string>
using namespace std;

int prec(char op) {                                // 優先級：^ > * / > + -
    if (op == '^') return 3;
    if (op == '*' || op == '/') return 2;
    return 1;
}
bool rightAssoc(char op) { return op == '^'; }     // 右結合的運算子

vector<string> toPostfix(const vector<string>& tokens) {
    vector<string> out;
    stack<char> st;
    for (const string& t : tokens) {
        if (isNumber(t)) {
            out.push_back(t);                      // 規則 1：數字直接輸出
        } else if (t == "(") {
            st.push('(');                          // 規則 2：括號進場
        } else if (t == ")") {
            while (st.top() != '(') {              // 規則 3：一路彈到配對的 (
                out.push_back(string(1, st.top())); st.pop();
            }
            st.pop();                              // 丟掉 (
        } else {
            char op = t[0];
            while (!st.empty() && st.top() != '(' &&       // 規則 4
                   (prec(st.top()) > prec(op) ||
                    (prec(st.top()) == prec(op) && !rightAssoc(op)))) {
                out.push_back(string(1, st.top())); st.pop();
            }
            st.push(op);
        }
    }
    while (!st.empty()) {                          // 收尾：全部倒出來
        out.push_back(string(1, st.top())); st.pop();
    }
    return out;
}
// ② 後序求值 —— 沒有任何優先級判斷
double evalPostfix(const vector<string>& tokens) {
    stack<double> st;
    for (const string& t : tokens) {
        if (isNumber(t)) {
            st.push(stod(t));
        } else {
            double b = st.top(); st.pop();   // 注意順序！後彈出的才是左運算元
            double a = st.top(); st.pop();
            st.push(apply(a, b, t[0]));
        }
    }
    return st.top();                     // 剩下的唯一一個就是答案
}
03

這個功能是怎麼做到的

從「為什麼不能邊讀邊算」開始。

問題定義

給一個字串形式的中序運算式，算出它的值。

  • 可能出現：非負數（含小數、多位數）、+ − * / ^、小括號。
  • 優先級 ^ > * / > + −；^ 是右結合，其餘左結合。
  • 括號可以任意巢狀，深度不限。
  • 不可以呼叫現成的 eval() 之類函式，那等於沒寫。
輸入輸出說明
3+4*2/(1-5)^23.5= 3 + 8 / 16
2^3^2512= 2^(3^2)，不是 (2^3)^2 = 64
10-2-35= (10−2)−3，不是 10−(2−3) = 11

邊界情況也要想到：括號不配對、運算子過多（1++2）、除以零、多位數 123 不能被拆成三個字元。

這題難在哪

難點 你不能從左往右邊讀邊算。
讀到 3 + 4 的時候還不能做加法 —— 因為下一個字元可能是 *，那 4 就得先跟後面的數字相乘。同理，讀到 ( 之後的所有運算，都要等 ) 出現才知道能不能算。

換句話說：你手上會累積一堆還沒輪到、正在等待的運算子，而且一定是最後等的那個先被處理。這就是後進先出 —— 題目本身在跟你要一個堆疊。

如果你硬要一次搞定…會遇到的麻煩
從左到右直接算3+4*2 會算成 14（錯，應該是 11）
用 if 判斷優先級括號一巢狀就爆炸，深度不限沒辦法寫死
用正規表示式巢狀括號不是正規語言，理論上就做不到
遞迴下降 parser可行，但那其實是借用呼叫堆疊做同一件事（見 04）

為什麼這題重要：編譯器、直譯器、Excel 公式、SQL 的 WHERE 條件、計算機 App，骨子裡跑的都是這一段。

關鍵洞察：把「決定順序」和「實際計算」拆開

一次同時處理優先級、括號、計算太難。拆成兩趟，每一趟都退化成小學生等級的問題：

中序（人看的）3 + 4 * 2

  • 要記「先乘除後加減」
  • 要處理括號
  • 眼睛得跳來跳去，不能從左讀到右一次算完
  • 電腦要邊讀邊回頭 → 很難寫

後序（電腦看的）3 4 2 * +

  • 完全不需要括號，也不需要優先級規則
  • 從左讀到右一次算完，永不回頭
  • 求值只要一個堆疊、十行程式
  • JVM、Python 虛擬機、HP 計算機都是這樣算的
兩趟 ① 中序 → 後序：只重排符號，完全不做算術。
② 後序求值：從左到右照著做，完全不管優先級。
兩趟都是 O(n)，加起來還是 O(n)。

階段一的四條規則

只有四種 token，所以只有四條規則：

  1. 遇到數字 → 直接輸出。
    理由：數字在後序式裡的相對位置不會變，它不用等任何人。
  2. 遇到 ( → 直接壓入堆疊。
    理由：它是一道牆。牆上面的運算子還沒結案前，牆下面的一律不准彈出。
  3. 遇到 ) → 一路彈出到碰見 (，再把這對括號丟掉。
    理由：括號內的帳現在可以結清了，而括號本身在後序式裡不需要存在。
  4. 遇到運算子 op → 先把堆疊頂端「該比它先算」的通通彈出，再把 op 壓進去。
    「該比它先算」＝ 頂端優先級更高，或一樣高且 op 是左結合。

讀完整串之後，把堆疊剩下的全部倒出來 —— 這就是完整的演算法。

手算階段一：3+4*2

讀到判斷動作堆疊（底→頂）輸出
3數字直接輸出（空）3
+堆疊是空的push+3
4數字直接輸出+3 4
*top 是 +，1 < 2 不該先算不彈出，直接 push+ *3 4
2數字直接輸出+ *3 4 2
（讀完）收尾pop *+3 4 2 *
（讀完）收尾pop +（空）3 4 2 * +
看第 4 列 * 比 + 晚進堆疊，卻比 + 早出來。「晚進早出」就是 LIFO 的定義 —— 優先級規則被堆疊天然地實現了，你不用另外寫排序。

手算階段二：3 4 2 * +

讀到動作堆疊
3數字 → push3
4數字 → push3 4
2數字 → push3 4 2
*pop 出 2、再 pop 出 4 → 4 × 2 = 8 → push 83 8
+pop 出 8、再 pop 出 3 → 3 + 8 = 11 → push 1111 ← 答案

整段求值沒有出現任何一次優先級判斷，也沒有括號 —— 因為順序在階段一就決定好了。這就是分兩趟的價值。

右結合為什麼要特別處理

算式遇到第二個運算子時後序結果值
10-2-3同級 + 左結合 → 彈出前一個 −10 2 - 3 -5 ✓
2^3^2同級 + 右結合 → 不彈出，一起等2 3 2 ^ ^512 ✓

差別就在規則 4 那個「且 op 不是右結合」的條件。拿掉它，2^3^2 會算成 64（錯）；把它套到 − 上，10-2-3 會算成 11（錯）。一個條件同時管住兩件事。

運算子優先級結合律例子
^ 次方3（最高）右結合 →2^3^2 = 2^(3^2) = 512
* /2左結合 ←8/4/2 = (8/4)/2 = 1
+ −1（最低）左結合 ←10-2-3 = (10-2)-3 = 5
(進堆疊後視為最低—像一道牆，擋住彈出

複雜度

時間空間為什麼
階段一 轉後序O(n)O(n)每個 token 最多被 push 一次、pop 一次
階段二 求值O(n)O(n)同上，掃一遍不回頭
合計O(n)O(n)最壞情況（全是左括號）堆疊會存下整串
攤還分析 規則 4 裡面有一個 while 迴圈，看起來像 O(n²)。但每個運算子一生只會被彈出一次，所以整段程式的總彈出次數不超過 n —— 平均下來每個 token 還是常數成本。這個論證叫攤還分析，在 03 單調堆疊 會再用一次。

五個最常見的錯誤

  • a = pop() 寫在 b = pop() 前面 —— 減法、除法、次方全部左右顛倒。10 3 - 會變成 3−10 = −7。這是期中考最愛考的陷阱，而且 + * 測不出來。
  • 規則 4 忘了排除 ( —— 左括號被優先級規則彈出，括號整個失效。
  • 條件寫成 >= 卻沒排除右結合 —— 2^3^2 變 64。
  • 迴圈結束忘了把堆疊倒空 —— 最後幾個運算子憑空消失。
  • tokenize 一次只讀一個字元 —— 12+3 被讀成 1、2、+、3，答案完全錯。多位數必須一次讀完。
04

程式架構與說明

只講流程與分工，不逐行拆解。

整體設計：先算完，再播放

跟 01 括號堆疊闖關 同一套架構。使用者按下按鈕之前，兩個階段的每一步就已經算完存進陣列了。

算式字串 "3+4*2"
tokenize() 切成 token：數字要一次讀完
buildSteps() 兩個階段一次跑完
steps[] 每一格：目前 token、堆疊快照、輸出快照、說明
render() 把 steps[目前步數] 畫出來

因為每一步都存了完整快照，上一步／下一步只是陣列索引加減一，不需要寫「反向操作堆疊」的邏輯。

三個函式，各管一件事

函式輸入 → 輸出負責什麼
tokenize() 字串 → token 陣列 把 "12+3" 切成 [12][+][3]。多位數與小數要一次讀完，這裡寫錯後面全錯。看不懂的字元直接丟錯誤。
buildSteps() token 陣列 → 步驟陣列 核心。裡面就是完整的調度場演算法 + 後序求值，每做一個動作就存一張快照。
render() 步驟 → 畫面 讀 steps[cur]，畫 token 條、堆疊塔、輸出區、說明面板。不含任何演算法。
分界線 把 snap() 那幾行拿掉，buildSteps() 就剛好變成教科書上的調度場演算法，一行不多。這條界線就是「演算法」和「教學包裝」的分野。

一個 step 長什麼樣

{
  phase:  // 'convert' 或 'eval' → 決定上方兩階段條哪一格亮
  ti:     // 目前指到第幾個 token → token 條的高亮位置
  stack:  // 階段一的運算子堆疊快照（橘色）
  vstack: // 階段二的數字堆疊快照（綠色）
  out:    // 目前的後序輸出快照
  msg:    // 這一步在做什麼、為什麼
  cls:    // 說明面板的顏色：good / pop / 空
}

注意 stack 和 vstack 是兩個不同的欄位，因為兩階段的堆疊裝的東西型別不同（一個裝符號、一個裝數字）。畫面靠 phase 決定要畫哪一個、用什麼顏色。

錯誤處理放在哪

所有錯誤都用 丟例外 的方式集中處理，而不是在畫面層到處寫 if：

錯誤在哪裡發現訊息
看不懂的字元tokenize()只支援數字、+ − * / ^ 和括號
右括號多了buildSteps() 規則 3一路彈出時堆疊先空了
左括號沒關buildSteps() 收尾倒空堆疊時倒出了 (
運算元不足buildSteps() 求值要 pop 兩個但堆疊不夠
式子結構不對buildSteps() 結尾算完後堆疊不是剛好剩 1 個
值得記 最後那條 —— 「算完後堆疊必須剛好剩一個元素」 —— 是一個非常便宜又有效的合法性檢查。剩太多代表運算子不夠，剩太少代表運算子太多。一行判斷擋掉兩類錯誤。

自己動手：給 AI 的 Prompt

用 C++ 實作一個支援 + - * / ^ 和括號的運算式計算機，用兩個 std::stack。

分三個函式：
1. tokenize(s)      -> 把 "3+4*2/(1-5)^2" 切成 token 串列（要支援多位數與小數）
2. to_postfix(toks) -> 用調度場演算法轉成後序
3. eval_postfix(p)  -> 用 Stack 求值

- 優先級 ^ > * / > + -，其中 ^ 是右結合
- 每一步印出「目前 token / Stack 內容 / 輸出內容」的表格
- 用這四個式子驗證：
  3+4*2/(1-5)^2  → 3.5
  (1+2)*(3+4)    → 21
  2^3^2          → 512   （不是 64！）
