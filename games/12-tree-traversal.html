走訪路線猜謎

前序、中序、後序、層序 —— 同一棵樹，四種走法，四份完全不同的名單。前三種只差「什麼時候簽名」，第四種乾脆把堆疊換成佇列。走完之後還有反向謎題：只給你名單，反推那棵樹長什麼樣。

怎麼玩

畫面上有一棵二元樹。走訪時目前的節點會亮橘色、已經「輸出」的節點變綠色，樹下面的輸出帶會依序長出節點。右邊的側欄同步演出幕後功臣：前中後序時是呼叫堆疊，層序時整個換成佇列。

演示模式

  1. 挑一棵樹（滿樹、歪樹、隨機形狀），或按「亂數長一棵」。
  2. 選一種走訪方式。同一棵樹把四種都跑一遍，比較輸出。
  3. 按 下一步 一格一格走，盯著側欄的堆疊怎麼疊高、佇列怎麼排隊。

闖關模式

  1. 每次都先問你：下一個被輸出的節點是誰？
  2. 答對得分、連對加分；答錯立刻解釋為什麼是那一個。

反推謎題

  1. 遊戲下方還有一關：只給「前序＋中序」（或「後序＋中序」）兩串名單。
  2. 一步步看「找根 → 用中序切左右」怎麼把整棵樹長回來。
操作 鍵盤 → 下一步、← 上一步、空白鍵 播放／暫停。

你會學到什麼

  • 四種走訪的定義與比喻 —— 前序＝進門先簽名、中序＝中場簽名、後序＝出門才簽名、層序＝一層一層掃地。
  • DFS 三兄弟只差「簽名時機」 —— 三份程式碼幾乎一模一樣，只有 visit 那一行換了位置，輸出就完全不同。
  • 遞迴＝堆疊、層序＝佇列 —— 這是本關最重要的記憶點。前三種靠呼叫堆疊「鑽到底再退回來」，層序把資料結構整個換成佇列，走法就變成「掃一層再掃下一層」。
  • 反推的原理 —— 前序（或後序）告訴你「根是誰」，中序負責「把左右子樹切開」；為什麼「前序＋後序」反而不一定能唯一重建。
  • 複雜度 —— 時間都是 O(n)；空間 DFS 是 O(h)（h＝樹高）、層序是 O(w)（w＝最寬那一層的節點數）。
建議順序 用滿樹把四種走法各跑一遍（尤其盯側欄）→ 切歪樹看堆疊疊到跟節點數一樣高 → 開闖關模式 → 最後玩下面的反推謎題。

    整份程式逐行白話說明（寫給完全沒學過程式的你）

      這個遊戲跑的程式（完整版）

      把視覺化全部拿掉之後的本體。注意前三個函式只有 visit 那一行的位置不同，第四個函式則整個換了資料結構：

      #include <cstdio>
#include <queue>
using namespace std;

struct Node { char val; Node *left, *right; };   // 一個節點：值 + 左右孩子的指標
void visit(char v) { printf("%c ", v); }         // 「簽名」＝把值印出來

void preorder(Node* t) {                         // 前序：根 → 左 → 右
    if (t == nullptr) return;
    visit(t->val);                                // 簽名放「最前面」
    preorder(t->left);
    preorder(t->right);
}
void inorder(Node* t) {                          // 中序：左 → 根 → 右
    if (t == nullptr) return;
    inorder(t->left);
    visit(t->val);                                // 簽名夾「中間」
    inorder(t->right);
}
void postorder(Node* t) {                        // 後序：左 → 右 → 根
    if (t == nullptr) return;
    postorder(t->left);
    postorder(t->right);
    visit(t->val);                                // 簽名放「最後面」
}
void levelOrder(Node* root) {                    // 層序：換成佇列
    queue<Node*> q;
    q.push(root);
    while (!q.empty()) {
        Node* t = q.front(); q.pop();
        visit(t->val);
        if (t->left)  q.push(t->left);
        if (t->right) q.push(t->right);
    }
}

      DFS 三兄弟靠的是系統幫你維護的呼叫堆疊（就是 04 關畫出來的那座）；層序沒有半行遞迴，靠的是你自己準備的佇列。

      為什麼一定要有「中序」？換成「前序＋後序」就會出事

      前序、後序都能告訴你「根是誰」，但只有中序能把左右子樹切開——根的左邊全是左子樹、右邊全是右子樹。少了這把刀，就會出現兩棵不同的樹、名單卻一模一樣：

         樹一：       樹二：
     A            A
    /              \
   B                B

樹一　前序 = A B　　後序 = B A
樹二　前序 = A B　　後序 = B A     // 完全相同！

      兩棵樹的前序都是「先簽 A 再簽 B」、後序都是「先簽 B 再簽 A」——你分不出 B 到底掛在左邊還是右邊。所以「前序＋後序」只有在每個節點都恰好有 0 或 2 個孩子時才能唯一重建；一般的樹，必須有中序參與。

      03

      這個功能是怎麼做到的

      四種走法怎麼來、為什麼前三種是一家人、第四種為什麼要換資料結構。

      問題定義：什麼是「走訪」

      走訪（traversal）＝把樹上每個節點恰好拜訪一次，並按某種固定順序把它們「輸出」。樹不像陣列有天生的先後順序，所以「按什麼順序唸」本身就是一個要回答的問題。常見答案有四種：

      走法順序生活比喻屬於哪一家
      前序 Preorder根 → 左 → 右進門先簽名：一走進房間就先簽，再進去逛DFS（深度優先）
      靠堆疊
      中序 Inorder左 → 根 → 右中場簽名：左半邊逛完、回到門口簽名，再逛右半邊
      後序 Postorder左 → 右 → 根出門才簽名：整個房間逛完，離開前最後一刻才簽
      層序 Level-order一層掃完換下一層一層一層掃地：先掃一樓、再掃二樓，絕不跳層BFS（廣度優先）
      靠佇列

      三個名字裡的「前、中、後」，指的都是同一件事：「自己」排在左右子樹的什麼位置。

      先破除一個直覺：「不就是從上唸到下、從左唸到右？」

      很多人以為樹只有一種自然的唸法。錯 —— 那種「由上而下、由左而右」的唸法只是四種之一（層序），而且它反而是最特殊的一種。

      • 樹是巢狀結構，不是一排字 —— 每個節點下面還掛著整棵子樹。「唸到 B 的時候，要不要先把 B 底下的整片唸完？」不同的答案就是不同的走訪。
      • 順著指標走，天生就會「鑽到底」 —— 程式拿到一個節點，手上只有它的左右孩子。自然的寫法是遞迴：一路往下鑽、再一路退回來。想「橫著掃」反而做不到，因為同一層的節點之間根本沒有指標相連。
      關鍵 「橫著掃」需要一個地方暫存「這一層還沒處理的節點」，而且要先進先出 —— 這就是為什麼層序非用佇列不可。

      關鍵觀察：DFS 三兄弟只差「簽名時機」，層序整個換了資料結構

      把 02 段的程式碼並排看，會發現一件漂亮的事：

      • 前序、中序、後序的程式碼一字不差，只有 visit 那一行的位置不同 —— 放在兩個遞迴呼叫的前面、中間、後面。走的路線其實完全一樣（每個節點都會「經過」三次），差別只是在第幾次經過時簽名。
      • 它們三個都不需要你寫任何堆疊 —— 因為遞迴本身就是堆疊（04 關畫過的呼叫堆疊）。「鑽到底再退回來」的記憶，全記在那疊 frame 裡。
      • 層序連一行遞迴都沒有 —— 它要的不是「最晚進來的先處理」（LIFO），而是「最早排隊的先處理」（FIFO）。需求從堆疊變成佇列，整個程式的形狀就從遞迴變成 while 迴圈。
      記這句 堆疊讓你鑽得深，佇列讓你掃得寬。選了哪個資料結構，就決定了走出來是 DFS 還是 BFS —— 07 關的迷宮用的是同一個道理。

      演算法

      DFS（前／中／後序）：一條遞迴走天下

      1. 遇到空節點（nullptr）—— 直接 return。這是遞迴的煞車。
      2. 按自家順序做三件事 —— 「處理左子樹」「簽名」「處理右子樹」，只是排列不同：前序＝簽、左、右；中序＝左、簽、右；後序＝左、右、簽。
      3. 「處理子樹」就是呼叫自己 —— 那一整片交給遞迴，呼叫堆疊會記住「我做到一半、等你回來」。

      層序：佇列的固定節奏

      1. 根節點先排隊。
      2. 隊伍不空就重複：隊伍最前面的人出列 → 輸出他 → 他的左右孩子（如果有）排到隊伍最後面。
      3. 孩子屬於下一層，自然排在這一層所有人後面 —— 「一層掃完才換下一層」不是特別設計，是 FIFO 的必然結果。
      最常錯 DFS 忘了寫 nullptr 的檢查（無限遞迴直到爆掉）；層序忘了只把存在的孩子入隊（把 nullptr 排進去，出列時就當機）。

      手算一次：同一棵樹，四種輸出

      就是遊戲裡的「滿樹」關卡。考試時先把樹畫出來，再按各自的口訣走一遍：

              A
      ┌─┴─┐
      B   C
    ┌─┴┐ ┌┴─┐
    D  E F  G
      走法口訣輸出看點
      前序根左右A B D E C F G根 A 排第一個；先把左半邊 BDE 整片吃完才碰 C
      中序左根右D B E A F C G根 A 卡在正中間，左邊 DBE 全是左子樹、右邊 FCG 全是右子樹
      後序左右根D E B F G C A根 A 排最後一個；每個節點都比自己的孩子晚出現
      層序一層層A B C D E F G正好一層一層：A｜BC｜DEFG
      • 根的位置就是名字 —— 前序最前、中序正中（把左右分開）、後序最後。反推謎題全靠這三條性質。
      • 前序 ≠ 層序 —— 兩個的第一個字都是根，但第三個字就分家了（前序鑽到 D，層序橫掃到 C）。

      複雜度

      • 時間 O(n) —— 四種走法都一樣：每個節點恰好被拜訪一次，每次做的事（簽名、把孩子入隊）都是固定成本。
      • DFS 空間 O(h) —— h 是樹高（從根到最深葉子的層數）。呼叫堆疊最深時剛好疊了「根到目前節點」這一條路徑。平衡樹 h ≈ log₂n，很省；歪樹 h = n，堆疊跟節點數一樣高 —— 玩玩看遊戲裡的歪樹關卡。
      • 層序空間 O(w) —— w 是最寬那一層的節點數。佇列最長的瞬間，裝的差不多就是最寬的一層。滿樹的最底層約有 n/2 個節點，所以最壞也是 O(n) —— 但形狀跟 DFS 相反：樹越歪 DFS 越吃虧、樹越滿層序越吃虧。

      常見誤解

      • 「中序輸出一定由小到大」 —— 只有二元搜尋樹（BST）才有這個福利。普通的樹，中序只是位置順序，跟大小無關。（反過來記：BST 的定義就是「中序起來剛好有序」的樹。）
      • 「前序跟層序差不多吧，第一個都是根」 —— 第三個字就不一樣了。前序會鑽進左子樹深處，層序永遠橫著掃。
      • 「前序＋後序也能反推出樹」 —— 不行。單一個孩子時分不清它在左還是右（見 02 段結尾的反例）。要唯一重建，中序是必要的那一半。
      • 「層序用遞迴也寫得出來，所以跟資料結構無關」 —— 硬寫得出來（一層一層收集），但本質上你還是在維護「按層排隊」這件事。真正的分野在：LIFO 鑽深、FIFO 掃寬，這是資料結構決定的，不是語法。
      • 「visit 一定是印出來」 —— visit 是「對這個節點做事」的統稱：加總、複製、刪除都行。刪除整棵樹必須用後序（先刪孩子才能刪自己），這就是簽名時機真正重要的時刻。
