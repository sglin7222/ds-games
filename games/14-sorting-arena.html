怎麼玩

畫面上是一排高矮不一的柱子，每根柱子就是一個數字。排序就是把柱子由矮到高排好——你會看到每一次「比較」（把兩根放在一起看誰高）和每一次「交換」（兩根互換位置）。

演示模式（單獨看一個演算法）

  1. 挑一個演算法（氣泡／選擇／插入／合併／快速）和一組資料。
  2. 按 下一步 一格一格走：橘色＝正在比較，實心橘＝正在交換或搬移，綠色＝已經就定位、永遠不再動。
  3. 右邊計數器即時累加比較次數和交換／搬移次數，下方 C++ 程式逐行高亮。

闖關模式（猜下一步）

  1. 每走到關鍵處先不給答案，由你猜：下一步比較哪兩根？會不會交換？這一輪誰就定位？
  2. 答對得分、連對加分；答錯立刻解釋為什麼。建議先選「迷你 8 根」資料。

競技模式（本關重頭戲）

  1. 五個演算法拿到同一份資料，五個小柱狀圖並排同時開跑。
  2. 每按一次「下一步」大家各走一步（或按播放齊跑），右側記分板即時排名比較次數，誰先排完誰亮完賽。
  3. 換「完全逆序」再跑一次，看氣泡排序被海放；換「幾乎排好」，看插入排序反殺。
操作 鍵盤 → 下一步、← 上一步、空白鍵 播放／暫停。

你會學到什麼

  • 五個經典排序的動作本質 —— 氣泡＝相鄰互換讓大的往右浮；選擇＝每輪挑最小的放定位；插入＝像整理撲克牌把新牌插進排好的左手；合併＝兩疊排好的牌合成一疊；快速＝選一個基準值把大家分成兩堆。
  • 比較與交換是兩回事 —— 選擇排序比較很多、交換卻只有 n−1 次；插入排序用「搬移」不用「交換」。計數器會讓你看見差別。
  • O(n²) 和 O(n log n) 差多少 —— 不是背出來的，是記分板上一翻兩瞪眼的數字。
  • 資料長相決定勝負 —— 幾乎排好時插入排序接近 O(n)；完全逆序時氣泡排序最慘；已排好＋固定 pivot 會讓快速排序退化。
  • 穩定性 —— 同分的人保不保持原本順序？為什麼合併穩定、選擇不穩定。
  • 為什麼 O(n log n) 是比較排序的極限 —— 每次比較最多把可能性砍一半。
建議順序 先用演示模式看完氣泡和插入建立直覺 → 切競技模式跑「隨機」和「完全逆序」感受差距 → 最後用「迷你 8 根」玩闖關模式驗收。

    整份程式逐行白話說明（寫給完全沒學過程式的你）

      這個遊戲跑的程式（完整版）

      把視覺化全部拿掉，「競技場」的本體就是這樣：同一份資料各跑一次、每個比較和交換都計數。這裡放氣泡（O(n²) 代表）對決快速（O(n log n) 代表），其餘三個在上面的演算法面板都有完整程式：

      #include <cstdio>
#include <cstdlib>
#include <ctime>

long long C = 0, M = 0;                          // C = 比較次數、M = 交換次數
bool lt(int x, int y) { C++; return x < y; }     // 所有比較都經過這裡，順便計數
void sw(int &x, int &y) { int t=x; x=y; y=t; M++; }

void bubbleSort(int a[], int n) {
    for (int i = 0; i < n - 1; i++)
        for (int j = 0; j < n - 1 - i; j++)
            if (lt(a[j + 1], a[j])) sw(a[j], a[j + 1]);
}
void quickSort(int a[], int L, int R) {
    if (L >= R) return;
    int p = a[R], i = L - 1;
    for (int j = L; j < R; j++)
        if (lt(a[j], p)) sw(a[++i], a[j]);
    sw(a[i + 1], a[R]);
    quickSort(a, L, i);  quickSort(a, i + 2, R);
}
int main() {
    srand((unsigned)time(0));
    int x[14], y[14];
    for (int i = 0; i < 14; i++) x[i] = y[i] = rand() % 30 + 1;   // 同一份資料

    C = M = 0; bubbleSort(x, 14);
    printf("氣泡：比較 %lld 次、交換 %lld 次\n", C, M);
    C = M = 0; quickSort(y, 0, 13);
    printf("快速：比較 %lld 次、交換 %lld 次\n", C, M);
}

      n = 14 看起來差距還不大；把 14 改成 10000 再跑一次，氣泡的比較次數大約是 5000 萬，快速大約 15 萬——這就是第 03 段要講的事。

      03

      這個功能是怎麼做到的

      從「排序是什麼」走到「為什麼有的排法天生就快」，中間每一步為什麼非要不可。

      問題定義

      給一排數字，把它們由小到大重新排好。聽起來只有一題，其實資料的「長相」會讓同一個演算法表現天差地遠——所以本關的資料集不是隨便選的，每一組都是為了讓某個演算法現出原形：

      資料集長相誰佔便宜誰吃虧
      隨機亂序17, 3, 28, 9, …合併、快速（平均 O(n log n)）三個 O(n²) 選手
      幾乎排好2, 4, 8, 6, 10, …插入（接近 O(n)）、氣泡（提前收工）選擇（照樣全掃）、固定 pivot 的快速
      完全逆序30, 28, 26, …合併（照常 n log n）氣泡（每一對都要換，最壞情況）
      大量重複14, 6, 22, 14, 6, …看穩定性的好教材單邊分堆的快速

      先破除一個直覺：「反正都能排好，誰做都差不多」

      五個演算法最後都會把柱子排好，看結果完全分不出高下。差別全部藏在過程的成本裡——這正是競技模式存在的理由。用 n = 14 的完全逆序資料實際數一次：

      • 氣泡排序 —— 比較 91 次、交換 91 次：每一對相鄰柱子都是錯的，每一次比較都得動手。
      • 選擇排序 —— 比較 91 次、但交換只有 13 次：它比較不省，交換卻極省。「比較次數」和「交換次數」是兩種不同的成本。
      • 合併排序 —— 比較 30 次上下就結束：它根本不跟你玩相鄰互換，直接把問題切半。
      關鍵 n = 14 時是 91 比 30；n = 10000 時是 5000 萬比 13 萬。演算法的差距不是快一點點，是隨著資料變大拉開到不能忽視。

      關鍵觀察：比較是唯一的資訊來源，別浪費它

      排序演算法唯一能問的問題是「這兩個數字誰大？」。快慢的分水嶺，就在每一次比較換到多少資訊：

      • O(n²) 三兄弟 —— 氣泡每次比較最多修正「一對相鄰的錯誤」；逆序資料有 n(n−1)/2 對錯誤，所以至少要做 n(n−1)/2 次修正。一次比較，只換到一格進展。
      • 合併排序 —— 比較的對象是「兩疊已經排好的牌」的頂端。一次比較就確定一張牌的最終去向，而且兩疊排好這件事本身就是之前比較攢下來的資訊，完全沒有浪費。
      • 快速排序 —— 一輪分堆用 n 次比較，就讓「左邊全部小於 pivot、右邊全部不小於」同時成立——一次掃描，全場的相對位置資訊都有了進帳。
      所以 快的演算法不是「手腳比較快」，而是把之前比較過的結果記住、重複利用（排好的子堆、pivot 兩側的關係）；慢的演算法每輪都把大部分資訊丟掉重來。

      五位選手：各自的一句話與生活比喻

      1. 氣泡排序 Bubble —— 反覆走訪相鄰兩根，左比右大就交換；每輪最大的「浮」到最右邊。比喻：一排人兩兩比身高，高的往右換，最高的一輪就換到底。
      2. 選擇排序 Selection —— 每輪把剩下的全部看完挑出最小的，放到左邊定位。比喻：從整副牌裡每次挑出最小的一張，依序疊成新的一疊。
      3. 插入排序 Insertion —— 左手的牌永遠排好；每次抽一張新牌，從右往左找位置插進去。比喻：整理撲克牌，人類本能就是這樣排的。
      4. 合併排序 Merge —— 把整排切半再切半，小到一張自然排好；然後兩疊已排好的牌合成一疊：每次只比兩疊頂端，小的先放下。
      5. 快速排序 Quick —— 選一個基準值 pivot，一輪掃描把「比它小的」全趕到左邊，pivot 就定位；左右兩堆各自重複同一招。比喻：老師說「比 160 矮的站左邊」，一聲令下全班分成兩隊。
      最常漏 合併排序的 a[i] <= a[j] 那個等號：一樣大時要拿左邊的，穩定性就靠它。寫成 < 也能排好，但同分的順序會亂掉。

      手算一次：插入排序 [5, 2, 4, 6, 1, 3]

      考試在紙上追蹤時就畫這張表。「手上的牌」是抽出來的 key，粗體是這一輪剛插好的位置：

      輪 i手上的牌往左比了誰搬移結果
      125>2 → 挪12 5 4 6 1 3
      245>4 → 挪；2≤4 → 停12 4 5 6 1 3
      365≤6 → 停（原地不動）02 4 5 6 1 3
      416,5,4,2 全部>1 → 挪到最左41 2 4 5 6 3
      536,5,4 → 挪；2≤3 → 停31 2 3 4 5 6

      總共比較 12 次、搬移 9 次。注意第 3 輪：資料本來就對，成本幾乎是零——把整排都「幾乎排好」，每一輪都像第 3 輪，整趟就接近 O(n)。這就是插入排序的主場。

      五演算法比較總表

      演算法最好平均最壞額外空間穩定？
      氣泡O(n)O(n²)O(n²)O(1)穩定
      選擇O(n²)O(n²)O(n²)O(1)不穩定

      • 穩定性白話版 —— 兩個「同分」的元素，排完之後保不保持原本的前後順序？想像班級名單先按名字排好、再按成績排：穩定排序會讓同分的人仍照名字順序排列，不穩定排序會把他們打亂。先後套用兩次排序的需求（先按日期、再按類別）非穩定不可。
      • 選擇排序為什麼不穩定 —— 「把最小的換過來」那一下交換是跳著換的，可能把某個同分元素越過它的同伴丟到後面。
      • 合併的代價 —— 三欄都是 O(n log n) 很漂亮，但要 O(n) 的暫存盒；快速平均一樣快又幾乎不用額外空間，所以實務更常見。

      為什麼 O(n log n) 是「用比較來排序」的極限

      直觀版，不用任何數學符號也能懂：

      1. n 個不同的數字，可能的排列順序有 n! 種（14 個數字就是 871 億種）。排序前，正確答案藏在這 n! 種裡的其中一種。
      2. 每問一次「A 和 B 誰大？」，答案只有兩種，所以最多把「還有可能的排列」砍成一半。
      3. 要從 n! 種砍到只剩 1 種，至少要砍 log₂(n!) 次——這個數大約就是 n log n。砍得再聰明也不能更少，因為一次比較就是只有兩種答案。
      邊界 這個極限只管「靠比較」的排序。如果數字範圍很小，計數排序（Counting Sort）根本不比較、直接數每個值出現幾次，可以到 O(n+k)——它繞過了規則，不是打破了規則。

      複雜度：n² 和 n log n 是從哪裡長出來的

      • O(n²) —— 「n 輪 × 每輪掃 n 個」的結構：氣泡與選擇的雙層巢狀迴圈（迴圈裡面又包一個迴圈，外圈每走一步、內圈就得從頭跑完一遍）。1+2+…+(n−1) = n(n−1)/2，量級就是 n²。
      • O(n log n) —— 「切半」只能切 log₂n 層（14 根切 4 層就見底），每一層的合併或分堆總工作量是 n，相乘得 n log n。
      • 空間 —— 氣泡／選擇／插入原地交換 O(1)；合併要一個跟資料一樣大的暫存盒 O(n)；快速的額外空間是遞迴呼叫疊起來的深度，平均 O(log n)。

      常見誤解

      • 「快速排序永遠最快」 —— 反例：資料已經排好＋固定拿最右邊當 pivot。每輪分堆一邊全空、一邊 n−1 個，切半變成削皮，直接退化成 O(n²)。所以工業級的快排會隨機選 pivot，或用三數取中，C++ 的 std::sort 甚至會在偵測到退化時切換成堆積排序（introsort）。
      • 「O(n²) 的排序都是垃圾」 —— n 很小（十幾個）或資料幾乎排好時，插入排序常常是實測最快的。所以 std::sort 和 Python 的 timsort 都在小段落改用插入排序收尾。
      • 「比較次數少＝一定比較快」 —— 還要看交換／搬移成本和快取行為。選擇排序交換極少，若「搬動一個元素」非常昂貴（例如大結構），它反而有戲。
      • 「排好了它自己會知道」 —— 只有氣泡（靠 swapped 旗子）和插入天生會提早收工；選擇和固定寫法的合併、快速，資料排好了照樣把全部工作做完。

      程式架構與說明

      只講流程與分工，不逐行拆解。看懂這一段，你就能自己加第六種排序。

      整體設計：先算完，再播放——競技場也一樣

      五個演算法各自先一口氣跑完，把每一步的完整柱狀圖快照存進自己的 steps 陣列；畫面只負責把「第 N 步」畫出來。競技模式沒有任何並行魔法——只是五份 steps 陣列共用同一個進度數字 T，每按一步大家的游標一起 +1，誰的陣列先走到底誰完賽。

      同一份資料 data = [17, 3, 28, …]
      buildBubble / buildSelection / buildInsertion / buildMerge / buildQuick 各自把整趟排序跑完
      5 份 steps[] 每一格都是當下柱狀圖的完整快照＋累計計數
      單獨模式畫 steps[S.cur]；競技模式畫 5 份 steps[min(T, 終點)]
      • 前進後退變成加減一 —— 「倒轉一次交換」不用寫任何反向邏輯。
      • 計數器不用重算 —— 每個 step 都帶著當下累計的 cmp／swp，跳到任何一步數字都對。
      • 競技模式幾乎免費 —— 演算法函式一行都不用改，只是同時讀五份陣列。
      代價 每步存一份陣列快照，記憶體 O(步數 × n)。教學規模（n ≤ 16、幾百步）完全沒問題，真實工程不會這樣寫。

      {
  kind:  // start / pass / cmp / swap / keep / shift / place / take / pick / lock / done
         // → 決定柱子顏色、徽章文字、說明面板底色
  arr:   // 這一步「動作做完之後」的整排柱子快照 → 柱狀圖直接畫這個
  hi:    // 目前高亮的柱子索引（比較中的兩根、被搬動的那根）
  done:  // 已就定位的索引集合 → 綠色柱子
  min / pivot / key / soft / range: // 各演算法專屬記號：最小候選、基準值、
         // 手上的牌、暫時排好的前綴、目前處理的區段（範圍外變淡）
  cmp, swp:  // 到這一步為止的累計比較數、交換／搬移數 → 計數器與記分板
  line:  // C++ 要高亮第幾行（每個演算法有自己的 CODE 陣列）
  title, msg: // 說明面板的標題與內文
  quiz:  // 闖關題（可有可無）：{ q, opts, ans, ansLabel }
}

      注意 arr 是快照不是參考——每一步都複製一份新陣列。這是「可以自由倒退、跳到任何一步」的底氣。

      自己動手：給 AI 的 Prompt

      用 C++ 實作氣泡、選擇、插入、合併、快速五種排序，
全部透過同一個計數函式做比較（每次比較 cmpCnt++、每次交換/搬移 movCnt++）。

步驟：
1. 五個函式吃同一種介面：sort(vector<int>& a)
2. 寫隨機測試：1000 組隨機陣列，驗證五個函式輸出完全相同、且真的排好
3. 對 n = 1000 的三種資料（隨機／已排好／完全逆序）各跑一次，
   印出一張 5×3 的表：每格是「比較次數 / 搬移次數」
4. 把 n 提高到 100000，只跑合併和快速，實測耗時

寫完後回答：
- 表格裡哪一格最出乎你意料？為什麼？
- 選擇排序的比較次數為什麼三種資料都一模一樣？
- 已排好的資料上，插入排序的比較次數是多少？這說明了什麼？

      延伸挑戰二：穩定性的現場證據
