拓撲排序

選課的時候，「資料結構」要先修過「程式設計」和「離散數學」。把每門課畫成一個點、每條先修規定畫成一個箭頭，問題就變成：怎麼把所有點排成一排，讓每個箭頭都往後指？方法很樸素——一直挑「已經沒有先修」的課出來修，修完就把它的箭頭擦掉。看入度一個一個降到 0，課一門一門排進結果。

先搞懂：拓撲排序（Topological Sort）到底是什麼

沒學過程式也看得懂。先把名詞和定義弄清楚，後面的遊戲才不會霧煞煞。

定義：拓撲排序（Topological Sort）

DEFINITION · 拓撲排序 Topological Sort
給一張有向圖，把所有頂點排成一排，使得每一條有向邊 u → v，u 都排在 v 前面。這樣的一排就叫一個拓撲順序。

只有有向無環圖（DAG）才排得出來：只要圖裡有環，就一定排不出來。另外，答案通常不只一種。

同一個定義，換個說法內容
白話有一堆事情，有些事要先做完才能做另一件。拓撲排序就是排出一張「照著做絕對不會卡住」的待辦清單。
看圖把頂點照拓撲順序從左排到右，畫回原本的箭頭——所有箭頭都往右指，沒有一條往左回頭。
用入度說入度＝還有幾門先修沒修完。每次挑一個入度 0（已經沒有先修）的點排出來，再把它的箭頭擦掉、讓別人的入度減 1，一直重複。這就是遊戲裡的 Kahn 演算法。
目的 在一堆「誰要在誰前面」的規定之下，排出一個全部規定都遵守的順序。比喻：大一新生排四年的修課計畫。「程式設計 → 資料結構」的意思是程式設計要先修。只要每門課都排在它所有先修課的後面，這份修課計畫就行得通。
先備 這一關用到第 21 關「圖的基本概念」的頂點、邊、鄰接串列，以及第 22 關「圖的走訪」的佇列和 BFS。還沒玩過的話，先去看那兩關的 00 段。

先認識這些詞（照順序讀，後面的詞會用到前面的）

頂點、邊 vertex / edge
圖由頂點（畫成圓圈，這一關的每個圓圈是一門課或一件事）和邊（連兩個頂點的線）組成。（第 21 關）
課程地圖上的每一門課是一個點，課跟課之間的關係是一條線。
有向邊 directed edge
有方向的邊，畫成箭頭 u → v。這一關它的意思一律是「u 一定要排在 v 前面」。反過來 v → u 是另一條不同的邊。
「程式設計 → 資料結構」：先修程式設計，才能修資料結構。
有向圖 directed graph
每一條邊都是有向邊的圖。第 21、22 關的校園地圖是無向圖（路可以雙向走），這一關換成有向圖。
單行道地圖：每條路只能照箭頭方向走。
入度 / 出度 in-degree / out-degree
入度＝有幾條箭頭指進來；出度＝有幾條箭頭指出去。入度 0 表示沒有任何人要排在它前面。
入度＝這門課有幾門先修；出度＝它是幾門課的先修。
路徑 path
順著箭頭方向，一個頂點接一個頂點走下去的路線，例如 計概 → 程設 → 資結 → 演算法。
一條「先修鏈」：要修演算法，得先一路修完前面那串。
環 cycle
順著箭頭走，最後走回出發點的路徑。例如 X → Y → Z → X。
「修 X 要先修 Y、修 Y 要先修 Z、修 Z 要先修 X」——三門課誰都修不了。
有向無環圖 DAG, directed acyclic graph
有向、而且沒有任何環的圖。只有 DAG 才排得出拓撲順序。
一份寫得正確的先修規定表，不會有人繞圈圈互相卡住。
拓撲順序 topological order
把全部頂點排成一排，每條邊 u → v 都是 u 在前、v 在後。找出這種排法的過程就叫拓撲排序。
一份照著修就不會擋修的四年修課表。
佇列 queue
排隊的資料結構：從後面加入、從前面取出，先進先出（FIFO）。這一關佇列裡放「入度已經是 0、可以排出去的點」。（第 18、22 關）
已經符合資格、在櫃台前排隊等著選課的課。
Kahn 演算法 Kahn's algorithm
做拓撲排序最常見的方法：入度 0 的點進佇列 → 取出一個排進結果 → 擦掉它的出邊、鄰居入度減 1 → 減到 0 的進佇列，重複到佇列空。
每學期把「先修都修完了」的課拿來修，修完就有新的課解鎖。
V、E、O(V+E) 時間複雜度
V＝頂點數，E＝邊數。O(V+E) 的意思是：每個點、每條邊都只處理固定幾次，總工作量跟「點數＋邊數」成正比。
每門課看一次、每條先修規定看一次，就排完了。

有環就排不出來 環上的每一個點都要排在下一個點前面，繞一圈回來，就變成「X 要排在 X 自己前面」，這是不可能的。所以有環的圖沒有任何拓撲順序。遊戲第 4 關會看到：演算法跑到一半佇列就空了，剩下的點卡住，那就是有環的證據。

容易搞混的幾件事

常被搞混的東西跟拓撲排序一樣嗎？差在哪
一般的排序（第 14、20 關）不一樣一般排序比的是數值大小，任兩個都比得出誰大。拓撲排序只看箭頭，沒有箭頭相連的兩個點誰先都可以，所以答案不唯一。
BFS 廣度優先走訪（第 22 關）很像但不同兩個都用佇列。BFS 從一個起點出發，鄰居第一次被看到就進佇列；Kahn 從所有入度 0 的點出發，鄰居要等到入度減到 0（所有先修都排完了）才進佇列。
無向圖不能做無向邊沒有「誰在前」的意思，無法談拓撲順序。拓撲排序只對有向圖有意義。
「入度」和「出度」相反入度數指進來的箭頭（我的先修有幾門），出度數指出去的箭頭（我是幾門課的先修）。Kahn 演算法看的是入度。
有環的圖「排出一部分」不算定義要求所有頂點都排進去。有環時只能排出環以外、而且不被環卡住的那些點，不是拓撲順序。

自我檢查（先自己想，再點開看答案）

選課圖裡，E 演算法的入度是多少？G 物件導向的出度呢？
E 的入度 2：C 資料結構 → E、D 離散數學 → E。G 的出度 0：沒有任何課以物件導向為先修，所以它沒有指出去的箭頭。
選課圖：D B A C E H F G 是拓撲順序嗎？B A C D E F G H 呢？
第一個是：逐條檢查 B→A、A→C、D→C、A→G、C→E、C→F、D→E、E→H，前面的都排在後面的左邊。第二個不是：D 離散數學 → C 資料結構，但 C 排在 D 前面，等於還沒修離散就修資結。
早上出門那張圖，為什麼 A 一定排第一、E 一定排最後？
A 是唯一入度 0 的點，其他點都有人要排在它前面，所以第一個只能是 A。E 是唯一出度 0 的點，而且 B、C、D 都有路徑走到 E（例如 B→D→E），它們全都得排在 E 前面，所以 E 只能最後。
如果規定寫錯，變成「X → Y、Y → Z、Z → X」，為什麼一門都排不出來？
三個點的入度都是 1，沒有任何一個入度是 0，第一個位置沒人能排。換個角度：X 要在 Y 前、Y 要在 Z 前、Z 又要在 X 前，連起來就是 X 要在 X 自己前面——矛盾。

怎麼玩

上面是有向圖，每個圓圈右上角的小數字是它目前的入度。下面三排格子：入度陣列 indeg、佇列（入度 0、等著排出去的點）、結果（已經排好的順序）。被處理過的邊會變成淡淡的虛線，代表「擦掉了」。

演示模式

  1. 挑一個關卡，或自己輸入箭頭（例如 A>B A>C B>D，字母 A～L）。
  2. 按 下一步：先數每個點的入度，再把入度 0 的點放進佇列。
  3. 之後每一輪：從佇列前面取出一個點 → 排進結果 → 擦掉它的出邊、鄰居入度減 1 → 減到 0 的排到佇列後面。
  4. 隨時 上一步 倒回去，反覆走看不懂的地方。

闖關模式

  1. 先不給答案，由你回答：某個點的入度是多少？一開始誰進佇列？下一個取出的是誰？擦掉它的邊後誰的入度變 0？最後有沒有環？
  2. 答對得分、連對加分；答錯立刻解釋正確答案和理由。
操作 鍵盤 → 下一步、← 上一步、空白鍵 播放／暫停。

你會學到什麼

  • 入度就是「還有幾個先修」 —— 入度 0 的點隨時可以排出去。
  • Kahn 演算法 —— 佇列裝「可以排的點」，取出一個、擦掉它的邊、解鎖新的點。
  • 答案不唯一 —— 同時有好幾個點可以排時，挑誰都合法；程式靠固定規則讓結果唯一。
  • 順便抓到環 —— 佇列空了卻還有點沒排，就代表圖裡有環。
  • O(V+E) —— 每個點進出佇列一次、每條邊擦掉一次。

演算法（C++）——玩到哪，亮到哪

Kahn 演算法 · O(V+E)
    — 按「下一步」，這裡會用白話解釋目前亮起的那一行程式在做什麼。
    整份程式逐行白話說明（寫給完全沒學過程式的你）

      這個遊戲跑的程式（完整版）

      把視覺化全部拿掉，Kahn 演算法就這麼短。頂點用 0～n−1 編號（A＝0、B＝1……），adj[u] 是 u 指向的點，照編號由小到大排好——這就是遊戲的平手規則：

      #include <cstdio>
#include <vector>
#include <queue>
using namespace std;

// 回傳一個拓撲順序；如果圖裡有環，回傳空的 vector
vector<int> topoSort(int n, vector<vector<int>>& adj) {
    vector<int> indeg(n, 0);
    for (int u = 0; u < n; u++)              // 數每個點的入度
        for (int v : adj[u]) indeg[v]++;
    queue<int> q;
    for (int u = 0; u < n; u++)              // 入度 0 的點照編號進佇列
        if (indeg[u] == 0) q.push(u);
    vector<int> order;
    while (!q.empty()) {
        int u = q.front(); q.pop();          // 取出佇列最前面的點
        order.push_back(u);                  // 排進結果
        for (int v : adj[u]) {               // 擦掉 u 的每一條出邊
            indeg[v]--;
            if (indeg[v] == 0) q.push(v);    // 先修全修完了 → 排隊
        }
    }
    if ((int)order.size() < n) return {};    // 有點沒排到 → 有環
    return order;
}

int main() {
    // 選課圖：A程設 B計概 C資結 D離散 E演算法 F資料庫 G物件 H人工智慧
    int n = 8;
    vector<vector<int>> adj(n);
    auto edge = [&](char u, char v) { adj[u - 'A'].push_back(v - 'A'); };
    edge('A','C'); edge('A','G');            // 每個點的鄰居照字母順序加入
    edge('B','A');
    edge('C','E'); edge('C','F');
    edge('D','C'); edge('D','E');
    edge('E','H');
    vector<int> order = topoSort(n, adj);
    if (order.empty()) printf("有環，排不出來\n");
    for (int u : order) printf("%c ", 'A' + u);   // 印出 B D A C G E F H
    printf("\n");
}

      如果想要「佇列裡永遠先取字母最小的」，把 queue<int> 換成 priority_queue<int, vector<int>, greater<int>>、q.front() 換成 q.top() 就好。結果會不一樣（例如選課圖變成 B A D C E F G H），但一樣合法。這一頁的動畫用的是普通佇列，跟上面的程式一致。

      03

      這個功能是怎麼做到的

      從「一直挑沒有先修的課」這個直覺，到 O(V+E) 的 Kahn 演算法。

      問題定義

      輸入：一張有向圖，V 個頂點、E 條有向邊；每條邊 u → v 代表「u 要排在 v 前面」。

      輸出：一個包含全部 V 個頂點的順序，讓每條邊的起點都在終點左邊；如果圖裡有環、根本排不出來，要回報有環。

      破除錯誤直覺：照名字排？照先修門數排？都不行

      用選課圖試兩種「看起來很合理」的排法：

      排法排出來的順序哪裡錯
      照代號（字母）排A B C D E F G HB 計概 → A 程設 被倒過來：還沒修計概就修程設。D 離散 → C 資結 也倒過來了。代號跟先後規定一點關係都沒有。
      照「先修門數」（入度）由少到多排B D ｜ A F G H ｜ C EF 資料庫、H 人工智慧都只有 1 門先修，就排到有 2 門先修的 C 資結、E 演算法前面——但 C → F、E → H，資料庫要先修資結、AI 要先修演算法。
      為什麼會錯 入度只看「直接指進來的箭頭有幾條」，看不到更上游的一整串。H 人工智慧雖然只有 1 門直接先修，但那門（演算法）自己又要先修資結、離散，資結又要先修程設、程設又要先修計概……一路往回推，共有 5 門課都得排在它前面。所以入度不能只算一次就拿來排——要邊排邊更新。

      關鍵觀察：DAG 裡一定有入度 0 的點

      假設一張圖每個點的入度都 ≥ 1。隨便挑一個點，沿著某條指進來的箭頭往回走一步；到了新的點，它也有箭頭指進來，再往回走……可以一直走下去。但圖只有 V 個點，走 V 步之內一定會走到走過的點——這就繞出一個環了。

      • 所以：沒有環 ⇒ 一定有入度 0 的點。它沒有任何先修，放在第一個絕對安全。
      • 拿掉它之後，剩下的圖還是 DAG（拿掉點不會變出新的環），所以又會有新的入度 0 的點。一直重複，就能把全部的點排完。
      • 反過來：如果做到一半，剩下的點入度全都 ≥ 1，照上面的往回走論證，剩下的點裡一定有環。這就是 Kahn 演算法偵測環的原理。

      演算法：Kahn 演算法

      1. 數入度 —— 看過每一條邊 u → v，讓 indeg[v] 加 1。
      2. 入度 0 的點進佇列 —— 照編號（字母）順序放進去。
      3. 取出佇列最前面的點 u，把 u 排到結果的最後面。
      4. 擦掉 u 的每一條出邊 u → v：indeg[v] 減 1。如果減到 0，v 的先修全排完了，把 v 排到佇列後面。
      5. 重複 3、4，直到佇列空了。
      6. 檢查 —— 結果有 V 個點：完成；少於 V 個：圖裡有環，剩下沒排到的點就是卡在環上或被環擋住的點。
      一句話 佇列裡永遠只放「現在就可以排」的點；每排一個，就可能解鎖新的點。

      手算一次：選課圖

      考試在紙上追蹤時就是畫這張表。開始時入度：A1 B0 C2 D0 E2 F1 G1 H1，佇列（前 → 後）＝ B D。

      取出擦掉出邊後的入度變化佇列（前 → 後）結果
      B 計概A：1 → 0，進佇列D AB
      D 離散C：2 → 1；E：2 → 1AB D
      A 程設C：1 → 0，進佇列；G：1 → 0，進佇列C GB D A
      C 資結E：1 → 0，進佇列；F：1 → 0，進佇列G E FB D A C
      G 物件（沒有出邊）E FB D A C G
      E 演算法H：1 → 0，進佇列F HB D A C G E
      F 資料庫（沒有出邊）HB D A C G E F
      H 人工智慧（沒有出邊）（空）B D A C G E F H

      佇列空了，結果有 8 個點 ＝ V，完成：B D A C G E F H。每個點進出佇列各 1 次，每條邊擦掉 1 次（8 條）。這張圖其實一共有 48 種合法的修課順序，這只是其中一種。

      複雜度：為什麼是 O(V+E)

      • 數入度 O(V+E) —— 每個點的鄰接串列看一遍，等於每條邊看 1 次。
      • 佇列 O(V) —— 每個點入度變 0 只會發生 1 次，所以每個點最多進佇列 1 次、出佇列 1 次。
      • 擦邊 O(E) —— 點 u 被取出時才看它的出邊，而每個點只被取出 1 次，所以每條邊只被擦 1 次。
      • 合計 O(V+E)，額外空間 O(V)（indeg 陣列、佇列、結果）。
      對照 如果每一輪都「把所有點掃一遍，找一個入度 0 的」，要做 V 輪、每輪 O(V)，變成 O(V²)。用佇列把「已經可以排的點」記下來，就不用每輪重找。

      另一種做法：DFS 的「反後序」

      第 22 關的 DFS 也能做拓撲排序。重點是記錄每個點「完成」的時間：一個點要等它往下能走到的點全部走完，才算完成，然後記到一張清單上（這叫後序）。最後把這張清單倒過來，就是拓撲順序。

      • 為什麼對：有邊 u → v 時，v 一定比 u 先完成（u 要等 v 走完）。倒過來之後，u 就排在 v 前面。
      • 選課圖（從 A 開始、鄰居照字母順序）：完成的順序是 H E F C G A B D，倒過來是 D B A G C F E H——跟 Kahn 的答案不同，但一樣合法。
      • 不能用「拜訪的順序」（前序）：從 A 開始拜訪會先碰到 A，但 B 計概 → A 程設，B 必須在 A 前面。一定要用完成的順序倒過來。
      • 找環：DFS 時如果沿著邊走到一個「已經開始、但還沒完成」的點，就是繞回自己的祖先——有環。

      實際用途

      情境頂點邊 u → v
      編譯程式（make、各種建置工具）每個要產生的檔案v 要用到 u 的結果，所以先建 u
      試算表（Excel 重新計算）每個儲存格v 的公式用到 u（例如 C1 = A1 + B1）；出現環時 Excel 會跳出「循環參照」警告
      專案排程每個工作u 做完 v 才能開始（遊戲第 5 關）
      安裝套件（npm、apt）每個套件v 依賴 u，要先裝 u
      排修課計畫每門課u 是 v 的先修（遊戲第 2 關）

      常見誤解

      • 「拓撲排序的答案只有一個」 —— 通常有很多個。選課圖有 48 種，第 5 關的專案圖有 297 種。課本或程式給的只是「照某條平手規則排出來的那一個」。
      • 「Kahn 就是 BFS」 —— 結構很像，但 BFS 只要鄰居第一次被看到就排隊；Kahn 要等鄰居的入度減到 0 才排隊。第 2 關的 C 資料結構，被 A 擦邊時才變 0，被 D 擦邊時還是 1，不能提早排隊。
      • 「一開始把入度算好，照入度排就好」 —— 不行（見上面的反例），入度要邊排邊減。
      • 「有環的話，排出來的那一部分也算答案」 —— 不算。定義要求全部頂點都排進去；結果少於 V 個時，正確的回應是「有環，排不出來」。
      • 「剩下沒排到的點全部都在環上」 —— 不一定。第 4 關的 F 畢業審查不在環上，只是它的先修 E 卡在環裡，所以它也排不出來。
      下一關 拓撲排序處理的是「有方向、有先後」的圖。下一關回到有權重的無向圖：海大校園要鋪網路線，怎麼用最少的線把所有建築連起來？→ 第 24 關「最小生成樹」（Prim、Kruskal＋併查集）。

      程式架構與說明

      只講流程與分工，不逐行拆解。看懂這一段，你就能自己改這個遊戲。

      整體設計：先算完，再播放

      跟前面幾關一樣：使用者按「下一步」之前，整個 Kahn 演算法就已經跑完了。buildSteps 每做一個小動作（數入度、取出、擦一條邊……）就存一份入度陣列、佇列、結果、已擦掉的邊的快照；畫面只負責把第 N 步畫出來。

      關卡 v：頂點（代號、名稱、座標）　e："A>B A>C …"
      buildSteps(level) Kahn 演算法整個跑完一次；最後檢查有沒有環
      steps[] 每一格：indeg + 佇列 + 結果 + 擦掉的邊 + 說明 + 闖關題
      畫面只負責把 steps[目前步數] 畫出來
      • 前進後退變成加減一 —— 不必寫「把擦掉的邊畫回去」這種容易錯的邏輯。
      • 環也是先算好的 —— 最後一步若有點沒排到，buildSteps 會沿著「指進來的邊」往回走，找出一個環存在 step 裡，畫面只要把它塗紅。

      自己動手：給 AI 的 Prompt

      用 C++ 實作拓撲排序（Kahn 演算法），不要用任何圖論函式庫。

輸入：n 個頂點（0~n-1）、有向邊清單 {u, v}，意思是 u 要排在 v 前面。
需要的函式：
- vector<int> topoSort(int n, vector<vector<int>>& adj)   // 有環時回傳空的 vector

要求：
1. 用 indeg 陣列記錄入度、用 queue<int> 放入度 0 的點
2. 每取出一個點，印出「取出誰、哪些點的入度變了、佇列現在是什麼」
3. 用這張選課圖測試（A=0…H=7）：B→A A→C D→C A→G C→E C→F D→E E→H
   答案應該是 B D A C G E F H
4. 再加一條 H→C 讓它出現環，確認函式會回報有環，並印出沒排到的點
5. 解釋為什麼時間複雜度是 O(V+E)
