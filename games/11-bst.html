二元搜尋樹種樹

丟一個數字進去，看它一路比大小往下掉：比誰小就往左、比誰大就往右，最後長在唯一屬於它的位置。搜尋走同一條路，刪除節點的三種情況也一步一步演給你看。

怎麼玩・你會學到什麼

怎麼玩

畫面上是一棵樹：每個圓圈是一個「節點」，裡面裝一個數字。橘色小方塊是「掉落中的數字」，它每停在一個節點，就跟那個節點比一次大小，決定往左還是往右。

演示模式

  1. 從上方挑一個關卡：種樹、搜尋、三種刪除都有，也可以自己輸入一串數字來種。
  2. 按 下一步 看數字一格一格往下掉；或按 自動播放。
  3. 邊走邊看三件事同步變化：樹的形狀、右側「中序走訪」的輸出、下方 C++ 程式的高亮行。
  4. 看不懂就按 上一步 倒回去，反覆走。

闖關模式

  1. 先不給答案，由你猜：下一步往左還是往右？這個數字最後會種在誰底下？刪這個節點是三種情況中的哪一種？
  2. 答對得分、連對加分；答錯立刻告訴你正確答案和理由。
操作 鍵盤 → 下一步、← 上一步、空白鍵 播放／暫停。

你會學到什麼

  • BST 的家規：左小右大 —— 任何節點的左子樹全部比它小、右子樹全部比它大。插入、搜尋、刪除全靠這一條。
  • 搜尋為什麼快 —— 每比一次就丟掉半棵樹不用看，成本只跟「樹高」有關，平均 O(log n)。
  • 中序走訪＝自動排序 —— 照「左→根→右」把樹走一遍，數字就由小到大跑出來。這是 BST 最漂亮的性質。
  • 刪除的三種情況 —— 葉節點直接摘、單子節點讓孩子頂上、雙子節點要找「中序後繼」來替班。少會一種就不算會刪。
  • 退化成鏈的陷阱 —— 把排好序的數列照順序種進去，樹會歪成一條 O(n) 的長鏈，這正是 AVL、紅黑樹存在的理由。
  • 把遞迴讀成畫面 —— insert 裡再呼叫 insert，就是「機器裡再開一台小機器」，畫面會讓你看見它一層一層往下鑽。
建議順序 先玩「種一棵漂亮的樹」建立直覺，再玩「陷阱：照順序種」看樹歪掉，最後把三個刪除關都走過一遍，切闖關模式驗收。

演算法（C++）——玩到哪，亮到哪

insert / search / remove
    — 按「下一步」，這裡會用白話解釋目前亮起的那一行程式在做什麼。
    整份程式逐行白話說明（寫給完全沒學過程式的你）

      這個遊戲跑的程式（完整版）

      把教學用的視覺化全部拿掉，演算法本體就是這樣。struct Node 定義節點、三個函式對應遊戲裡的三種操作，inorder 就是右側那行「中序走訪」：

      #include <cstdio>

struct Node { int val; Node *left, *right; };          // 節點：一個數字 + 兩個指向孩子的指標

Node* insert(Node* root, int x) {                      // 插入：回傳插入後這棵子樹的根
    if (root == NULL) return new Node{x, NULL, NULL};  // 掉到空位 → 新節點在這裡誕生
    if (x < root->val)      root->left  = insert(root->left,  x);
    else if (x > root->val) root->right = insert(root->right, x);
    return root;                                       // 相等：已經有了，不重複種
}

bool search(Node* root, int x) {
    if (root == NULL)   return false;                  // 掉出樹外 → 樹裡沒有這個數
    if (x == root->val) return true;                   // 找到了
    return x < root->val ? search(root->left,  x)
                         : search(root->right, x);     // 小往左找、大往右找
}

Node* removeNode(Node* root, int x) {                  // 取名 removeNode，避免和 cstdio 的 remove 撞名
    if (root == NULL) return NULL;
    if (x < root->val)      root->left  = removeNode(root->left,  x);
    else if (x > root->val) root->right = removeNode(root->right, x);
    else {                                             // 就是這個節點，分三種情況
        if (!root->left && !root->right) { delete root; return NULL; }       // ① 葉節點：直接摘
        if (!root->left)  { Node* r = root->right; delete root; return r; }  // ② 只有右孩子：頂上
        if (!root->right) { Node* l = root->left;  delete root; return l; }  // ② 只有左孩子：頂上
        Node* s = root->right;                         // ③ 兩個孩子：找中序後繼
        while (s->left) s = s->left;                   //    右子樹一路向左＝最小的
        root->val = s->val;                            //    把後繼的值搬過來
        root->right = removeNode(root->right, s->val); //    再把原本的後繼刪掉
    }
    return root;
}

void inorder(Node* root) {                             // 中序走訪：左 → 根 → 右
    if (root == NULL) return;
    inorder(root->left);
    printf("%d ", root->val);
    inorder(root->right);
}

int main() {
    int a[] = {50, 30, 70, 20, 40, 60, 80};
    Node* root = NULL;
    for (int v : a) root = insert(root, v);
    inorder(root);                    // 印出：20 30 40 50 60 70 80 —— 自動排好序！
    root = removeNode(root, 50);      // 刪掉樹根：中序後繼 60 會頂上來
}

      三個函式各十行上下。遊戲頁面多出來的幾百行，全部是為了「讓掉落的過程看得見」——教學程式和生產程式的差別就在這裡。

      03

      這個功能是怎麼做到的

      從問題定義走到完整演算法，中間每一個判斷為什麼非要不可。

      問題定義

      我們要一本「隨時會變動的名冊」：數字會不斷加入（插入）、要能很快查到某個數字在不在（搜尋）、也會被拿走（刪除）。二元搜尋樹（BST）用一條家規解決全部三件事：

      家規 對每一個節點：左子樹裡的數全部比它小，右子樹裡的數全部比它大。（本頁不收重複數字。）

      「子樹」就是從某個節點往下的整串家族。注意家規管的是整棵子樹，不是只有直接的孩子：

      情況（樹根是 50）結果原因
      40 在 50 的左子樹合法40 < 50，小的住左邊
      60 在 50 的右子樹合法60 > 50，大的住右邊
      60 藏在 50 的左子樹深處不合法不管藏多深，比 50 大就不准出現在左邊
      同一個數出現兩次不收不小也不大，沒地方擺——insert 直接略過

      生活比喻：圖書館的分類架。站在任何一格前面，「編號比較小的一定在左邊那區、比較大的一定在右邊那區」——所以你永遠不用整館翻，一路問下去就到了。

      先破除一個直覺：「用排好序的陣列不就好了？」

      排序陣列配二分搜尋，查東西也是 O(log n)，看起來跟 BST 打平。但名冊是會變動的——插入和刪除一比，勝負立刻分出來：

      操作排序陣列二元搜尋樹（平均）
      搜尋O(log n)（二分搜尋）O(log n)
      插入O(n)O(log n)
      刪除O(n)O(log n)
      由小到大輸出O(n)O(n)（中序走訪）
      • 陣列插入要「搬家」 —— 想把 45 插進 [10,20,…,90] 的中間，後面每一個數都得往右挪一格，一百萬筆就挪一百萬次。
      • 刪除一樣慘 —— 抽掉中間一格，後面全部往左補。
      關鍵 樹用指標把節點串起來，插入刪除只要改幾張「名片」（指標），完全不用搬動其他人。這就是「用指標換掉搬家成本」。

      關鍵觀察一：每比一次，就丟掉半棵樹

      找 65：跟 50 比，65 比較大 → 左半邊整片從此不用看；跟 70 比，65 比較小 → 70 的右邊整片不用看。每一步都把「可能的範圍」砍掉一大塊，所以總步數＝走過的層數＝樹高。

      一棵長得勻稱的樹，每往下一層節點數大約翻倍：高度 h 的樹裝得下約 2h−1 個節點。反過來說，n 個節點只需要約 log₂n 層——一百萬個數字，20 次比較就見底。

      關鍵觀察二：中序走訪＝排序輸出

      「中序走訪」的規則只有一句：對每個節點，先走完左子樹、再輪到自己、最後走右子樹。因為家規保證「左邊全部較小、右邊全部較大」，這個順序印出來的就是由小到大。

      玩的時候盯著右側「中序走訪」面板：不管樹被插入、刪除成什麼形狀，那一行永遠保持排好序——只要它亂掉，就代表家規被破壞了。這也是檢查「一棵樹是不是合法 BST」最實用的方法。

      演算法（一）：插入

      1. 從樹根出發 —— 新數字 x 跟目前節點比大小。
      2. 比它小 → 往左；比它大 → 往右 —— 走到孩子那裡，重複同一件事（這就是遞迴：同樣的問題丟給小一號的子樹）。
      3. 掉到空位（NULL） —— 就地生出新節點裝 x。掉落路線是被大小關係唯一決定的，所以每個數字有唯一的家。
      4. 相等 —— 已經有了，什麼都不做。
      重點 新節點永遠長在最下面（原本的空位上），絕不會插在兩個舊節點中間——所以插入不用搬動任何人。

      演算法（二）：搜尋

      跟插入走一模一樣的路：小往左、大往右、相等就是找到。唯一多的一條是——掉出樹外（NULL）＝確定不存在。

      為什麼一條路就能斷定？因為如果 x 在樹裡，家規逼著它只可能長在這條路的終點。終點是空的，全樹就都不用再看了。

      演算法（三）：刪除的三種情況

      情況長相作法本頁關卡
      ① 葉節點沒有任何孩子直接摘掉，爸爸的指標改成 NULLdel 20
      ② 單子節點只有一個孩子把孩子那整棵子樹往上接，頂替自己的位置del 70
      ③ 雙子節點左右都有孩子去右子樹找最小的（中序後繼）把值抄過來，再回頭刪掉那個後繼del 50

      情況③是精華。左右都有人時不能直接摘——兩棵子樹會沒地方掛。解法是找「中序後繼」：比 x 大的數裡最小的那一個，也就是右子樹一路向左走到底。用它的值頂替 x 的位置，「左邊仍然全部較小、右邊剩下的仍然全部較大」，家規自動保持成立。而那個後繼因為已經「靠左靠到底」，最多只剩右孩子，回頭刪它一定落在①或②的簡單情況——問題保證會變簡單，不會鬼打牆。

      Node* removeNode(Node* root, int x) {
    if (root == NULL) return NULL;                     // 沒找到，不用刪
    if (x < root->val)      root->left  = removeNode(root->left,  x);   // 目標在左邊
    else if (x > root->val) root->right = removeNode(root->right, x);   // 目標在右邊
    else {                                             // 就是它！分三種情況
        if (!root->left && !root->right) { delete root; return NULL; }       // ①
        if (!root->left)  { Node* r = root->right; delete root; return r; }  // ②
        if (!root->right) { Node* l = root->left;  delete root; return l; }  // ②
        Node* s = root->right;                         // ③ 找中序後繼：
        while (s->left) s = s->left;                   //   右子樹一路向左到底
        root->val = s->val;                            //   值頂替上來
        root->right = removeNode(root->right, s->val); //   回頭刪掉後繼本人
    }
    return root;
}
      最常錯 雙子節點不能「隨便挑一個孩子接上來」。刪 50 時把左孩子 30 直接頂上，30 的右邊就得同時塞下 40 和整棵 70——結構直接爆掉。必須用中序後繼（或對稱的中序前驅）。

      手算一次：依序插入 50, 30, 70, 20, 40, 60, 80

      考試在紙上追蹤就是畫這張表。「路徑」欄記的是每一次比大小的結果：

      插入路徑（每一步的比較）種在哪樹高
      50樹是空的成為樹根1
      3030<50 ↙50 的左孩子2
      7070>50 ↘50 的右孩子2
      2020<50 ↙ → 20<30 ↙30 的左孩子3
      4040<50 ↙ → 40>30 ↘30 的右孩子3
      6060>50 ↘ → 60<70 ↙70 的左孩子3
      8080>50 ↘ → 80>70 ↘70 的右孩子3

      七個數字、高度只有 3——每個數字最多比 3 次就到家。這是「勻稱」的樹。

      陷阱：排好序再種，樹會歪成一條鏈

      換成依序插入 10, 20, 30, 40, 50, 60：每個新數字都比路上遇到的所有人大，一路往右、往右、再往右——種出一條「歪脖子」長鏈，高度＝節點數。

      • 搜尋退化成 O(n) —— 每次只丟掉「一個節點」而不是半棵樹，跟從頭到尾掃一遍的串列沒兩樣。
      • 越有秩序的輸入，種出越糟的樹 —— 這是 BST 最大的諷刺：資料剛好排過序，反而是最壞情況。
      伏筆 所以真實世界用的是會自動轉正的平衡樹——AVL 樹、紅黑樹。它們在插入刪除時做「旋轉」把歪掉的地方扶正，保證高度永遠是 O(log n)。C++ 的 std::map、std::set 底下就是紅黑樹。

      複雜度

      • 三種操作都是 O(樹高) —— 插入、搜尋、刪除走的都是「樹根到某處」的一條路，成本由樹高決定。
      • 平均 O(log n) —— 插入順序夠隨機時，樹高大約是 log₂n 的常數倍。
      • 最壞 O(n) —— 排好序的輸入把樹種成鏈，樹高＝n。
      • 空間 O(n) —— n 個節點各存一個值加兩個指標；遞迴另外吃 O(樹高) 的呼叫堆疊。

      常見誤解

      • 「BST 會自己保持平衡」 —— 不會。普通 BST 的形狀完全由插入順序決定，照順序插就退化成鏈。自動平衡是 AVL／紅黑樹加上去的能力。
      • 「家規只要管直接的孩子」 —— 錯。是整棵左子樹都要比它小。反例：60 放在 50 的左孫位置，每對父子局部都合法，整棵卻是壞的。
      • 「搜尋不到要把整棵樹翻完才能確定」 —— 不用。一條路走到 NULL 就足以斷定不存在，因為它「只可能」在那條路的終點。
      • 「刪雙子節點可以把某個孩子直接接上來」 —— 不行，另一棵子樹會沒地方掛。要用中序後繼（右子樹最小）或中序前驅（左子樹最大）頂替。
      • 「中序後繼要先排序才找得到」 —— 不用排序。右子樹一路向左走到底，就是後繼本人。

      給 AI 的 Prompt

      想讓 AI 幫你重做或擴充這一關？把下面這段貼給它，就能得到同等級的成品：

      請用純 HTML+CSS+JS（單一檔案、不用框架、離線可用）做一個「二元搜尋樹」互動教學頁：
1. 用 SVG 畫樹：x 座標＝節點的中序順位、y 座標＝深度，節點是圓圈＋數字。
2. 演算法先跑完產生 steps[]，每一步存整棵樹的深拷貝快照；畫面只畫 steps[目前步]。
   支援 下一步/上一步/自動播放/進度條/鍵盤 → ← 空白鍵。
3. 插入動畫：掉落中的數字停在目前比較的節點上方，顯示「比它小→往左 / 比它大→往右」，
   掉到 NULL 就種下新節點。搜尋同一條路，多「相等=找到 / 掉出樹外=不存在」。
4. 刪除三情況逐步演：葉節點淡出直接摘；單子節點讓孩子頂上；雙子節點先走右子樹
   一路向左找中序後繼，把值抄過來，再回頭刪掉後繼。
5. 關卡：漂亮的樹（50 30 70 20 40 60 80）、退化鏈（10 20 30 40 50 60，帶出 O(n)
   與平衡樹伏筆）、搜尋命中/未命中、三種刪除各一，另允許使用者輸入數列種樹。
6. 附一個逐行高亮的真 C++ 面板（struct Node + 遞迴 insert/search/remove），
   每行配一句給零基礎讀者的白話說明，遞迴用「機器裡再開一台小機器」比喻。
7. 加闖關模式：猜下一步往左/往右、猜數字最後種在誰底下、猜刪除是哪一種情況，
   答對計分、連對加分、答錯立刻解釋。

      延伸挑戰

      1. 找最小／最大按鈕 —— 加兩顆按鈕：最小值＝從樹根一路向左到底、最大值＝一路向右。在 buildSteps 加一種新 op，重用現有的 goL/goR 步驟就能做出動畫。
      2. 改用中序前驅刪除 —— 把情況③改成「左子樹一路向右找最大」來頂替，對同一棵樹分別執行兩種刪法，比較刪完的樹形有什麼不同。
      3. 退化偵測器 —— 當「樹高 == 節點數且節點數 ≥ 4」時，在說明面板跳出警告並建議讀 AVL 樹。再進一步：實作一次「左旋」把三個一直線的節點轉成三角形，你就摸到平衡樹的門把了。
