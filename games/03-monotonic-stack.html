Game 03 · Monotonic Stack

單調堆疊

面試出現率最高的堆疊技巧，把 O(n²) 的暴力解壓成 O(n)。整題只有一句話要想通：「當我發現一個更矮的，前面那些還在等待的就可以結算了。」

核心結構堆疊 Stack

01

怎麼玩・你會學到什麼

兩道經典題，其實是同一題。

怎麼玩

  1. 上方切換兩道題目：柱狀圖最大矩形（LC 84）或 每日溫度（LC 739）。
  2. 選一組範例數字，或自己輸入（逗號分隔，最多 24 個）。
  3. 按 下一步 一格一格走，看堆疊什麼時候 push、什麼時候一口氣彈出好幾個。
  4. 柱狀圖模式會即時畫出正在結算的矩形（綠色虛線）和目前最大的矩形（橘色實線）。
  5. 看不懂就按 上一步 倒回去，或按 隨機 換一組數字再看一次。
盯著這個數字 右邊的 總 push+pop 欄位。不管你輸入什麼，它永遠不會超過 2n —— 這就是「為什麼有巢狀 while 迴圈卻仍然是 O(n)」的親眼證據。

你會學到什麼

  • 換個角度枚舉 —— 不枚舉「所有區間」（n² 個），改枚舉「誰當高度」（n 個）。這是整題的轉折點。
  • 「等待 ↔ 結算」的模式 —— 堆疊裡放的是「還沒定案、正在等右邊界」的元素。
  • 單調性是副產品，不是刻意維護的 —— 因為「來了更矮的就馬上結算」，留下來的自然遞增。
  • 左邊界是免費的 —— 彈出時堆疊裡它下面那個，剛好就是左邊第一個比它矮的。
  • 哨兵（sentinel）技巧 —— 尾巴補一根高度 0，就不用另外寫收尾程式碼。
  • 攤還分析 —— 每個元素一生最多 push 一次、pop 一次，所以總操作 ≤ 2n。
  • 一招通吃一族題目 —— 接雨水、股票跨度、下一個更大元素，全是同一個模板。
建議順序 先玩每日溫度（比較單純，只要記天數），看懂「等待 ↔ 結算」之後，再回頭玩柱狀圖（多了左右邊界的計算）。

      這個遊戲跑的程式（完整版）

      // ① 柱狀圖最大矩形（LC 84）—— 堆疊遞增
#include <stack>
#include <vector>
using namespace std;

int largestRectangle(vector<int> h) {
    h.push_back(0);                          // 哨兵！逼堆疊在結束前清空
    stack<int> st;                           // 存索引，不是高度
    int best = 0;
    for (int i = 0; i < (int)h.size(); i++) {
        while (!st.empty() && h[st.top()] >= h[i]) {   // 來了更矮的 → 結算
            int top = st.top(); st.pop();
            int height = h[top];
            int left = st.empty() ? 0 : st.top() + 1;  // 左界＝下面那根的右邊一格
            int width = i - left;                      // 右界＝現在這根
            best = max(best, height * width);
        }
        st.push(i);
    }
    return best;
}
      // ② 每日溫度（LC 739）—— 堆疊遞減，只有比較符號反過來
vector<int> dailyTemperatures(const vector<int>& t) {
    vector<int> ans(t.size(), 0);
    stack<int> st;
    for (int i = 0; i < (int)t.size(); i++) {
        while (!st.empty() && t[st.top()] < t[i]) {    // 來了更暖的 → 結算
            int j = st.top(); st.pop();
            ans[j] = i - j;                            // 等了幾天
        }
        st.push(i);
    }
    return ans;                  // 留在堆疊裡的，答案就是預設的 0
}

      兩段程式碼只差一個比較符號和結算那一行。把它們並排看，就看得出「單調堆疊」是一個模板而不是兩個演算法。

      這個功能是怎麼做到的

      從暴力解開始，因為要先知道浪費在哪。

      題目一：柱狀圖中最大的矩形（LeetCode 84）

      給一個非負整數陣列 heights，代表一排柱子的高度，每根寬度都是 1。找出能在這張柱狀圖裡畫出的最大矩形面積（矩形必須完整落在柱子內，可以橫跨連續多根）。

      輸入輸出
      [2,1,5,6,2,3]10

5 │       ██ ██        ← 最大矩形：以高度 5 橫跨第 2、3 根
4 │       ██ ██           面積 = 5 × 2 = 10

      關鍵限制 矩形的高度會被區間裡最矮的那根壓死。橫跨第 2、3 根時高度只能是 min(5,6)=5；貪心地想用高度 6，就只能佔 1 格，面積剩 6。

      題目二：每日溫度（LeetCode 739）

      給一個陣列，第 i 個元素是第 i 天的氣溫。對每一天回答：還要等幾天才會遇到比今天更暖的日子？如果之後都不會更暖，答 0。

      輸入輸出
      [73,74,75,71,69,72,76,73][1,1,4,2,1,1,0,0]

      第 0 天 73°，隔天就 74° → 等 1 天。第 2 天 75°，要一路等到第 6 天的 76° → 等 4 天。第 6 天 76° 是最高溫，之後再也沒更暖的 → 0。

      這兩題其實是同一題

      翻譯 兩題都在問同一句話：「對每個元素，找出它右邊第一個比它小（或比它大）的元素在哪裡。」
      • 每日溫度 → 直接就是在問「右邊第一個更大的元素」。
      • 柱狀圖 → 以第 i 根為高的矩形，左界是「左邊第一個比它矮的」，右界是「右邊第一個比它矮的」。
        面積 = h[i] × (右界 − 左界 − 1)

      這類問題有個共同名字：Next Greater / Next Smaller Element，而它們的共同解法就是單調堆疊。

      第 0 步：先寫暴力解，才知道浪費在哪

      int brute(const vector<int>& h) {        // O(n²)
    int best = 0;
    for (int i = 0; i < (int)h.size(); i++) {
        int lo = h[i];
        for (int j = i; j < (int)h.size(); j++) {
            lo = min(lo, h[j]);              // 區間最小值 = 矩形高度
            best = max(best, lo * (j - i + 1));
        }
    }
    return best;
}

      正確，但每個區間都重算一次最小值。n = 10 萬時要跑 50 億次 —— 面試直接掛。

      浪費點 「第 3 根左邊第一個比它矮的是誰」這件事，被重複問了無數次。

      第 1 步：換個角度枚舉

      不要枚舉「所有區間」（有 n² 個），改成枚舉「誰當這個矩形的高度」（只有 n 個）。

      對第 i 根柱子，答案就是：它能往左右延伸多遠而不被更矮的柱子擋住。問題瞬間變成：找左邊第一個比它矮的、右邊第一個比它矮的。

      第 2 步：關鍵洞察（整題只有這一個要想通）

      我們從左往右掃。掃到第 i 根時，前面那些柱子的右邊界還不知道，所以它們只能先掛在那裡等。問題是：這些「等待中」的柱子要用什麼結構存？

      洞察 如果 j < i 而且 h[j] ≥ h[i]，那第 j 根可以馬上結算，永遠不必再等。

      為什麼？因為任何想跨過第 i 根的矩形，高度都會被 h[i] 壓下去，不可能再用到 h[j] 這麼高。所以第 i 根就是第 j 根的右邊界 —— 現在就能算出它的答案。

      而「馬上結算並丟掉」的直接後果是：能留在容器裡的柱子，必定由下往上遞增。

      名字的由來 這就是「單調」堆疊的由來 —— 單調不是我們刻意維護的，是規則的副產品。很多人把因果搞反了，以為要先想辦法維持單調，其實反過來。

      第 3 步：左邊界是免費送的

      彈出第 j 根時，堆疊裡緊接在它下面的那根，正好就是「左邊第一個比它矮的柱子」—— 因為中間所有比它高的都已經被彈掉了，比它矮的又不可能還留在下面。

      left  = st.empty() ? 0 : st.top() + 1;  // 左界：下面那根的右邊一格；堆疊空代表能一路延伸到最左
right = i - 1;                          // 右界：現在這根的左邊一格
width = right - left + 1 = i - left
area  = h[j] * width

      兩個邊界都是 O(1) 拿到的 —— 這正是暴力解要花 O(n) 去掃的東西。

      第 4 步：哨兵，處理「永遠等不到」的柱子

      如果柱子一路遞增（例如 [1,2,3,4,5]），掃到最後堆疊裡還塞著一整排沒結算的柱子。

      賴皮但漂亮 在陣列尾巴補一根高度 0 的假柱子。它比誰都矮，會逼著堆疊全部彈空 —— 於是不用再寫一段重複的收尾程式碼。

      這招叫哨兵（sentinel），在鏈結串列（dummy head）、字串處理（補結束符）都會再看到。在上面的遊戲裡，柱狀圖模式最右邊那根斜線柱子就是它。

      第 7 步：為什麼是 O(n)（攤還分析）

      暴力解 O(n²)

      • 對每根柱子，往左掃到比它矮的、往右掃到比它矮的
      • 10 萬根柱子 → 100 億次比較，跑不完
      • 浪費在哪：同一段區間被重複掃了無數次

      單調堆疊 O(n)

      • 堆疊裡放「還在等右邊界的柱子」，高度保持遞增
      • 來了一根更矮的 → 它就是右邊界，把比它高的通通結算
      • 省在哪：「誰比我矮」被堆疊順手記住了，不用重掃
      暴力解單調堆疊
      時間O(n²)O(n)
      空間O(1)O(n)（最壞：全遞增）
      論證雙層迴圈每個索引最多 push 一次、pop 一次 → 總操作 ≤ 2n

      巢狀的 while 不代表 O(n²)：要看的是整趟下來的總操作次數，不是單次迴圈的最壞情況。這個技巧叫攤還分析，你可以在遊戲右邊的「總 push+pop」欄位親眼驗證它永遠 ≤ 2n。

      兩題並排比較

      柱狀圖最大矩形每日溫度
      堆疊裡存什麼索引（還沒定案的柱子）索引（還在等更暖那天）
      單調方向遞增（由下往上變高）遞減（由下往上變冷）
      什麼時候彈出來了更矮的 h[top] >= h[i]來了更暖的 t[top] < t[i]
      彈出時算什麼面積 = 高 × (右界 − 左界)天數 = i − top
      沒被彈到的怎麼辦用哨兵 0 逼它們全部出場答案就是 0（之後都沒更暖的）
      時間複雜度O(n)O(n)

      五個最常見的錯誤

      • 堆疊存高度而不存索引 —— 算寬度時沒有位置資訊，整題卡死。永遠存索引，高度用 h[idx] 查。
      • 左界寫成 st.top() —— 少算一格。正確是 st.top() + 1，堆疊空時是 0。
      • 忘記哨兵 —— 遞增陣列 [1,2,3] 直接回傳 0，因為沒有任何元素被結算。
      • 先 push 再檢查 —— 順序反了。必須「先把該結算的彈完，才輪到自己進場」。
      • 每日溫度把 < 寫成 <= —— 同溫度的日子被誤判成「更暖」，答案全錯。

      程式架構與說明

      只講流程與分工，不逐行拆解。

      整體設計：先算完，再播放

      跟 01、02 同一套架構。差別在這一頁有兩個獨立的資料層函式，因為兩道題目結算的東西不同。

      數字字串 "2,1,5,6,2,3"
      parseData() 切開、驗證、擋掉壞輸入
      buildHist()柱狀圖：算面積
      buildTemp()每日溫度：算天數
      同一個 render() 把 steps[目前步數] 畫出來
      為什麼分兩個 兩題的迴圈骨架一模一樣，只有「彈出條件」和「彈出時做什麼」不同。硬要合併成一個函式，會塞滿 if mode ===，反而看不出兩題的共通結構。分開寫，然後把兩份程式碼並排看，才學得到東西。

      一個 step 長什麼樣

      {
  i:        // 目前掃到第幾根 → 柱狀圖的深色柱
  stack:    // 堆疊快照，存的是索引 → 右邊塔 + 柱子染橘色
  rect:     // 這一步正在結算的矩形 {l, r, h, area} → 綠色虛線框
  best:     // 目前最大面積
  bestRect: // 目前最大的那個矩形 → 橘色實線框
  ops:      // 累計 push + pop 次數 → 用來驗證 ≤ 2n
  ans:      // 每日溫度模式的答案陣列快照（null = 還沒填）
  msg, cls: // 說明面板的文字與顏色
}

      兩個模式共用同一個 step 結構，各自只填自己用得到的欄位 —— 所以 render() 只有一份。

      畫面怎麼決定每根柱子的顏色

      顏色條件意思
      綠色rect 範圍內這一步正在結算的矩形涵蓋到它
      橘色在 stack 裡還在等右邊界，還沒定案
      深色i === 目前索引剛掃到的那一根
      淡化i < 目前索引已經結算完，不會再變

      判斷有先後順序（綠 → 橘 → 深 → 淡），因為一根柱子可能同時符合多個條件。順序寫錯，畫面就會顯示錯誤的狀態。

      兩個矩形框怎麼疊

      柱狀圖模式會同時畫兩個絕對定位的框：

      • 橘色實線＝目前為止的最大矩形（先畫，在下層）
      • 綠色虛線＝這一步正在結算的矩形（後畫，在上層）

      兩者座標都由 索引 × (柱寬 + 間距) 算出來 —— 因為柱子是固定寬度的 flex 項目，位置可以直接用算的，不必去量 DOM。固定寬度換來座標可預測，這是刻意的取捨。

      自己動手：給 AI 的 Prompt

      用 C++ 先寫暴力解，再用單調堆疊優化「柱狀圖中最大的矩形」。

步驟：
1. 寫 O(n²) 暴力解 brute(h)：對每根柱子往左右擴張
2. 寫 O(n) 單調堆疊解 fast(h)：用哨兵 0 收尾
