怎麼玩・你會學到什麼

先看這一段，再往下玩。

怎麼玩

在輸入框打任何東西——數字、名字、早餐品項都可以——然後按按鈕。畫面中間那一排就是佇列裡的資料：右邊是入口（放資料），左邊是出口（取資料）。

  1. 放資料：打字後按「放資料」或鍵盤 Enter。懶得打字，就按下面的「快速放入」。
  2. 取資料：把第一筆拿出來。拿走就不在佇列裡了。
  3. 看第一筆：只看現在排第一的是誰，不拿走。
  4. 檢視所有資料：從第一筆到最後一筆全部列出來。

每按一次，「輸出」視窗會像真的程式一樣印出結果，下方的 C++ 程式會亮起對應的那幾行。

試試看 ① 放 A、B、C，按「取資料」——拿到的是誰？② 連按三次「看第一筆」，資料有變少嗎？③ 全部取光之後再按一次「取資料」。④ 放 1、2、3，取一筆，再放 4——按「檢視所有資料」前先猜順序。

你會學到什麼

  • 取出順序＝放入順序 —— 佇列是先進先出（FIFO）。不管你放什麼、怎麼穿插著取，先放的一定先出來。
  • 「看」和「取」是兩回事 —— 看第一筆不會改變佇列；取資料會讓它少一筆、第一筆換人。
  • 取資料其實是兩個動作 —— C++ 裡要先 front()（看是誰）再 pop()（拿掉），因為 pop() 自己不會告訴你拿掉的是誰。
  • 空的時候不能取、不能看 —— 程式一定要先檢查 empty()。
  • 「檢視所有資料」是最貴的動作 —— 佇列只肯讓你看第一筆。想看全部，得複製一份、一筆一筆取出來印，資料有幾筆就要做幾次。
和 18 關的差別 18 關的資料是自動編號的號碼牌，這一頁的資料完全由你決定，而且多了「檢視所有資料」。放一些沒有大小順序的東西（蛋餅、奶茶、漢堡），更能看出順序只跟「誰先放」有關。

        同樣四個功能，做成用鍵盤選單操作的主控台程式。整段貼到編譯器就能跑：

        #include <iostream>
#include <queue>
#include <string>
using namespace std;

int main() {
    queue<string> q;                       // 一個空的佇列，裡面放文字
    int choice;

    while (true) {                         // 一直重複，直到選 0
        cout << "\n1 放資料  2 取資料  3 看第一筆  4 檢視所有資料  0 結束\n請選擇: ";
        if (!(cin >> choice) || choice == 0) break;

        if (choice == 1) {                 // 放資料
            string x;
            cout << "要放什麼: ";
            cin >> x;
            q.push(x);
            cout << "已放入 " << x << "，共 " << q.size() << " 筆\n";
        } else if (choice == 2) {          // 取資料
            if (q.empty()) { cout << "沒有資料可以取\n"; continue; }
            cout << "取出 " << q.front() << "\n";  // 先看是誰
            q.pop();                       // 再拿掉
        } else if (choice == 3) {          // 看第一筆
            if (q.empty()) { cout << "沒有資料\n"; continue; }
            cout << "第一筆是 " << q.front() << "\n";
        } else if (choice == 4) {          // 檢視所有資料
            queue<string> copy = q;        // 複製一份，拿複製品開刀
            cout << "共 " << copy.size() << " 筆:";
            while (!copy.empty()) {
                cout << " " << copy.front();
                copy.pop();
            }
            cout << "\n";
        }
    }
    return 0;
}

        03

        這個功能是怎麼做到的

        四顆按鈕各自對應佇列的哪些動作，以及為什麼「檢視所有資料」最特別。

        問題定義

        做一個可以「放資料、取資料、看第一筆、檢視所有資料」的容器，而且取出來的順序要跟放進去的順序一樣。這正是佇列（queue）的規則：先進先出（FIFO）。四顆按鈕對應到 C++ 是這樣：

        按鈕C++ 寫法佇列會變嗎空的時候
        放資料q.push(x)多一筆（排最後）沒問題，x 就是第一筆
        取資料q.front() 再 q.pop()少一筆（第一筆走）不能做，要先檢查
        看第一筆q.front()不變不能做，要先檢查
        檢視所有資料複製一份，逐筆 front + pop不變（動的是複製品）沒問題，印出 0 筆

        先破除一個直覺：「檢視所有資料」不是用迴圈從頭看到尾

        如果資料放在陣列裡，看全部很簡單：第 0 格、第 1 格、第 2 格……一路看過去。很多人以為佇列也可以這樣。不行：

        • std::queue 沒有「第幾格」 —— 寫 q[1] 會編譯錯誤。它只提供 front()（第一筆）和 back()（最後一筆）兩個窗口，中間的資料看不到。
        • 想看第二筆，只能先把第一筆拿掉 —— 第一筆 pop 掉之後，原本的第二筆才會變成新的 front。可是這樣一路看下去，佇列就被你拿光了。
        解法 先複製一份（queue<string> copy = q;），然後對複製品一筆一筆「看第一筆、拿掉」，直到複製品空了。原本的 q 完全沒被動到。畫面上資料一個一個跳起來的動畫，演的就是這個過程。

        關鍵觀察：順序只跟「誰先放」有關

        放進去的東西是什麼、大還是小、長還是短，佇列一概不管。它只記得先後。

        依序放入連取三次，依序拿到注意
        3、1、23、1、2不會幫你排大小
        奶茶、蛋餅、漢堡奶茶、蛋餅、漢堡不會照筆畫或字母排
        A、A、BA、A、B重複的資料各算一筆
        所以 右邊「取出順序」那一格，永遠跟你放資料的順序一模一樣。這就是佇列能拿來做「排隊」「等候」「依序處理」的原因。

        四個功能的做法

        1. 放資料 —— q.push(x)，x 排到最後面。就這一行。
        2. 取資料 —— 先問 q.empty()；不是空的，就 q.front() 把第一筆抄下來（印出來），再 q.pop() 把它拿掉。
        3. 看第一筆 —— 先問 q.empty()；不是空的，就 q.front()。到此為止，不 pop。
        4. 檢視所有資料 —— 複製一份 copy；只要 copy 不是空的，就印出 copy.front() 再 copy.pop()，重複到空。
        最常漏 「取資料」和「看第一筆」的差別只有一行 q.pop()。少寫這行，資料永遠取不走；多寫這行，你以為只是看一眼，資料卻不見了。

        手算一次

        依序做：放 A、放 B、看第一筆、放 C、取資料、檢視所有資料、取資料、取資料、取資料。先蓋住右邊兩欄自己算。

        步動作程式印出佇列（第一筆 → 最後一筆）
        1放 A—A
        2放 B—A B
        3看第一筆AA B
        4放 C—A B C
        5取資料AB C
        6檢視所有資料B CB C
        7取資料BC
        8取資料C（空）
        9取資料沒有資料可以取（空）

        算完可以回到上面的操作台照做一遍，對照「輸出」視窗。

        複雜度

        • 放資料、取資料、看第一筆：O(1) —— 都只碰佇列的頭或尾，資料有 3 筆還是 300 萬筆，做一次花的力氣一樣。
        • 檢視所有資料：O(n) —— 有 n 筆就要複製 n 筆、印 n 次。資料變兩倍，時間就變兩倍。這是四個功能裡唯一會「越多越慢」的。
        • 空間 O(n) —— 佇列裡有幾筆就占幾份記憶體；檢視時還會暫時多一份複製品。

        常見誤解

        • 「看第一筆會把它拿走」 —— 不會。連按幾次「看第一筆」，筆數都不變。
        • 「取資料可以指定要取哪一筆」 —— 不行，永遠只能取第一筆。想拿中間那筆，只能把它前面的全部先取走。需要「指定拿哪個」的話，你要的不是佇列。
        • 「檢視所有資料很便宜，可以常常做」 —— 每做一次就複製整個佇列。真實程式裡通常只在除錯時才印全部內容。
        • 「佇列空了再取，會拿到空字串或 0」 —— C++ 不保證任何事（未定義行為），可能拿到垃圾、可能當掉。所以程式裡每次取、每次看之前都先檢查 empty()。
