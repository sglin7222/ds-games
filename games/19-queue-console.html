01

怎麼玩・你會學到什麼

先看這一段，再往下玩。

怎麼玩

你是櫃台人員。每位客人有三項資料：排隊編號（系統自動發的號碼牌）、姓名、電話。畫面中間那一排是正在候位的客人：右邊是入口（登記），左邊是櫃台（叫號入座）。

  1. 登記候位：輸入姓名和電話，按「登記候位」。系統發一張號碼牌，客人排到最後面。懶得打字就按「＋ 範例客人」。
  2. 叫下一位：請排最前面的客人入座。他會離開候位隊伍，出現在看板的「目前叫號」。
  3. 看下一位：只看下一個輪到誰，不叫號。
  4. 候位名單：列出所有候位客人的編號、姓名、電話。
  5. 查順位：輸入排隊編號，回答「前面還有幾組」。

每按一次，「輸出」視窗會像真的程式一樣印出結果，下方的 C++ 程式會亮起對應的那幾行。

試試看 ① 登記三位客人，叫號一次——入座的是誰？② 連按三次「看下一位」，候位組數有變嗎？③ 登記 1～4 號，叫號兩次，再查 4 號的順位——是 3 還是 1？④ 全部叫完之後再按一次「叫下一位」。

你會學到什麼

  • 佇列裡可以排「一整筆資料」 —— 用 struct 把編號、姓名、電話綁成一張候位單，佇列裡排的是整張單子，不是單一個數字。
  • 入座順序＝登記順序 —— 先進先出（FIFO）。這就是「公平」在程式裡的寫法。
  • 編號不是順位 —— 編號是發出去就不變的身分；順位是「現在前面還有幾組」，每叫一次號就會變。
  • 「看」和「叫」是兩回事 —— 看下一位用 front()，佇列不變；叫號是 front() 再 pop()，少一組。
  • 空的時候不能叫、不能看 —— 程式一定要先檢查 empty()。
  • 名單和查詢比較貴 —— 佇列只肯讓你看第一筆。想看全部或找某個人，得複製一份、一筆一筆拿出來看：O(n)。
和 18 關的差別 18 關的佇列裡只有號碼，而且只練五個基本動作。這一頁把同樣五個動作組成一套真的能用的系統：每筆資料有三個欄位，還多了「名單」和「查順位」這兩個需要把整個佇列走一遍的功能。

          可以直接執行的完整程式（主控台版）

          上面的面板是系統的五個核心函式。加上選單就是一支完整的程式——整段貼到編譯器就能跑：

          #include <iostream>
#include <queue>
#include <string>
using namespace std;

struct Customer {                 // 一張候位單
    int no;                       // 排隊編號
    string name;                  // 姓名
    string phone;                 // 電話
};

queue<Customer> waiting;          // 候位隊伍
int nextNo = 1;                   // 下一張號碼牌

void join() {                     // 1 登記候位
    Customer c;
    c.no = nextNo++;
    cout << "姓名: ";  cin >> c.name;
    cout << "電話: ";  cin >> c.phone;
    cout << "您是 " << c.no << " 號，前面還有 " << waiting.size() << " 組\n";
    waiting.push(c);
}

void callNext() {                 // 2 叫下一位
    if (waiting.empty()) { cout << "目前沒有人候位\n"; return; }
    Customer c = waiting.front();
    cout << "請 " << c.no << " 號 " << c.name << " 入座（電話 " << c.phone << "）\n";
    waiting.pop();
}

void peekNext() {                 // 3 看下一位
    if (waiting.empty()) { cout << "目前沒有人候位\n"; return; }
    cout << "下一位: " << waiting.front().no << " 號 " << waiting.front().name << "\n";
}

void showAll() {                  // 4 候位名單
    queue<Customer> copy = waiting;          // 複製一份，拿複製品開刀
    cout << "候位 " << copy.size() << " 組\n";
    while (!copy.empty()) {
        Customer c = copy.front();
        cout << "  " << c.no << " 號  " << c.name << "  " << c.phone << "\n";
        copy.pop();
    }
}

void ask() {                      // 5 查順位
    int no;
    cout << "排隊編號: ";  cin >> no;
    queue<Customer> copy = waiting;
    int count = 0;                // 前面已經數過幾組
    while (!copy.empty()) {
        if (copy.front().no == no) {
            cout << no << " 號前面還有 " << count << " 組\n";
            return;
        }
        count++;
        copy.pop();
    }
    cout << "候位名單裡沒有 " << no << " 號\n";
}

int main() {
    int choice;
    while (true) {
        cout << "\n== 海大餐廳排隊系統 ==\n"
             << "1 登記候位  2 叫下一位  3 看下一位  4 候位名單  5 查順位  0 打烊\n"
             << "請選擇: ";
        if (!(cin >> choice) || choice == 0) break;
        if (choice == 1) join();
        else if (choice == 2) callNext();
        else if (choice == 3) peekNext();
        else if (choice == 4) showAll();
        else if (choice == 5) ask();
        else cout << "沒有這個選項\n";
    }
    cout << "打烊，謝謝光臨\n";
    return 0;
}

          03

          這個系統是怎麼做到的

          從「餐廳要什麼」推到「為什麼是佇列」，以及每筆資料有三個欄位時怎麼放。

          問題定義

          餐廳客滿時要讓客人候位，而且先登記的要先入座。每位客人要記三件事：排隊編號（叫號用）、姓名（確認身分用）、電話（叫到人不在時聯絡用）。系統要提供五個功能：

          功能對應的佇列動作佇列會變嗎沒人候位時
          登記候位waiting.push(c)多一組（排最後）沒問題，他就是下一位
          叫下一位front() 再 pop()少一組（第一位入座）不能做，要先檢查
          看下一位front()不變不能做，要先檢查
          候位名單複製一份，逐筆 front + pop不變（動的是複製品）沒問題，印出 0 組
          查順位複製一份，邊數邊找不變（動的是複製品）沒問題，回答查無此號

          先破除一個直覺：「編號幾號，前面就有幾組」不對

          拿到 12 號，很多人直覺是「前面還有 11 組」。只有在開店後完全沒叫過號的時候才對。

          • 編號是身分，發出去就不變 —— 12 號永遠是 12 號，不管前面走了多少人。號碼牌也不會回收重發，否則同時會有兩個 12 號。
          • 順位是位置，每叫一次號就變 —— 1～10 號都入座之後，12 號前面只剩 11 號一組。順位要看他現在排在佇列的第幾個，跟編號的數字大小無關。
          關鍵 所以「查順位」沒辦法用編號算出來，只能從佇列的第一位開始往後數，數到這個編號為止——這就是程式裡 ahead() 在做的事，也是它比較慢（O(n)）的原因。

          關鍵觀察：把三個欄位綁成一張候位單

          佇列一格只能放「一個東西」，可是每位客人有三項資料。開三個佇列分別放編號、姓名、電話？可以，但三個要永遠同步，只要有一個少 pop 一次，姓名和電話就對不上了。

          正確的做法是用 struct（結構）自己定義一種新的資料型別，把三個欄位綁在一起：

          struct Customer {       // 定義「候位單」長什麼樣
    int no;            // 排隊編號：整數
    string name;       // 姓名：文字
    string phone;      // 電話：文字（不是整數，見下方常見誤解）
};

queue<Customer> waiting;   // 佇列裡排的是一張一張候位單
          所以 push 進去的是整張單子，front() 拿出來的也是整張單子，要看其中一欄就加一個點：waiting.front().name 是「下一位的姓名」。佇列的五個動作完全沒變，變的只是裡面排的東西。

          五個功能的做法

          1. 登記候位 —— 填一張候位單（編號用 nextNo，填完 nextNo 加 1），waiting.push(c) 排到最後。
          2. 叫下一位 —— 先問 empty()；有人就 front() 把第一張單子抄下來、印出編號姓名電話，再 pop()。
          3. 看下一位 —— 先問 empty()；有人就 front()。到此為止，不 pop。
          4. 候位名單 —— 複製一份 copy；只要 copy 不是空的，就印出 copy.front() 再 copy.pop()。
          5. 查順位 —— 複製一份 copy，準備計數器 count = 0；每看一張單子，是要找的編號就回報 count，不是就 count 加 1、pop 掉看下一張。看完都沒有，回報 −1（查無此號）。
          最常漏 登記時忘了 nextNo++，每個人都拿到 1 號；叫號時忘了 pop()，同一位客人被叫一百次，後面的人永遠等不到。

          邊界情況

          • 沒人候位時叫號／看下一位 —— 對空佇列做 front() 或 pop() 是未定義行為（可能印出亂碼、可能當掉）。函式第一行就先檢查 empty()。
          • 查一個不在名單裡的編號 —— 可能是已經入座，也可能是根本沒發過這個號碼。ahead() 把整份複製品看完都沒找到，就回傳 −1。網頁版會再幫你分辨是哪一種。
          • 輸入不合理的資料 —— 姓名空白、電話打成英文字。這不是佇列的問題，但真的系統一定要擋：網頁版在登記前會檢查姓名不能空白、電話要是 0 開頭的 9～10 位數字。

          手算一次

          依序做：小明、怡君、志豪登記；叫號；雅婷登記；查 4 號順位；叫號；候位名單。先蓋住右邊兩欄自己算。

          複雜度

          • 登記、叫號、看下一位：O(1) —— 都只碰佇列的頭或尾。候位 3 組還是 300 組，做一次花的力氣一樣。尖峰時段櫃台最常做的就是這三件事，所以佇列很適合。
          • 候位名單、查順位：O(n) —— 要把複製品從頭看到尾（查順位運氣好可以提早停）。候位組數變兩倍，時間就變兩倍。
          • 空間 O(n) —— 候位幾組就占幾張候位單的記憶體；印名單、查順位時還會暫時多一份複製品。

          常見誤解

          • 「電話是數字，所以用 int 存」 —— 不行。0912345678 存成整數，開頭的 0 會不見；而且電話不會拿來加減乘除，還可能有「-」或分機。不拿來計算的號碼，一律用文字（string）存——學號、身分證字號也一樣。
          • 「有人入座後，後面的人編號要往前補」 —— 不用，也不可以。客人手上的號碼牌不會變；會變的是順位。
          • 「看下一位會把他叫走」 —— 不會。front() 只是看，候位組數不變。
          • 「客人不想等了，從名單中間把他刪掉就好」 —— std::queue 做不到，它只能從最前面拿。要支援「取消候位」得換別的結構（見第 04 段的挑戰題）。
          • 「候位名單可以常常印」 —— 每印一次就複製整個佇列。真的系統會另外想辦法（例如改用可以直接走訪的 std::deque）。

          程式架構與說明

          只講流程與分工，不逐行拆解。看懂這一段，你就能自己改這個系統。

          整體設計：邊做邊畫

          這一頁沒有劇本可以事先算好——下一位客人是誰、什麼時候叫號，完全由你決定。所以採用最直接的架構：按鈕直接改動佇列，改完把整個畫面重畫一次。

          櫃台操作 登記 / 叫號 / 看下一位 / 名單 / 查順位
          join() / callNext() / peekNext() / showAll() / ask() 改動佇列，並記下「剛剛發生了什麼」
          waiting[]、nextNo 與 last 候位隊伍 + 下一張號碼牌 + 最近一次操作的說明
          render() 照目前狀態把每一塊畫面重畫
          • 程式短 —— 五個功能就是五個小函式，跟第 02 段的 C++ 幾乎一個對一個。
          • 畫面永遠跟資料一致 —— 看板、走道、側欄讀的是同一份 waiting，每次都整個重畫，不會有哪一塊忘了更新。
          代價 不能倒退：叫錯號沒有「上一步」。另外資料只存在這個分頁的記憶體裡，重新整理就全部清空——真正營業用的系統要把資料存進資料庫，這一頁是教學用的示範。

          自己動手：給 AI 的 Prompt

          看懂之後，把下面這段丟給 Claude，讓它陪你把程式從頭寫一次：

          用 C++ 寫一個主控台版的「海大餐廳排隊系統」。

資料：
每位候位客人是一個 struct Customer，有三個欄位：
排隊編號（int，系統從 1 開始自動發、不重複）、姓名（string）、電話（string）。
所有候位客人放在一個 std::queue<Customer> 裡。

功能（文字選單，重複執行直到選 0）：
1 登記候位：輸入姓名、電話，發號碼牌，印出「您是 N 號，前面還有 K 組」
2 叫下一位：印出並移除最前面的客人（編號、姓名、電話）
