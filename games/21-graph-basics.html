圖的基本概念

校園裡有校門、圖書館、餐廳、系館、宿舍、體育館，中間有 9 條路相連。這種「一堆地點＋誰跟誰相連」的資料，就叫做「圖」。這一關先把圖的名詞弄懂，再學電腦怎麼把一張圖記下來：一張大表格（鄰接矩陣），或每個地點一條鄰居清單（鄰接串列）。遊戲裡同一張圖會同時用三種樣子顯示，加一條邊，三邊一起變。

先搞懂：「圖」到底是什麼

沒學過程式也看得懂。這是圖單元的第一關，後面的走訪、拓撲排序、最小生成樹、最短路徑都用這裡的詞。

定義：圖（Graph）

DEFINITION · 圖 Graph
一張圖 G 由兩樣東西組成：一群頂點（點），和一群邊（每條邊連接兩個頂點）。寫成 G = (V, E)：V 是所有頂點的集合，E 是所有邊的集合。

「集合」就是「一堆東西放在一起，不重複」。海大校園地圖寫成圖就是：V = {A, B, C, D, E, F}（6 個地點），E = {A–B, A–C, B–C, B–D, C–D, C–E, D–E, D–F, E–F}（9 條路）。

同一個定義，換個說法內容
白話圖就是一份「誰跟誰有連在一起」的紀錄。點是東西，線是關係。
數學寫法G = (V, E)。一條連接 u 和 v 的邊寫成 (u, v) 或 u–v。本單元也用 V 代表頂點個數、E 代表邊的條數：校園圖 V = 6、E = 9。
它不在乎什麼點畫在哪裡、線畫得多長、彎的還直的，全都不重要。只要「誰跟誰相連」一樣，就是同一張圖。這跟地圖的比例尺無關。
目的 把「關係」交給電腦處理。地圖上的路、社群網站上的好友、課程的先修關係、網頁之間的超連結，全都是「一堆東西＋它們之間的連線」。只要寫成圖，同一套方法就能回答「走得到嗎？」「最近的路是哪條？」「先修課要先上哪門？」這些問題。
注意 這裡的「圖」不是長條圖、圓餅圖、折線圖那種統計圖表，也不是照片。英文分得很清楚：統計圖叫 chart 或 plot，這裡的圖叫 graph。它是一種資料結構，記的是「誰連到誰」。
先備 只要知道陣列：一排有編號的格子，編號從 0 開始（第 13 關把樹存進陣列時用過）。第 10 關的「串列」和第 11～13 關的「樹」看過更好——你會發現樹其實是一種特別的圖。

先認識這些詞（照順序讀，後面的詞會用到前面的）

頂點 vertex（也叫節點 node）
圖上的每一個點，代表一個東西。這一關用字母 A～F 命名。「頂點」和「節點」是同一個東西的兩種叫法。
捷運路線圖上的每一個車站。
邊 edge
連接兩個頂點的一條線，代表這兩個東西之間有關係（有路、是朋友……）。本單元的圖沒有「自己連自己」的邊，兩點之間最多一條邊。
兩個車站之間的那一段軌道。
V 和 E vertex set / edge set
V 是所有頂點、E 是所有邊。算複雜度時，V 也代表頂點個數、E 代表邊的條數。校園圖：V = 6、E = 9。
車站總數、軌道總段數。
相鄰／鄰居 adjacent / neighbor
兩個頂點之間有一條邊直接相連，就說它們相鄰，彼此是鄰居。校園圖裡 A 的鄰居是 B、C；A 和 D 不相鄰（要繞路才到）。
捷運上「下一站就到」的兩個車站。
無向圖／有向圖 undirected / directed
邊沒有方向、兩頭都能走，叫無向圖，寫 A–B。邊有箭頭、只能照箭頭走，叫有向圖，寫 A→B；A→B 有，不代表 B→A 也有。
無向＝雙向道；有向＝單行道。臉書好友是無向，IG 追蹤是有向。
權重／加權圖 weight / weighted graph
寫在邊上的數字，代表走這條邊的成本（這一關是走路幾分鐘）。邊有權重的圖叫加權圖；沒有權重時，每條邊都一樣。
每段路要走幾分鐘、要付多少過路費。
度數 degree
一個頂點連著幾條邊（＝有幾個鄰居），寫 deg(u)。有向圖分兩種：出度（out-degree，從它出發的箭頭數）和入度（in-degree，指向它的箭頭數）。
一個路口有幾條路接出去。
路徑 path
一串頂點，每相鄰的兩個之間都要有邊，例如 A→B→D→F。路徑的長度＝走了幾條邊（加權圖常改成權重加總）。
搭捷運從一站一站坐到目的地的路線。
簡單路徑 simple path
一個頂點都不重複的路徑。A→C→B→C→E 是路徑，但 C 出現兩次，所以不是簡單路徑。
不繞回去走過的車站。
環 cycle
從一個頂點出發，不重複頂點、也不重複邊，最後走回出發點，而且至少經過 3 個頂點。B→C→E→D→B 是環；A→B→A 只是同一條邊來回，不算環。
公車的環狀線：繞一圈回到起點站。
連通／連通元件 connected / connected component
無向圖裡任兩個頂點之間都有路徑，叫連通。不連通的圖會斷成好幾塊，每一塊（塊內互相走得到、跟塊外完全走不到）叫一個連通元件。
一座島上的路都連在一起；兩座沒有橋的島，就是兩個連通元件。
樹 tree
連通而且沒有環的無向圖。V 個頂點的樹一定剛好 V−1 條邊。第 11～13 關的樹，就是再多挑一個頂點當「根」的這種圖。
家族族譜：每個人都連得到，但不會繞圈。
鄰接矩陣 adjacency matrix
一張 V × V 的表格（程式裡叫二維陣列）M。u 和 v 相鄰，第 u 列第 v 欄 M[u][v] 就填 1（加權圖填權重），不相鄰填 0。
班上同學的「誰認識誰」對照表，橫的直的都是全班名單。
鄰接串列 adjacency list
每個頂點一條清單，只寫它的鄰居。adj[A] = B, C 表示 A 的鄰居是 B、C。清單長度就是度數。
每個人的手機通訊錄：只存自己認識的人。
稀疏圖／稠密圖 sparse / dense
邊比「所有可能的邊」少很多叫稀疏；幾乎每兩點都有邊叫稠密。V 個頂點的無向圖最多 V×(V−1)÷2 條邊（6 個頂點最多 15 條）。真實世界的圖大多很稀疏。
全國道路網很稀疏（每個路口只接幾條路）；小班同學互相都認識就很稠密。
O(V²)／O(V+E) 時間／空間複雜度
描述「圖變大時，要花的時間或格子數怎麼跟著變多」。O(V²)：跟頂點數的平方成正比（V 變 10 倍，變 100 倍）。O(V+E)：跟「頂點數＋邊數」成正比。
V² 像全班兩兩配對的表格；V+E 像只記每個人和他真正的朋友。

同一張校園圖的三種版本：無向、有向、加權

遊戲第 1～3 關就是這三張。地點一模一樣，差在「邊」帶了什麼資訊：

度數，以及一個一定成立的事實：度數總和 ＝ 2 × 邊數

頂點ABCDEF合計
鄰居B CA C DA B D EB C E FC D FD E—
度數23443218 ＝ 2 × 9
握手定理 無向圖裡，所有頂點的度數加起來 ＝ 2 × 邊數。原因很簡單：每條邊有兩個端點，算度數時它在兩端各被數一次。就像一群人握手，每握一次手會用掉兩隻手。校園圖：2 + 3 + 4 + 4 + 3 + 2 = 18 ＝ 2 × 9。有向圖則是：出度總和 ＝ 入度總和 ＝ 邊數（每個箭頭剛好一個起點、一個終點）。

路徑、簡單路徑、環：自己先判斷

先看第一排：每一張的綠色路線是不是簡單路徑（每一步都有邊、頂點不重複）？

再看第二排：綠色（或紅色）的路線是不是環？

連通、連通元件，以及「樹是一種特別的圖」

第一排：這張圖連通嗎（任兩點之間都走得到）？

第二排：這是不是一棵樹（連通、而且沒有環）？

樹 ⊂ 圖 樹是圖的一種：樹 ＝ 連通 ＋ 沒有環。所以圖比樹自由得多——可以有環、可以斷成好幾塊、可以有方向、一個頂點可以有任意多個鄰居。也因為這樣，存圖不能像第 13 關存 heap 那樣用 2i+1、2i+2 公式算位置，要另外想辦法。這就是下一段的主題。

電腦怎麼記住一張圖：兩種做法

電腦看不到圖片。我們要把「誰跟誰相連」寫成格子和數字。先把頂點編號：A＝0、B＝1、C＝2、D＝3、E＝4、F＝5，這樣才能當陣列的格子號碼。常用的方法有兩種：

問題鄰接矩陣（表格）鄰接串列（清單）
要多少格子永遠 V × V ＝ 36 格，不管有幾條邊V 條清單，裡面共 2E ＝ 18 格（每條無向邊在兩端各記一次）
D 和 B 相鄰嗎？直接看 M[D][B] 那一格，一步就知道要把 adj[D] 從頭看一遍，最多看 deg(D) 格
列出 C 的所有鄰居把第 C 列 6 格全部看完（V 格）adj[C] 本身就是答案，只看 deg(C) ＝ 4 格
無向圖的特徵M[u][v] ＝ M[v][u]，表格對稱（沿對角線對摺會重合）v 在 adj[u] 裡，u 就一定在 adj[v] 裡
一句話 矩陣是「每一對都留一格」，查得快但佔空間；串列是「只記真的有的」，省空間但要一格一格找。無向圖的一條邊，兩種做法都要記兩次（u 那邊一次、v 那邊一次）。

容易搞混的幾件事

常被搞混的東西對嗎？為什麼
「圖就是統計圖表」不對這裡的圖（graph）是「頂點＋邊」的資料結構，跟長條圖（chart）是兩回事。
「點畫得近就代表相鄰」不對相不相鄰只看有沒有邊。校園圖裡 A 和 D 看起來不遠，但沒有邊，不相鄰。
「無向圖一條邊只要記一次」不對矩陣要改 M[u][v] 和 M[v][u] 兩格，串列要在 adj[u] 和 adj[v] 各加一筆。所以矩陣裡的 1 有 2E 個。
「A→B 有邊，B→A 一定也有」有向圖不一定有向圖的矩陣通常不對稱。單行道版本裡 C→B 有，B→C 沒有。
「樹和圖是兩種不相干的東西」不對樹就是「連通、沒有環」的圖。圖的方法（走訪、最短路徑）都能用在樹上。
「鄰接串列一定比較好」看情況邊很少（稀疏）時串列省很多空間；邊很多（稠密）、又常問「兩點相不相鄰」時，矩陣更好用。

自我檢查（先自己想，再點開看答案）

一張無向圖有 7 條邊，所有頂點的度數加起來是多少？
14。握手定理：度數總和 ＝ 2 × 邊數 ＝ 2 × 7。跟有幾個頂點、邊怎麼連都沒關係。
校園圖的鄰接矩陣，第 C 列有幾個 1？它跟什麼一樣？
4 個（在 A、B、D、E 那幾欄），剛好等於 deg(C) ＝ 4，也等於 adj[C] 的長度。矩陣某一列的 1 的個數就是那個頂點的度數。
有沒有可能畫出一張無向圖，裡面剛好有 3 個頂點的度數是奇數？
不可能。度數總和一定是 2 × 邊數，是偶數。奇數加起來要是偶數，奇數的個數就必須是偶數個。校園圖裡度數是奇數的是 B（3）、E（3），剛好 2 個。
有向單行道版本裡，A 的入度是多少？這代表什麼？
0。沒有任何箭頭指向 A：從校門出發可以走到任何地方，但從其他地方沒辦法直接回到校門（也繞不回來）。有向圖裡「走得到」是有方向的。
7 個頂點的樹有幾條邊？如果多加一條邊會怎樣？
6 條（V − 1）。樹已經連通，再多加一條邊，一定會在原本走得到的兩點之間多出第二條路，形成環，就不是樹了。

你會學到什麼

  • 圖的基本名詞 —— 頂點、邊、鄰居、度數、路徑、環、連通，後面四關都會用到。
  • 鄰接矩陣 —— V×V 表格，查「相不相鄰」O(1)，但空間永遠 O(V²)。
  • 鄰接串列 —— 每個頂點一條鄰居清單，空間 O(V+E)，列出鄰居只要 O(度數)。
  • 無向邊要記兩次 —— 矩陣對稱，1 的個數 ＝ 2E；度數總和 ＝ 2E。
  • 有向圖 —— 矩陣不再對稱，出度看列、入度看欄。
  • 怎麼選表示法 —— 稀疏用串列，稠密或常查相鄰用矩陣。
建議順序 第 1 關看無權重怎麼建 → 第 2 關看權重存在哪 → 第 3 關看有向圖的不對稱 → 第 4 關用矩陣檢查路徑和環 → 第 5 關比較空間 → 最後到自由模式自己畫一張圖。

    整份程式逐行白話說明（寫給完全沒學過程式的你）

      這個遊戲跑的程式（完整版）

      把視覺化全部拿掉，同時維護兩種表示法就這麼多。最後一段是「有權重時，清單連權重一起存」的常見寫法（第 17 關的地圖就是這樣存）：

      #include <iostream>
#include <vector>
#include <algorithm>   // find
#include <utility>     // pair
using namespace std;

const int V = 6;                       // A~F 編號 0~5
int M[V][V] = {};                      // 鄰接矩陣：V×V 格，全部 0
vector<vector<int>> adj(V);            // 鄰接串列：V 條空清單

// 在清單裡找到第一個 x，把它刪掉（要一格一格找：O(度數)）
void eraseOne(vector<int>& list, int x) {
    auto it = find(list.begin(), list.end(), x);
    if (it != list.end()) list.erase(it);
}

void addEdge(int u, int v, int w, bool directed) {
    M[u][v] = w;                       // 無權重圖 w 就傳 1
    adj[u].push_back(v);
    if (!directed) {                   // 無向：反方向也記一次
        M[v][u] = w;
        adj[v].push_back(u);
    }
}

void removeEdge(int u, int v, bool directed) {
    M[u][v] = 0;  eraseOne(adj[u], v);
    if (!directed) { M[v][u] = 0;  eraseOne(adj[v], u); }
}

bool isAdj(int u, int v) { return M[u][v] != 0; }   // O(1)
int deg(int u) { return (int)adj[u].size(); }       // 有向圖時是出度
int inDeg(int v) {                                   // 入度：數第 v 欄，O(V)
    int c = 0;
    for (int u = 0; u < V; u++) if (M[u][v] != 0) c++;
    return c;
}
void printNbrs(int u) {                              // O(度數)
    for (int v : adj[u]) cout << char('A' + v) << ' ';
    cout << '\n';
}

int main() {
    enum { A, B, C, D, E, F };         // A=0, B=1, ..., F=5
    int edges[9][3] = {{A,B,4},{A,C,2},{B,C,1},{B,D,5},{C,D,8},
                       {C,E,10},{D,E,2},{D,F,6},{E,F,3}};
    for (auto& e : edges) addEdge(e[0], e[1], 1, false);   // 第 1 關：無權重

    cout << isAdj(D, B) << '\n';       // 1
    cout << isAdj(A, F) << '\n';       // 0
    cout << deg(C) << '\n';            // 4
    printNbrs(B);                      // A C D

    // 有權重的另一種存法：清單裡每一格是 {鄰居, 權重}
    vector<vector<pair<int,int>>> wadj(V);
    for (auto& e : edges) {
        wadj[e[0]].push_back({e[1], e[2]});
        wadj[e[1]].push_back({e[0], e[2]});
    }
    for (auto [v, w] : wadj[D])        // B 5  C 8  E 2  F 6
        cout << char('A' + v) << ' ' << w << "  ";
}

      03

      這個功能是怎麼做到的

      為什麼需要圖 → 電腦怎麼記 → 兩種記法各自擅長什麼。

      問題定義：為什麼需要「圖」

      很多問題的核心不是「一排數字」，而是東西之間的關係。陣列、堆疊、佇列只能表示「誰在誰前面」；樹只能表示「誰是誰的上司」。關係一旦可以亂連、可以繞圈，就需要圖：

      情境頂點邊種類想問的問題
      地圖導航路口、地點道路加權（分鐘）；單行道是有向最快怎麼走？（第 17 關）
      社群網路使用者好友／追蹤好友是無向；追蹤是有向朋友的朋友有誰？（第 22 關）
      課程先修課程「先修 → 後修」有向、不能有環課要照什麼順序修？（第 23 關）
      網頁連結網頁超連結有向哪些網頁最重要？（搜尋引擎排名）
      佈線／鋪路建築物可以拉線的位置加權（成本）用最少的錢全部連起來？（第 24 關）
      迷宮每個格子相鄰而且沒牆無向走得出去嗎？（第 07 關其實就是圖）

      這一關要解決的是最前面的那一步：把一張圖存進電腦，而且要讓「u、v 相不相鄰？」「u 的鄰居有誰？」這兩個最常見的問題答得快。

      先破除錯誤直覺

      • 「存圖就是存一張圖片」 —— 電腦要的是「誰連到誰」，不是畫面。座標、顏色、線的長短，對演算法都不重要。同一張圖換個畫法，存起來完全一樣。
      • 「存一份邊的清單就夠了」 —— 把 9 條邊列成一長串是可以（叫 edge list，第 24 關 Kruskal 會用），但要回答「C 的鄰居有誰」就得把每條邊都看一遍，O(E)。圖演算法最常問的就是鄰居，所以要換成「以頂點為主」的存法。
      • 「看起來近就是鄰居」 —— 只有邊說了算。

      關鍵觀察：兩個最常問的問題，各有一種最快的存法

      1. 「u、v 相鄰嗎？」 —— 如果每一對 (u, v) 都事先留一格，直接看那一格就好，O(1)。這就是鄰接矩陣：用二維陣列，格子號碼直接算出來，跟陣列「第 i 格直接跳過去」是同一個道理。
      2. 「u 的鄰居有誰？」 —— 如果每個頂點都隨身帶一份「我的鄰居」名單，直接把名單唸出來，O(度數)。這就是鄰接串列。名字裡的「串列」是因為早期用第 10 關的鏈結串列做；現在 C++ 通常用 vector，觀念一樣。
      3. 無向圖的對稱 —— u–v 這條邊，從 u 看是鄰居、從 v 看也是鄰居，所以兩種存法都要在兩端各記一次：矩陣改兩格、串列加兩筆。

      演算法：addEdge 同時改兩份紀錄

      1. 編號 —— 把頂點換成 0～V−1 的整數（A＝0、B＝1……），才能當格子號碼。
      2. 開空的 —— 矩陣 V×V 全部填 0；串列開 V 條空清單。
      3. 加一條邊 u–v（權重 w） —— M[u][v] = w，adj[u].push_back(v)。如果是無向圖，再做一次反方向：M[v][u] = w、adj[v].push_back(u)。沒有權重就把 w 當 1。
      4. 查相鄰 —— 看 M[u][v] != 0。
      5. 度數 —— adj[u].size()（有向圖是出度）；入度要數矩陣的第 v 欄。
      6. 列鄰居 —— 把 adj[u] 從頭走到尾。
      注意 用 0 代表「沒有邊」，前提是權重不會是 0。如果權重可能是 0 或負數（例如「免費的路」），就要改用一個特別的數（例如 −1 或很大的 INF）代表沒有邊，或另外開一張 0/1 表格。

      複雜度：兩種做法比一比

      操作鄰接矩陣鄰接串列說明
      空間O(V²)O(V+E)矩陣不管有沒有邊都留格子；串列只記真的邊（無向 2E 格＋V 條清單）。
      u、v 相鄰嗎？O(1)O(deg(u))矩陣直接看一格；串列要在 adj[u] 裡找。
      列出 u 的所有鄰居O(V)O(deg(u))矩陣要掃整列（很多 0 也得看）；串列只看鄰居。
      加一條邊O(1)O(1)改格子；push_back 加到清單尾巴。
      刪一條邊O(1)O(deg(u))串列要先找到它在清單哪裡。
      看過整張圖每條邊O(V²)O(V+E)第 22 關的 DFS／BFS 就是這件事。

      差距在圖變大時非常明顯。假設一個城市的道路網有 V ＝ 10,000 個路口、E ＝ 30,000 條路（每個路口平均接 6 條，很稀疏）：

      存法要幾格每格 4 bytes 約
      鄰接矩陣 V²100,000,000400 MB
      鄰接串列 V＋2E10,000 ＋ 60,000 ＝ 70,000280 KB

      矩陣裡 99.94% 的格子都是 0，白白佔空間。

      怎麼選表示法

      情況選誰理由
      邊很少（稀疏），V 很大鄰接串列空間 O(V+E)，矩陣會塞不下。道路網、社群網路、網頁都是這種。
      常常要「走遍鄰居」（DFS、BFS、Dijkstra、Prim）鄰接串列只看真的鄰居，整張圖 O(V+E)。
      邊很多（稠密），幾乎每兩點都有邊鄰接矩陣反正格子都會用到，不浪費；而且查相鄰最快。
      V 很小（幾百以內），又常問「u、v 有沒有邊」鄰接矩陣V² 不大，寫起來最簡單。
      實務 大部分題目和真實系統預設用鄰接串列（vector<vector<int>>）。本單元第 22～24 關和第 17 關都用串列。

      常見誤解

      • 「矩陣裡 1 的個數就是邊數」 —— 無向圖要除以 2：每條邊佔 M[u][v] 和 M[v][u] 兩格。校園圖 18 個 1，9 條邊。有向圖才是一個 1 一條邊。
      • 「度數看矩陣的對角線」 —— 對角線是「自己連自己」，本單元永遠是 0。度數是整列的非 0 格數，也是 adj[u] 的長度。
      • 「有向圖的度數也只有一種」 —— 要分出度（看第 u 列、adj[u] 長度）和入度（看第 u 欄）。用串列算入度比較麻煩，要把每條清單都看一遍。
      • 「鄰接串列裡的順序有意義」 —— 對圖本身沒有，A 的鄰居是 {B, C} 還是 {C, B} 都一樣。但它會影響第 22 關走訪的先後順序，所以本單元一律照字母順序加邊。
      • 「加權圖不能用串列」 —— 可以，清單裡每一格改存 {鄰居, 權重} 兩個數就好（上面完整版最後一段）。
      下一關 圖存好了，接下來要「走」它：從一個頂點出發，怎麼把走得到的頂點全部拜訪一遍？深度優先（DFS）和廣度優先（BFS）有什麼差別？怎麼算出圖有幾個連通元件？→ 第 22 關「圖的走訪：DFS 與 BFS」

      用 C++ 寫一個圖的類別 Graph，同時用「鄰接矩陣」和「鄰接串列」存同一張圖。

需要的成員：
- Graph(int V, bool directed)

- void removeEdge(int u, int v)
