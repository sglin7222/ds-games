最短路徑派遣

07 關的迷宮裡每一步成本都一樣，普通佇列「先到先服務」就能保證最短。現在每條路有不同的權重——先到的不一定最快。把佇列升級成優先佇列，永遠先處理「目前已知最快抵達」的點，就是 Dijkstra。看它怎麼一步一步鬆弛、一個一個把節點「出爐」。

一句話定義

DEFINITION · 定義
Dijkstra（戴克斯特拉）演算法是一套固定步驟：在一張「每條路都標好長度、而且長度都不是負數」的地圖上，從一個起點出發，算出到每一個地點的最短距離。

它的做法只有一句話：每次都先處理「目前已知離起點最近」的那個點，再用它去更新鄰居的距離。名字來自荷蘭電腦科學家 Edsger Dijkstra，他在 1956 年想出這個方法。

這句話裡有好幾個沒聽過的詞——「地圖」在電腦裡叫什麼、「長度」怎麼標、「更新距離」是什麼意思。別急，下面一個一個拆。先記住 Dijkstra 想解決的事情只有一件：

目的 給你一張路網和一個出發點，回答「到每個地方最快要多久、該怎麼走」。就像消防隊的派遣中心：消防局固定在一個地方，城裡任何一個地址起火，都要馬上知道最快幾分鐘能到、走哪幾條路。導航 App 幫你找路，核心也是這件事。
先備 這是圖單元的最後一關。建議照順序先玩：21 圖的基本概念 → 22 圖的走訪 DFS／BFS → 23 拓撲排序 → 24 最小生成樹，再來這裡。優先佇列的原理在 13 堆積。

先認識這些詞（照順序讀，後面的詞會用到前面的）

演算法 algorithm
解決一個問題的固定步驟。每一步都寫得很清楚，照著做一定會結束，而且一定得到答案。Dijkstra 就是一套演算法。
食譜：照「先切菜、再熱鍋、再下鍋」的順序做，誰來做都煮得出同一道菜。
圖 graph
一堆「點」，加上連接這些點的「線」。電腦科學裡的「圖」不是照片或圖表，而是專門用來表示誰和誰相連的資料。
捷運路線圖：一個個車站，用路線連起來。
節點 / 頂點 node / vertex
圖上的每一個點（遊戲裡的每個圓圈）。在這一關，一個節點就是一個地點，用 A、B、C……命名。「節點」和「頂點」是同一個東西的兩種叫法。
捷運路線圖上的每一個車站。
邊 / 鄰居 edge / neighbor
連接兩個節點的一條線，代表這兩地之間有路可以直接走。被一條邊直接連到的節點，叫做彼此的鄰居。
兩個相鄰車站之間的那一段軌道；相鄰的兩站就是鄰居。
無向圖 / 有向圖 undirected / directed
邊沒有方向、兩頭都能走，叫無向圖；邊有箭頭、只能照箭頭方向走，叫有向圖。本關的地圖全部是無向圖：A–B 這條路，A 到 B、B 到 A 都可以走，花的時間一樣。
無向＝雙向道；有向＝單行道。
權重 weight
寫在每條邊上的數字，代表走這條邊要付出的成本（本關當作「幾分鐘」）。有權重的圖叫加權圖。Dijkstra 要求權重都不是負數（0 或正數）。
每一段路要開幾分鐘；也可以是油錢、過路費。
路徑 / 路徑長度 path / path length
路徑＝沿著邊一站接一站走的路線，例如 A → B → D。路徑長度＝路上每條邊的權重全部加起來，不是數經過幾條邊。
搭公車轉兩次車：總時間是每一段車程相加，不是「搭了幾段」。
最短路徑 shortest path
從起點到某個節點的所有路徑裡，路徑長度最小的那一條。它的長度就叫起點到那個節點的最短距離。
從家到學校有好幾種走法，最省時的那一種。
無限大 ∞ infinity
比任何數字都大的「數」。在這一關，∞ 的意思是「目前還不知道怎麼去」。一開始除了起點，每個點的距離都先寫 ∞；程式裡用一個超大的數 INF 來代替。
筆記本上先寫「未知」，等找到路再改成真正的分鐘數。
距離表 / parent 表 dist / parent
dist 表：每個節點一格，記「目前已知從起點到這裡最快幾分鐘」，起點是 0、其他先填 ∞。parent 表：記「這條最快走法裡，到這裡的上一站是誰」。從終點沿 parent 一路往回找，就能還原整條路線。
一本筆記本，每個地點一行：「到 X 最快 n 分鐘，上一站是 Y」。
鬆弛 relax
站在節點 u，看它的一條邊 u–v（權重 w）：如果「先到 u 再走這條邊」的 dist[u] + w 比 dist[v] 小，就把 dist[v] 改成這個更小的數，並記 parent[v] = u。沒有比較小就什麼都不改。
發現一條更快的走法，就把筆記擦掉重寫。名字聽起來怪，記住「鬆弛＝試著更新成更短」就好。
優先佇列 priority queue
一種候位名單：東西隨時放進去，每次拿出來的都是數值最小的那個（不是最早來的那個）。本關放進去的是 (dist, 節點) 這樣的「票」。它的內部就是第 13 關的堆積（heap），只是反過來讓「最小的」站最上面。
一般佇列是排隊買票，先到先服務；優先佇列是急診檢傷，最急的先看。
出爐（定案） settled / visited
一個節點從優先佇列被取出、而且驗過是有效的票，那一刻它的 dist 就定案，之後永遠不會再變。本頁叫「出爐」；別的課本常叫「已確定」或「已拜訪（visited）」。
麵包出爐就定型了；這個地點的最短距離蓋章確認，不再修改。
過期條目 stale entry
同一個節點可能在佇列裡有好幾張票。dist 被鬆弛變小後，新票放進去，舊票不刪。等舊票被取出時，發現票上的數字比 dist 表上的大，就知道它過期，直接丟掉（這招叫 lazy deletion，懶惰刪除）。
改過時間的舊車票：上車時剪票員一看日期不對，直接作廢。
O(V+E)、O((V+E) log V) Big-O 記號
描述「圖變大時，工作量怎麼跟著變多」。V＝節點個數，E＝邊的條數。O(V+E)：工作量大約跟「點數＋邊數」成正比。Dijkstra 是 O((V+E) log V)：再多乘一個 log V——它長得很慢，V 是 1000 時 log V 大約才 10。
O(V+E) 像把每個車站、每段軌道都走過一次；多乘的 log V 是每次排隊候位要付的一點手續費。

把問題說精確：輸入什麼、輸出什麼

  1. 輸入——一張圖（有哪些節點、哪些邊、每條邊的權重，權重都 ≥ 0），再加上一個起點。
  2. 輸出——起點到每一個節點的最短距離（完全沒有路相連的點，答案就是 ∞）。順便留下 parent 表，任何一個點的最短路線都能還原出來。
  3. 「最短」的意思——路徑上所有邊的權重加起來最小。不是經過的邊最少，也不是畫面上看起來最近。

常被搞混的東西跟最短路徑一樣嗎？差在哪
經過最少條邊的路不一樣最短路徑看的是權重加總。上面的例子：S → G 直達只有 1 條邊卻要 9；繞 3 條邊只要 6。
畫面上看起來最近不一樣圖上節點畫在哪裡只是為了好看。兩個點畫得再近，權重寫 100 就是要 100 分鐘。距離只看邊上的數字。
BFS 廣度優先搜尋（第 07 關）特例BFS 用普通佇列，只數邊數；所以只有在每條邊權重都一樣時，它找到的才是最短路徑。Dijkstra 把普通佇列換成優先佇列，權重不同也能算對。
優先佇列 vs. 堆積 heap（第 13 關）相關優先佇列是「要做什麼」（每次拿最小的），heap 是「怎麼做」。第 13 關是最大堆積；Dijkstra 用的是最小堆積，規則反過來而已。
有負權重的圖不能用Dijkstra 相信「路只會越走越長」，所以敢說「取出就定案」。有負數的邊時，繞遠路可能反而更短，這個保證就破了，答案可能是錯的。這種圖要改用 Bellman-Ford 演算法。
dist 表上「目前的數字」還不一定出爐之前，dist 只是「目前已知最快」，之後還可能被鬆弛得更小（例如 C：∞ → 5 → 3）。出爐那一刻才是最終答案。

自我檢查（先自己想，再點開看答案）

第 1 關「教學小圖」從 A 出發，6 個點 A～F。還沒開始跑之前，dist 表應該長什麼樣子？為什麼其他點不先填 0？
dist 表是 A = 0，B、C、D、E、F 全部 = ∞。起點到自己不用走，所以是 0；其他點還不知道怎麼去，所以是 ∞。如果先填 0，意思就變成「已經知道 0 分鐘能到」，鬆弛時要找「比 0 更小」的數字——永遠找不到，筆記就再也不會被更新，答案全錯。
同一張教學小圖裡，A 和 C 之間有一條權重 5 的直達道路。為什麼最後 dist[C] 是 3，不是 5？
因為還有一條路：A → B → C，長度 2 + 1 = 3，比直達的 5 短。最短距離看的是權重加總，不是邊數。演算法先把 C 標成 5（從 A 鬆弛），等 B 出爐後再鬆弛成 3。佇列裡那張 (5, C) 舊票之後被取出時，就是一張過期條目，直接跳過。
現在要鬆弛邊 u–v，權重 w = 4。已知 dist[u] = 7。如果 dist[v] = 10，要不要改？如果 dist[v] = ∞ 呢？
先算 dist[u] + w = 7 + 4 = 11。
・dist[v] = 10：11 沒有比 10 小 → 不改，dist[v] 維持 10，也不發新票。
・dist[v] = ∞：11 比 ∞ 小 → 要改，dist[v] 變成 11、parent[v] = u，並把 (11, v) 放進優先佇列。
有三條單行道：A→B 權重 2、A→C 權重 5、C→B 權重 −4。從 A 出發，Dijkstra「取出就定案」的保證哪裡出問題？
優先佇列裡 B（2）比 C（5）小，所以 B 先被取出，宣布 dist[B] = 2 定案。但真正最短的是 A → C → B：5 + (−4) = 1，比 2 還小。「取出就定案」是靠「路只會越走越長、繞路不可能更快」撐起來的；負權重讓繞路反而變快，這個保證就不成立了。所以 Dijkstra 只能用在權重都 ≥ 0 的圖。

你會學到什麼

  • 為什麼 BFS 在加權圖上會答錯 —— 邊數最少 ≠ 總時間最短。第 2 關就是專門設計來讓 BFS 出糗的反例。
  • 優先佇列是什麼 —— 一種「永遠讓最小的排最前面」的候位名單。把 07 關的普通佇列換成它，BFS 就升級成 Dijkstra。
  • 鬆弛（relax） —— 「發現更快的走法就更新筆記」這個動作的正式名字。整個演算法就是不停地鬆弛。
  • lazy deletion（過期條目） —— dist 被更新後，佇列裡的舊條目不用刪，取出時認出它過期、跳過就好。
  • 貪心為什麼是對的 —— 為什麼被取出的節點 dist 就此定案、永不再變。
  • 負權重為什麼會壞掉 —— Dijkstra 的保證建立在「路只會越走越長」上。
  • 複雜度 O((V+E) log V) —— log 是優先佇列收的手續費。

    整份程式逐行白話說明（寫給完全沒學過程式的你）

      這個遊戲跑的程式（完整版）

      把視覺化全部拿掉之後的演算法本體。跟 07 關的 BFS 對照著看：整體骨架幾乎一樣，差別只在容器從 deque 換成 priority_queue、多了一張 dist 筆記、以及一行「過期就跳過」：

      #include <vector>
#include <queue>
#include <utility>
#include <climits>
using namespace std;

const int INF = INT_MAX;

// g[u] = {{v, w}, ...}：u 的每個鄰居 v 與那條邊的權重 w
vector<int> dijkstra(int n, const vector<vector<pair<int,int>>>& g,
                     int s, vector<int>& parent) {
    vector<int> dist(n, INF);
    parent.assign(n, -1);
    dist[s] = 0;

    // pair 比大小時先比第一個數字 → 放 (dist, 節點)，
    // greater<> 讓「最小的排最前面」：永遠先處理已知最快抵達的點
    priority_queue<pair<int,int>, vector<pair<int,int>>,
                   greater<pair<int,int>>> pq;
    pq.push({0, s});

    while (!pq.empty()) {
        auto [d, u] = pq.top(); pq.pop();
        if (d > dist[u]) continue;            // 過期條目 → 跳過（lazy deletion）
        for (auto [v, w] : g[u]) {
            if (dist[u] + w < dist[v]) {      // 鬆弛：發現更快的走法
                dist[v] = dist[u] + w;
                parent[v] = u;
                pq.push({dist[v], v});        // 發新票；舊票不用刪
            }
        }
    }
    return dist;                              // 路徑本身沿 parent 回溯（見第 03 段）
}

      二十行出頭。遊戲頁面多出來的幾百行，全部都是為了「讓過程看得見」。

      03

      這個功能是怎麼做到的

      從「BFS 為什麼不夠用」走到完整的 Dijkstra，每個判斷為什麼非要不可。

      問題定義

      給一張地圖：節點是地點，邊是兩地之間的道路，每條邊有一個權重——走那段路要花的時間（或油錢、過路費，總之是成本）。從起點出發，找出到每個地點的最省時走法。導航軟體、網路封包路由、遊戲 AI 找路，核心都是這一題。

      先把幾個會一直出現的詞用白話講清楚：

      術語白話生活比喻
      權重 weight走這條邊要付出的成本這段路要開幾分鐘

      parent 表最快走法裡，每個點的上一站「要到 X，先到 Y 再走過去」的那個 Y

      出爐 settled某個點被取出且有效，dist 從此定案這家的最短路線蓋章確認，之後不會再改

      先破除一個直覺：拿 07 關的 BFS 直接來用，會答錯

      07 關證明過：BFS 保證最短。但那個保證有一行小字——「每一步成本都一樣」時才成立。BFS 數的是「經過幾條邊」，不是「總共花多少時間」。看這張圖：

      • BFS 的答案：S → A → G —— 只經過 2 條邊，BFS 覺得它「最短」，但總時間是 10。
      • 真正的最短：S → B → C → D → G —— 經過 4 條邊，總時間只要 4。邊數多，反而快。
      關鍵 普通佇列「先到先服務」，可是在加權圖上先到的不一定最快。我們需要的不是「先發現誰就先處理誰」，而是「目前已知最快抵達的那個點先處理」——這正是優先佇列做的事。上面的第 2 關就是這張圖，親手跑一次看 Dijkstra 怎麼避開陷阱。

      關鍵觀察：取出的那一刻，dist 就定案了

      Dijkstra 是一個貪心演算法：每一輪都挑「目前已知 dist 最小」的點 u 出爐，並且大膽宣布——u 的 dist 從此不會再變小了。憑什麼？

      1. 假設有一條「更快到 u」的路存在。這條路一定得先經過某個還沒出爐的點 x，再繞到 u。
      2. 但 u 是目前佇列裡 dist 最小的，所以 dist[x] ≥ dist[u]。
      3. 權重都不是負的，路只會越走越長：經過 x 繞到 u 至少要 dist[x] + (x 到 u 的路程) ≥ dist[u]。繞路不可能更快——矛盾，所以更快的路不存在。
      所以 「每次都先處理目前最快的」不是隨便貪，是因為其他任何走法都得先經過一個至少一樣遠的點。這個保證只需要一個前提：權重不是負的。第 3 步用到了它——這也預告了下面「負權重會壞掉」那一段。

      演算法

      準備 dist 表（起點 0、其他 ∞）、parent 表，和一個裝 (dist, 節點) 的優先佇列，先放入 (0, 起點)。然後重複：

      1. 取出最小 —— 從優先佇列拿出 dist 最小的條目 (d, u)。
      2. 驗票 —— 如果 d 比筆記上的 dist[u] 大，這是張過期舊票（後來已經發現更快走法），直接跳過，回到第 1 步。
      3. 出爐 —— 否則 u 的 dist 定案。逐一檢查 u 的每條邊 u–v（權重 w）。
      4. 鬆弛 —— 若 dist[u] + w < dist[v]：更新 dist[v]、記 parent[v] = u、把新條目 (dist[v], v) 放進佇列。不比較快就什麼都不做。
      5. 佇列空了就結束。要走到終點的完整路線，從終點沿 parent 一路回溯到起點（跟 07 關一模一樣的招）。
      最常漏 第 2 步的驗票。dist 被鬆弛更新後，佇列裡還躺著它的舊條目——C++ 的 priority_queue 沒辦法進去改或刪，所以標準做法是放著不管，取出時再認出它過期（lazy deletion，懶惰刪除）。忘了這一行，同一個點會被重複展開，答案通常還是對的但效率變差；在別的變形題裡甚至會直接算錯。

      負權重為什麼會壞掉

      想像三個點、三條單行道：A→B 權重 2，A→C 權重 5，C→B 權重 −4（走這段路反而倒賺時間，現實少見，但匯率換匯、某些成本模型會出現）。

      為什麼一定要是單行道？如果 C–B 是雙向的 −4，就能在 B、C 之間來回繞，每繞一圈總長再少 8，「最短路」可以無限小，根本沒有答案——這叫負環。本頁的地圖都是雙向路，所以這個例子要特別說成單行道。

      • Dijkstra 從 A 出發，第二輪就把 B 以 dist = 2 出爐定案——因為 2 比 5 小。
      • 但真正的最短是 A → C → B：5 + (−4) = 1。教科書版的 Dijkstra（有「已出爐就不再處理」的 visited 標記）不會回頭改 B——答案錯了。
      • 本頁的「懶惰刪除」寫法沒有 visited 標記，這個小例子剛好會把 B 重新放回佇列、算出 1；但「取出就定案」的保證已經破功，圖再大一點，同一個點可能被反覆重算非常多次，效率保證就沒了。
      • 壞掉的原因就在「關鍵觀察」的第 3 步：貪心的證明用了「路只會越走越長」。負權重讓繞路可能更快，整個證明垮掉。
      記住 有負權邊 → 不能用 Dijkstra，要換 Bellman-Ford（慢一點，但允許負權，還能偵測負環）。第 04 段的延伸挑戰會帶你寫。

      複雜度

      • 時間 O((V+E) log V) —— V 是節點數、E 是邊數。每條邊最多造成一次成功鬆弛、往佇列塞一個條目，佇列裡最多約 E 個條目，每次放入／取出要 O(log) 整理堆（heap）。白話：比 BFS 的 O(V+E) 多付一個 log，是優先佇列「隨時保持最小在最上面」收的手續費。
      • 空間 O(V+E) —— 鄰接串列 O(V+E)、dist 與 parent 各 O(V)、佇列最壞 O(E)。
      • 教學版注意 —— 本頁的 JS 用「每次取出前排序整個陣列」模擬優先佇列，好懂但慢；真正的 std::priority_queue 是二元堆，每次操作只要 O(log n)。

      常見誤解

      • 「Dijkstra 就是 BFS」 —— 反過來說才對：BFS 是 Dijkstra 在「所有權重都是 1」時的特例。權重全一樣時，優先佇列的行為恰好退化成普通佇列，兩者走訪順序一致。權重一不一樣，勝負立判——見第 2 關。
      • 「dist 被更新過就是最終答案」 —— 不是。dist 在出爐前可能被鬆弛好幾次（教學小圖的 C：∞ → 5 → 3）。被取出且驗票有效那一刻才定案。
      • 「發現更短路要去佇列裡改掉舊條目」 —— 不用，也很難（std::priority_queue 根本不提供）。直接塞新條目，舊的取出時跳過——lazy deletion。
      • 「優先佇列裡面是完全排好序的」 —— 不是。堆（heap）只保證最上面那個是最小的，其餘只是「大致有序」。遊戲面板把內容整個排好給你看，是為了教學方便。
      • 「有負權邊照樣能跑」 —— 程式跑得完、還會給你一個數字，但可能是錯的（見上面的反例）。錯得不吭聲的程式最危險。
