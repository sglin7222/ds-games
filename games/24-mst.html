Game 24 · Minimum Spanning Tree

最小生成樹

學校要在六棟建築之間鋪網路線，每兩棟之間的施工長度不一樣。要讓每一棟都連得上，又要總長度最短，該挑哪幾段來鋪？這一關用兩種方法解它：Kruskal 從最便宜的線開始挑、遇到會繞圈的就跳過；Prim 從一棟建築開始，每次往外接一段最便宜的線。兩種方法走法不同，總長度一樣都是 13。

難度中階～進階
時間O(E log E)

先搞懂：最小生成樹（MST）到底是什麼

沒學過程式也看得懂。先把名詞和定義弄清楚，後面的遊戲才不會霧煞煞。

定義：最小生成樹（Minimum Spanning Tree）

DEFINITION · 最小生成樹 MST
在一張連通的加權無向圖裡，挑出一部分的邊，讓所有頂點都連在一起、沒有環，而且這些邊的權重加起來最小。挑出來的這組邊就叫最小生成樹。

頂點有 V 個時，最小生成樹一定剛好有 V − 1 條邊。校園有 6 棟建築，所以要挑 5 段線。

同一個定義，換個說法內容
白話用最少的總長度，把所有地點「串」起來。只要彼此找得到路就好，不要求兩點之間是直達或最近。
拆成三個條件① 全部連到：每個頂點都在裡面，任兩個頂點之間都有路。② 沒有環：不會繞一圈回到原點。③ 總重最小：所有符合 ①② 的挑法裡，權重加總最小的那個。
名字拆開看生成（spanning）＝ 涵蓋全部頂點；樹 ＝ 連通又沒有環；最小 ＝ 總權重最小。
目的 花最少的錢，把所有地方接起來。比喻：學校要鋪網路線，A 校門、B 圖書館、C 餐廳、D 系館、E 宿舍、F 體育館。圖上每條邊是「可以鋪線的路段」，數字是長度。六棟都要連上網，線越短越省錢——多鋪一段繞成一圈是浪費，因為少了它大家還是連得到。真實世界的電網、水管、光纖、道路規劃，都是這個問題。
先備 這一關用到三個前面的東西：第 21 關「圖的基本概念」（頂點、邊、權重、環、連通）、第 22 關「圖的走訪」（連通元件——一張圖可以分成好幾塊）、第 13 關「堆積」（Prim 用最小堆積快速拿出最便宜的邊）。還沒玩過的話，先去看它們的 00 段。

先認識這些詞（照順序讀，後面的詞會用到前面的）

加權無向圖 weighted undirected graph
一堆頂點用邊連起來，邊沒有方向（A–B 和 B–A 是同一條），每條邊上有一個數字叫權重（長度、價錢、時間）。V＝頂點數，E＝邊數。（第 21 關）
校園地圖：建築是頂點，路段是邊，路段長度是權重。
環 cycle
從一個頂點出發，沿著邊走，不重複走同一條邊，最後回到出發點。例如 A–B–C–A。
在校園裡繞一圈回到原地。
連通 connected
任兩個頂點之間都有路可以走到。不連通的圖會分成好幾塊，每一塊叫一個連通元件。（第 22 關）
整個校園的路都接在一起，沒有孤島。
子圖 subgraph
從原本的圖裡挑一部分頂點和邊出來，形成的新圖。只能挑、不能新增原本沒有的邊。
從完整的校園地圖上，用螢光筆畫出其中幾段路。
樹 tree
連通而且沒有環的圖。V 個頂點的樹一定剛好 V−1 條邊：少一條就斷開，多一條就出現環。
一個家族樹：每個人都找得到彼此，但不會繞圈。
生成樹 spanning tree
一個子圖，它包含原圖的全部頂點，而且本身是一棵樹（連通、沒有環、V−1 條邊）。一張圖通常有很多棵不同的生成樹。
用螢光筆畫幾段路，剛好讓六棟建築彼此走得到，而且畫的路不繞圈。
總重 total weight
一棵生成樹裡所有邊的權重加起來。我們要比的就是這個數字。
鋪網路線的總長度＝總花費。
最小生成樹 MST
所有生成樹裡，總重最小的那一棵（可能不只一棵，總重都一樣）。
所有鋪線方案裡，最省錢的那一種。
切割／跨越兩邊的邊 cut / crossing edge
把頂點分成兩群（左邊、右邊），就是一個切割。一端在左邊、另一端在右邊的邊，叫跨越兩邊的邊。
在地圖上畫一條線把校園切成兩半，跨過這條線的路段。
貪心 greedy
每一步都挑眼前最划算的選擇，挑了就不反悔。MST 的兩個演算法都是貪心，而且證明過一定對。
逛夜市每攤都先買最便宜的那樣。
併查集 Union-Find / DSU
記錄「誰跟誰同一組」的工具。每個頂點有一個 p[x]（往上一層是誰），一路往上找到的老大（p[x] = x 的那個）就代表這一組。兩個動作：find（找老大）、union（兩組合併）。
每個社團有一個社長；問「你們社長是誰」就知道是不是同一社。
優先佇列 priority queue / min-heap
一個盒子，放進去的東西可以隨時拿出最小的那個。用最小堆積做，放進去、拿出來都只要 O(log n)。（第 13 關）
號碼牌機，永遠叫號碼最小的先來。
O(E log E) 時間複雜度
邊有 E 條時，大約要做 E × log₂ E 步。主要花在把邊排序。E = 1,000 時約 1 萬步。
把所有路段依長度排一次隊，再從頭看過去。

再判斷：這是「最小」生成樹嗎？

為什麼沒有環 如果挑出來的邊裡有一個環，環上隨便拿掉一條，大家還是連得到（繞環的另一邊就好），總重卻變小了。所以總重最小的那組邊，一定不會有環——它一定是一棵樹。

關鍵觀念：切一刀，跨過去最便宜的那條一定要

這叫切割性質（cut property）：不管怎麼切，跨越兩邊的邊裡最便宜的那條，一定可以放進最小生成樹。理由很直白：如果最小生成樹沒用它、而是用了另一條更貴的跨越邊，把貴的換成便宜的，大家還是連得到，總重更小——矛盾。後面兩個演算法，都是一直在用這個性質。

最小生成樹 ≠ 最短路徑

很多人以為「最小生成樹裡兩點之間的路，就是最短路」。不是。看這個三角形：

兩個不同問題 最小生成樹：讓全部連起來，總長最短（鋪網路線）。最短路徑（第 17 關）：從某一點到另一點，走的路最短（導航）。校園地圖剛好兩者一樣，但一般不會。

容易搞混的幾件事

常被搞混的東西跟最小生成樹一樣嗎？差在哪
最短路徑（第 17 關 Dijkstra）不一樣最短路徑只管「起點到某點」最近；MST 只管「全部接起來」總長最短。上面的三角形就是反例。
走訪樹（第 22 關 BFS／DFS 走出來的樹）不一定BFS／DFS 走出來的也是生成樹（連通、無環），但它不看權重，總重通常不是最小。
「挑最便宜的 V−1 條邊」不一樣可能成環、也可能有頂點沒接到（上面第二排中間那張）。要「跳過會成環的邊」才對——這就是 Kruskal。
最小生成樹只有一棵？不一定權重有平手時可能有好幾棵，但總重一定一樣。所有權重都不一樣時，才保證只有一棵。（遊戲第 4 關）
邊數一定是 V−1？連通時是樹一定是 V−1 條。圖不連通時湊不出一棵樹，只能每塊各做一棵，叫最小生成森林：邊數 ＝ V − 塊數。（遊戲第 6 關）

自我檢查（先自己想，再點開看答案）

一張連通圖有 10 個頂點、30 條邊。它的最小生成樹有幾條邊？
9 條（V − 1）。跟邊有幾條無關。少於 9 條一定有頂點接不到，多於 9 條一定有環。
整張圖裡權重最小的那條邊，一定會在 MST 裡嗎？
會（至少有一棵 MST 用到它）。把它的兩端切成兩邊，它就是跨越兩邊最便宜的邊——切割性質。Kruskal 第一條收的就是它，因為只有一條邊時不可能成環。
整張圖裡權重最大的那條邊，一定不會在 MST 裡嗎？
不一定。如果某個頂點只有這一條邊連出去，不用它那個頂點就接不到，只好用。只有當它在某個環上、而且是環上最重的，才可以丟掉。
校園地圖上，MST 用了 B–D 5，卻沒用比較便宜的 A–B 4。為什麼？
因為 A–B 4 加進去會成環：先收的 B–C 1、A–C 2 已經讓 A、B 走得到彼此（A–C–B），再加 A–B 就繞成 A–B–C–A。而 B–D 5 是把左邊 {A,B,C} 和右邊 {D,E,F} 接起來最便宜的邊，一定要。

你會學到什麼

  • 最小生成樹的定義 —— 全部連通、沒有環、V−1 條邊、總重最小。
  • Kruskal —— 邊由小到大排好，一條一條看，會成環就跳過。
  • 併查集 —— 用 find 找老大，判斷兩端是不是已經同一組（同一組再連就成環）。
  • Prim —— 從一個頂點長出去，每次接上「離開目前這棵樹最便宜的邊」，用最小堆積找。
  • 切割性質 —— 兩個演算法都對的原因。
  • 平手與不連通 —— 最小生成樹可能不只一棵；不連通的圖只能做出最小生成森林。
建議順序 第 1 關 Kruskal → 第 2 關 Prim（同一張圖，總重一樣 13，但收邊順序不同）→ 第 3 關換起點 → 第 4 關平手 → 第 5 關一直成環（看 find 怎麼找老大）→ 第 6 關不連通。

    整份程式逐行白話說明（寫給完全沒學過程式的你）

      這個遊戲跑的程式（完整版）

      把視覺化全部拿掉，兩個演算法就這麼短。上面的面板會依關卡切換成 Kruskal 或 Prim 那一段；這裡是可以直接編譯的完整版（C++17）。頂點用編號 0～n−1（A=0、B=1……），邊用 (w, u, v) 三個數一組：

      #include <bits/stdc++.h>
using namespace std;
typedef tuple<int,int,int> T;             // (權重, 頂點, 頂點)

// ---------- Kruskal ＋ 併查集 ----------
int p[100];                                 // p[x]：x 往上一層是誰；p[x] == x 代表 x 是老大
int find(int x) {
    if (p[x] != x) p[x] = find(p[x]);       // 一路往上找老大，順手把 x 直接掛到老大底下
    return p[x];
}
int kruskal(int n, vector<T> edges) {        // edges 裡每一條是 (w, u, v)，u < v
    sort(edges.begin(), edges.end());       // 先比 w，平手比 u，再平手比 v
    for (int x = 0; x < n; x++) p[x] = x;   // 一開始每個頂點自己一組
    int total = 0, cnt = 0;
    for (auto [w, u, v] : edges) {
        int ru = find(u), rv = find(v);
        if (ru == rv) continue;             // 已經同一組 → 再連就成環，跳過
        if (ru < rv) p[rv] = ru; else p[ru] = rv;   // 兩組合併，編號小的當老大
        total += w; cnt++;                  // 收下這條邊
        if (cnt == n - 1) break;            // 收滿 V−1 條就完成
    }
    return total;
}

// ---------- Prim ＋ 最小堆積 ----------
int prim(int n, vector<vector<pair<int,int>>>& adj, int s) {   // adj[v] = {(鄰居, 權重), …}
    vector<bool> in(n, false);              // in[v]：v 是否已經在樹裡
    priority_queue<T, vector<T>, greater<T>> pq;   // 票 (w, v, from)，最小的先出來
    pq.push({0, s, -1});                    // 起點：花 0 就能進樹
    int total = 0;
    while (!pq.empty()) {
        auto [w, v, from] = pq.top(); pq.pop();
        if (in[v]) continue;                // v 早就在樹裡 → 舊票，丟掉
        in[v] = true; total += w;           // 用 from–v 這條邊把 v 接進樹
        for (auto [x, wx] : adj[v])
            if (!in[x]) pq.push({wx, x, v}); // 從 v 往外的邊都變成候選票
    }
    return total;
}

int main() {
    int n = 6;                              // A B C D E F = 0 1 2 3 4 5
    vector<T> edges = {{4,0,1},{2,0,2},{1,1,2},{5,1,3},{8,2,3},
                       {10,2,4},{2,3,4},{6,3,5},{3,4,5}};
    vector<vector<pair<int,int>>> adj(n);
    for (auto [w, u, v] : edges) { adj[u].push_back({v, w}); adj[v].push_back({u, w}); }
    for (auto& a : adj) sort(a.begin(), a.end());   // 鄰居照字母順序
    printf("Kruskal = %d\n", kruskal(n, edges));    // 13
    printf("Prim    = %d\n", prim(n, adj, 0));       // 13（從 A 出發）
}

      03

      這個功能是怎麼做到的

      從「挑最便宜的」這個直覺出發，修掉它的漏洞，就得到 Kruskal 和 Prim。

      問題定義

      給一張連通的加權無向圖（V 個頂點、E 條邊），挑出 V−1 條邊，讓所有頂點連通、沒有環，而且權重總和最小。輸出這些邊（或它們的總重）。

      最笨的方法是把所有「挑 V−1 條邊」的組合都試一遍。校園地圖 9 條挑 5 條就有 126 種；邊一多，組合數爆炸，完全不可行。我們要一個「一條一條決定、不用反悔」的方法。

      破除錯誤直覺

      直覺對嗎？反例
      「直接挑最便宜的 V−1 條邊」錯校園挑最便宜的 5 條：1、2、2、3、4，A–B–C 成環，而且左邊 {A,B,C} 和右邊 {D,E,F} 根本沒接上。
      「每個頂點都接它最便宜的那條邊」錯校園：A 接 A–C 2、B 和 C 接 B–C 1、D 和 E 接 D–E 2、F 接 E–F 3——只接出 4 條邊，分成兩塊，B–D 5 永遠不會被選到。
      「MST 就是從某點出發的最短路徑樹」錯三角形 A–B 3、B–C 3、A–C 4：MST 是 {A–B, B–C}，但 A 到 C 的最短路是直接走 A–C 4。（00 段的圖）
      「最便宜的先挑，但遇到會成環的就跳過」對這就是 Kruskal。只要多一個「會不會成環」的檢查。

      關鍵觀察：切割性質

      把頂點隨便分成兩群。跨越兩群的邊裡，最便宜的那條一定可以放進最小生成樹（00 段那張切成 {A,B,C}｜{D,E,F} 的圖）。

      • Kruskal 為什麼對：它看到一條邊 u–v、而且 u、v 還不同組時，把「u 那一組」當左邊、其他當右邊。比這條便宜的邊都已經看過了：不是收下（在組內）就是成環被跳過（也在組內），沒有一條跨過這一刀。所以 u–v 就是跨越這刀最便宜的，可以收。
      • Prim 為什麼對：把「目前已經在樹裡的頂點」當左邊、其他當右邊。它每次挑的，正是跨越這一刀最便宜的邊。
      • 平手時：跨越的邊裡有好幾條一樣便宜，挑哪一條都可以，結果可能是不同的樹，但總重一樣。所以程式要把平手規則寫死，答案才固定。
      本頁的平手規則 Kruskal：邊寫成 (w, u, v)，u 的字母比 v 小；先比權重 w，一樣再比 u，再一樣比 v。所以 A–C 2 排在 D–E 2 前面。Prim：票寫成 (w, v, from)；先比 w，一樣比要加入的頂點 v，再一樣比 from。這兩個規則就是 C++ tuple 比大小的預設方式，所以遊戲的動畫和程式跑出來的一模一樣。

      演算法一：Kruskal（從最便宜的邊開始挑）

      1. 把所有邊依權重由小到大排序。
      2. 每個頂點自己一組（併查集：p[x] = x）。
      3. 從最便宜的邊開始，一條一條看 u–v：用 find 找 u 的老大、v 的老大。
      4. 老大一樣 → u、v 已經連在一起了，再加這條會成環 → 跳過。
      5. 老大不一樣 → 收下這條邊，用 union 把兩組併成一組（本頁規則：字母小的老大當新老大）。
      6. 收滿 V−1 條就停（剩下的邊不用看了）。

      為什麼要併查集？「加這條會不會成環」等於問「u 和 v 現在是不是已經走得到彼此」。每次都用第 22 關的 BFS 去走一遍太慢（O(V+E)）；併查集只要沿著 p[] 往上找老大。程式第 3 行的 p[x] = find(p[x]) 叫路徑壓縮：找完之後順手把路上每個人直接掛到老大底下，下次就一步到位。遊戲第 5 關看得到它把 D→C→A 壓成 D→A（第 6 關是把 F→E→D 壓成 F→D）。

      手算 Kruskal：校園地圖

      排好序：B–C 1、A–C 2、D–E 2、E–F 3、A–B 4、B–D 5、D–F 6、C–D 8、C–E 10。p[] 依序是 p[A] p[B] p[C] p[D] p[E] p[F]：

      #邊（權重）find(u)find(v)結果p[A..F] 之後總重
      1B–C（1）BC收下，p[C] = BA B B D E F1
      2A–C（2）AC→B，老大 B收下，p[B] = AA A B D E F3
      3D–E（2）DE收下，p[E] = DA A B D D F5
      4E–F（3）E→D，老大 DF收下，p[F] = DA A B D D D8

      —D–F 6、C–D 8、C–E 10已經收滿 V−1 = 5 條，不用再看13

      演算法二：Prim（從一個頂點長出去）

      1. 選一個起點放進樹（本頁的程式：放一張票 (0, 起點, −1) 進優先佇列）。
      2. 從優先佇列拿出最小的票 (w, v, from)。
      3. 如果 v 已經在樹裡 → 這是舊票（從那時到現在 v 已經用別的邊接進來了），丟掉。
      4. 否則用 from–v 這條邊把 v 接進樹，總重加 w。
      5. 看 v 的每個鄰居 x：x 還不在樹裡，就放一張票 (w(v,x), x, v) 進優先佇列。回到第 2 步，直到佇列空了。

      優先佇列就是第 13 關的最小堆積：放票、拿最小的票都只要 O(log n)。舊票不刪、拿到時再丟，這招和第 17 關 Dijkstra 一樣，叫 lazy deletion。

      另一種寫法是不用堆積，改用一個 key[v] 陣列記「v 接進樹最便宜要多少」，每輪掃一遍找最小——每輪 O(V)，總共 O(V²)。點很少、邊很多（稠密圖）時這個版本反而好。本頁動畫用的是堆積版本，跟上面的程式一行一行對應。

      取出的票 (w, v, from)處理接進樹的邊總重放進 pq 的新票
      (0, A, −)A 是起點，進樹—0(4,B,A) (2,C,A)
      (2, C, A)C 進樹A–C 22(1,B,C) (8,D,C) (10,E,C)
      (1, B, C)B 進樹B–C 13(5,D,B)
      (4, B, A)B 已在樹裡 → 舊票，丟掉—3—
      (5, D, B)D 進樹B–D 58(2,E,D) (6,F,D)
      (2, E, D)E 進樹D–E 210(3,F,E)
      (3, F, E)F 進樹E–F 313—（鄰居都在樹裡）
      (6,F,D) (8,D,C) (10,E,C)都是舊票，一張一張丟掉，佇列空了—13—

      收到的邊和 Kruskal 一模一樣（校園地圖的 MST 只有一棵），總重都是 13，只是收邊的順序不同：Kruskal 是 B–C、A–C、D–E、E–F、B–D（全圖最便宜的先）；Prim 是 A–C、B–C、B–D、D–E、E–F（從 A 一路長出去）。

      複雜度

      V＝頂點數，E＝邊數。連通圖的 E 至少 V−1，最多約 V²／2，所以 log E 和 log V 只差一個常數倍（log E ≤ 2 log V）。

      演算法主要花在哪時間額外空間
      Kruskal排序 E 條邊 O(E log E)；之後最多 E 次 find／union，有路徑壓縮時每次平均不超過 O(log V)，實際上幾乎是常數O(E log E)O(V + E)
      Prim（堆積版）每條邊最多變成一張票（另一端還不在樹裡時才放），每張票放進、拿出堆積各 O(log E)；E 張票合計 O(E log E) ＝ O(E log V)O(E log V)O(E)
      Prim（key 陣列版）V 輪，每輪掃一遍 V 個頂點找最小O(V²)O(V)

      什麼時候用哪一個

      情況建議原因
      邊本來就是一張清單（例如 (w,u,v) 的表格）Kruskal排序＋併查集就寫完，程式最短。
      稀疏圖（E 跟 V 差不多）兩個都好都是 O(E log V) 左右。
      稠密圖（E 接近 V²），或用鄰接矩陣存Prim（key 陣列版）O(V²) 不用排序 V² 條邊。
      圖不連通，要最小生成森林Kruskal不用改，跑完自然每塊各一棵；Prim 要對每一塊各從一個起點跑一次。
      邊會一條一條陸續加進來Kruskal 的併查集併查集很適合「隨時問兩點是否已連通」。

      常見誤解

      • 「Kruskal 和 Prim 一定挑出同一棵樹」 —— 權重有平手時不一定，但總重一定一樣。權重全都不同時，MST 只有一棵，兩個一定一樣。
      • 「Prim 的起點不同，總重會不同」 —— 不會。從哪裡出發都得到最小生成樹（第 2、3 關：從 A、從 F 都是 13）。
      • 「成環的判斷就是看這條邊的兩端是不是已經有邊」 —— 不對。要看兩端是不是已經走得到彼此（同一組），中間可能隔好幾條邊，例如 A–B 4：A、B 之間沒有直接的邊，但 A–C–B 已經連起來了。
      • 「最小生成樹裡兩點之間的路就是最短路」 —— 不是，看 00 段的三角形。要最短路請用第 17 關的 Dijkstra。
      • 「權重可以是負的嗎？會壞掉嗎？」 —— 不會。Kruskal 和 Prim 只比大小，負權重一樣對（這點跟 Dijkstra 不同）。
      下一關 MST 讓「全部連起來」最省；如果你要的是「從校門走到體育館最快的路」，那是另一個問題——到 第 17 關「最短路徑（Dijkstra）」，它也用優先佇列，但比的是「從起點走過來的總距離」，不是單一條邊的長度。

      自己動手：給 AI 的 Prompt

      用 C++ 寫最小生成樹，兩種方法都要：

1. Kruskal：邊存成 tuple(w, u, v)，sort 之後一條一條看；
   用併查集（find 要有路徑壓縮、union 讓編號小的當老大）判斷會不會成環。
2. Prim：用 priority_queue 存 tuple(w, v, from)，greater 讓最小的先出來；
   拿到 v 已在樹裡的舊票就丟掉。

要求：
- 頂點 A~F 對應 0~5，邊：A-B 4, A-C 2, B-C 1, B-D 5, C-D 8, C-E 10, D-E 2, D-F 6, E-F 3
- 兩種方法都印出「收邊的順序」和總重（應該都是 13）
- 每一步印出 Kruskal 的 p[] 陣列，標出哪條邊因為成環被跳過
- 再測一張不連通的圖，說明 Kruskal 會得到什麼（最小生成森林）
