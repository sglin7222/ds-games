怎麼玩

畫面上半是一棵「完全二元樹」（先當它是一張公司組織圖：一個主管最多帶兩個下屬），下半是一排陣列格子。同一個數字在樹上和陣列裡永遠同一個顏色——交換時樹上兩顆球互換，陣列兩格也同時互換。

演示模式

  1. 挑一個關卡，或自己輸入幾個數字。
  2. 按 下一步 一格一格走：每一步都會標明「誰跟誰比、要不要換、為什麼」。
  3. 盯著「同色」這件事看：橘框是主角，虛線框是跟它比較的人，綠框是剛交換的兩個。
  4. 隨時 上一步 倒回去，反覆走看不懂的地方。

闖關模式

  1. 先不給答案，由你回答：下一步誰跟誰比較？會不會交換？取走堆頂之後誰補位？爸爸在陣列哪一格？
  2. 答對得分、連對加分；答錯立刻解釋正確答案和理由。
操作 鍵盤 → 下一步、← 上一步、空白鍵 播放／暫停。

你會學到什麼

  • 用陣列存樹的三條公式 —— parent=(i−1)÷2、left=2i+1、right=2i+2。為什麼「完全二元樹」剛好能這樣存、一格都不浪費。
  • 上浮 sift-up —— 新元素從尾端一路跟爸爸比大小，像新人太強一路升職，最多走 log n 層。
  • 下沉 sift-down —— 取走堆頂後，最後一格補位再往下沉；為什麼一定要跟「較大的那個孩子」交換。
  • 為什麼根一定是最大值 —— 「每個爸爸 ≥ 孩子」這條局部規矩，怎麼保證全域的最大在門口。
  • buildHeap 為什麼是 O(n) —— 從最後一個非葉子往前下沉，和逐一插入 O(n log n) 當場對比。
  • heapsort 的雛形 —— 連續取最大值，出來的序列自動由大到小。
建議順序 第 1、2 關看上浮 → 第 3 關看下沉 → 第 4 關看 heapsort 雛形 → 第 5、6 關用同一包數字對比 buildHeap O(n) 和逐一插入。

    整份程式逐行白話說明（寫給完全沒學過程式的你）

      這個遊戲跑的程式（完整版）

      把視覺化全部拿掉，一個能用的 max-heap 就這麼大——注意 buildHeap 只是把 pop 裡的下沉拿來重複用：

      #include <vector>
using namespace std;

int parent(int i) { return (i - 1) / 2; }   // 整數除法：小數直接捨去
int left_ (int i) { return 2*i + 1; }
int right_(int i) { return 2*i + 2; }

void siftUp(vector<int>& h, int i) {          // 上浮：insert 用
    while (i > 0 && h[parent(i)] < h[i]) {
        swap(h[parent(i)], h[i]);
        i = parent(i);
    }
}
void siftDown(vector<int>& h, int i) {        // 下沉：pop 和 buildHeap 用
    int n = h.size();
    while (true) {
        int b = i, L = left_(i), R = right_(i);
        if (L < n && h[L] > h[b]) b = L;
        if (R < n && h[R] > h[b]) b = R;
        if (b == i) break;                    // 自己最大 → 停
        swap(h[i], h[b]);
        i = b;
    }
}
void push(vector<int>& h, int x) {            // O(log n)
    h.push_back(x);                           // 放到尾端＝樹的最左下空位
    siftUp(h, h.size() - 1);
}
int pop(vector<int>& h) {                     // O(log n)
    int top = h[0];                           // 根一定是最大
    h[0] = h.back();  h.pop_back();           // 最後一格補洞 → 不會產生洞
    siftDown(h, 0);
    return top;
}
void buildHeap(vector<int>& h) {              // O(n)！第 03 段解釋為什麼
    for (int i = (int)h.size()/2 - 1; i >= 0; --i)
        siftDown(h, i);                       // 從最後一個非葉子往前
}

      遊戲頁面多出來的幾百行，全部都是為了「讓過程看得見」——教學程式和生產程式的差別就在這裡。

      03

      這個功能是怎麼做到的

      從「我要隨時拿最大值」這個需求，一路走到用陣列存樹。

      問題定義

      我們要一個「袋子」：隨時可以丟數字進去（insert），隨時可以拿走目前最大的那個（extract-max）。急診室的檢傷分類、作業系統挑下一個要跑的程式、遊戲裡挑威脅最高的敵人——全是這個需求。先看看幾種做法各要花多少力氣（n 是袋子裡的數量）：

      做法insertextract-max問題
      亂放的陣列O(1)O(n)每次拿都要整包掃一遍找最大
      排好序的陣列O(n)O(1)每次插入都要挪出位置
      堆積 heapO(log n)O(log n)兩邊都快——本頁主角

      先破除一個直覺：「想隨時拿最大，就得整包排好序」

      不用。排好序是「每個人都知道自己是第幾名」，但我們的需求只有「第一名要站在門口」——其他人愛怎麼亂站怎麼亂站。全排序是殺雞用牛刀，而且刀很貴（每次插入 O(n)）。

      • 全排序管太多 —— 第二名之後的順序根本沒人問，卻要花力氣維護。
      • 只記最大值又管太少 —— 拿走最大值之後，誰是新的最大？沒有任何線索，只好整包重掃 O(n)。
      關鍵 堆積的答案是一條局部規矩：「每個爸爸 ≥ 自己的孩子」。規矩只管相鄰兩代，卻自動保證全場最大在根——因為任何人往上追祖先，一路只會越來越大，追到頂就是根。

      為什麼可以用陣列存樹：完全二元樹沒有洞

      「完全二元樹」的意思：一層填滿才開下一層，而且每層都由左到右、不跳格。把節點按「上到下、左到右」編號 0、1、2、3…，會發現編號連續沒有空格——所以直接把編號當陣列索引，一格都不浪費，也不必存任何「指標」（記錄孩子在哪的額外欄位）。爸爸孩子的關係變成三條純數學公式。以堆 [50,44,48,10,26,30,35]（n=7）為例：

      ih[i]parent = (i−1)÷2left = 2i+1right = 2i+2
      050—（根沒有爸爸）1 → 442 → 48
      1440 → 503 → 104 → 26
      2480 → 505 → 306 → 35
      3101 → 447 ≥ n 不存在8 ≥ n 不存在
      6352 → 4813 ≥ n 不存在14 ≥ n 不存在
      反過來想 如果樹不是完全二元樹（中間缺人），照層編號就會出現空號，陣列就得留空格，公式會指到空格踩空。所以「insert 永遠放最後一格、pop 永遠拿最後一格補洞」不是隨便選的——它們是唯二不會破壞完全性的動作。

      關鍵觀察：修規矩只要走一條路徑

      insert 或 pop 之後，全場最多只有一個人站錯位置。修正它不用碰整棵樹——太強就一路往上換（上浮），太弱就一路往下換（下沉），走的是樹上的一條直線路徑，最長就是樹的高度。而 n 個節點的完全二元樹，高度只有 log₂n 層：

      節點數 n7151000100 萬
      樹高（最多走幾步）23約 10約 20
      所以 100 萬個元素，insert 或 extract 最多比較約 20 次。這就是 O(log n)：資料翻倍，工作量只加 1。

      演算法

      insert(x) —— 上浮，像新人一路升職：

      1. 放尾端 —— x 放進陣列最後一格（樹的最左下空位），完全性不破壞。
      2. 跟爸爸比 —— 爸爸在 (i−1)÷2。爸爸比我小？交換，我升上去。
      3. 重複到停 —— 直到爸爸 ≥ 我，或我已經是根（i=0）。

      extract-max —— 補洞加下沉：

      1. 取走 h[0] —— 根一定是全場最大。
      2. 最後一格補洞 —— 把 h[n−1] 搬到 h[0]，刪掉最後一格。只有這樣陣列才不會中間破洞。
      3. 往下沉 —— 補上來的人多半太小：跟左右孩子（2i+1、2i+2）比，比較大的那個孩子小就跟它換，一路沉到自己最大或變成葉子。
      最常錯 下沉時跟較小的孩子換是初學者最常犯的錯：換上來的人會比另一個孩子小，規矩馬上又破。一定要跟兩個孩子中較大的換，換上來的人才能鎮得住兩邊。

      手算一次：依序 insert 35、26、48、10、44

      考試在紙上追蹤時就是畫這張表。陣列由左到右就是樹的「上到下、左到右」。

      步動作上浮過程陣列結果
      1insert 35第一個，直接當根[35]
      2insert 26爸爸=(1−1)÷2=0：35 ≥ 26，不換[35, 26]
      3insert 48爸爸 h[0]=35 < 48 → 換；到根，停[48, 26, 35]
      4insert 10爸爸=(3−1)÷2=1：26 ≥ 10，不換[48, 26, 35, 10]
      5insert 44爸爸 h[1]=26 < 44 → 換；再比 h[0]=48 ≥ 44，停[48, 44, 35, 10, 26]

      注意最後的 [48, 44, 35, 10, 26]：它不是由大到小排好的（26 在 10 後面），但每個爸爸都 ≥ 孩子——這才是堆的全部要求。

      buildHeap 為什麼是 O(n)（直觀版）

      把 n 個數一次變成堆，有兩條路：逐一 insert（每個最多浮 log n 層 → O(n log n)），或是 buildHeap：整包放進陣列，從最後一個非葉子往前，每格做一次下沉。後者只要 O(n)，關鍵在「誰做多少工」的分配：

      哪一層（以滿樹 n=15 為例）節點數每個最多沉幾層小計
      最底層（葉子）80（不用動）0
      倒數第二層414
      倒數第三層224
      根133

      合計 11 次交換上限 ≈ n，而不是 n·log n。一般化：一半的節點是葉子完全不用動、四分之一最多沉 1 層、八分之一最多沉 2 層……全部加起來不超過 2n。「會沉很深的人非常少，人多的那群幾乎不用動」——這就是 O(n) 的直觀理由。逐一 insert 剛好相反：人最多的最底層，每個人都可能浮 log n 層。

      複雜度

      • 看最大值 O(1) —— 就在 h[0]，看一眼。
      • insert / extract-max 各 O(log n) —— 上浮、下沉都只走一條路徑，最長是樹高。
      • buildHeap O(n) —— 上面那張表。
      • heapsort O(n log n) —— buildHeap 一次 O(n)，再 pop n 次、每次 O(log n)。
      • 空間 O(n) —— 就是那個陣列本身，沒有指標、沒有額外結構。

      其實你早就用過它：std::priority_queue

      C++ 標準庫的 priority_queue 內部就是本頁的東西——一個 vector 加上浮下沉。這一關玩懂了，它就不再是黑盒子：

      #include <queue>

priority_queue<int> pq;     // 內部：vector + 上浮/下沉，就是本頁的 max-heap
pq.push(35);                // = 放尾端 + siftUp        O(log n)
pq.top();                   // = h[0]                   O(1)
pq.pop();                   // = 最後一格補洞 + siftDown O(log n)

// 想要「最小的先出來」（min-heap）？只是比較方向相反：
priority_queue<int, vector<int>, greater<int>> minpq;

// 把本頁的函式包成類別，就是自己的 priority_queue：
class MaxHeap {
    vector<int> h;                        // 唯一的成員：一個陣列！
public:
    bool empty() const { return h.empty(); }
    int  top()   const { return h[0]; }
    void push(int x);                     // 尾端 + siftUp（同上）
    int  pop();                           // 補洞 + siftDown（同上）
};

      常見誤解

      • 「heap 是排好序的陣列」 —— 錯。反例：[50,44,48,10,26,30,35] 是合法的堆，但 44 排在 48 前面。同一層之間、叔姪之間完全沒有大小規定，唯一的保證是「爸爸 ≥ 孩子」。第 5、6 關還會看到：同一包數字能做出兩個不同的堆，都合法。
      • 「h[1] 一定是第二大」 —— 錯。第二大一定在 h[1] 或 h[2]（它只輸給根，所以一定是根的孩子），但不一定在 h[1]。上面的例子第二大是 h[2]=48。
      • 「pop 之後把較大的孩子往上遞補就好，幹嘛搬最後一格」 —— 遞補會讓洞一路往下移，最後停在中間某層——陣列出現空格，完全性壞掉，三條公式全部失效。搬最後一格是為了保住「沒有洞」。
      • 「這個 heap 就是記憶體的 heap（new / malloc 的那個）」 —— 撞名而已，兩者毫無關係。本頁的 heap 是一種資料結構；記憶體的 heap 只是「動態配置區」的歷史名稱。

      程式架構與說明

      只講流程與分工，不逐行拆解。看懂這一段，你就能自己改這個遊戲。

      整體設計：先算完，再播放

      使用者按「開始」之前，整關的過程就已經全部算好了。buildSteps 把該關所有 insert / extract / buildHeap 跑完，每一步存一份堆的完整快照；畫面只負責把第 N 步畫出來。

      關卡 ops：insert / extract / build 的清單
      buildSteps(level) 把整關跑完一次
      steps[] 每一格：堆快照 + 取出序列 + 比較/交換計數
      畫面只負責把 steps[目前步數] 畫出來
      • 前進後退變成加減一 —— 不必寫「反交換」「反下沉」這種必錯的邏輯。
      • 樹和陣列永遠同步 —— 兩塊畫面讀同一份快照，想不同步都難。這正是本關的教學重點。
      • 演算法與畫面分離 —— buildSteps 裡沒有半行畫面程式碼，就是純粹的堆積演算法。
      代價 每步存一份快照，記憶體 O(步數 × n)。教學規模（十幾個元素）毫無問題，真實工程不會這樣寫。

      自己動手：給 AI 的 Prompt

      用 C++ 的 vector<int> 從零實作一個 max-heap，不可以用 std::priority_queue。

需要的函式：
- void push(vector<int>& h, int x)   // 放到尾端，再上浮
- int  pop(vector<int>& h)           // 取 h[0]，最後一格補洞，再下沉
- void buildHeap(vector<int>& h)     // O(n)：從最後一個非葉子往前逐一下沉

要求：
1. 索引從 0 開始：parent=(i-1)/2、left=2i+1、right=2i+2
2. 下沉時一定跟「較大的那個孩子」交換 —— 並說明跟較小的換為什麼會壞掉
3. 用 [21, 64, 8, 52, 37, 90, 17] 測 buildHeap，印出結果，
   再寫一個 isHeap() 檢查每個 h[i] 都 >= 它的孩子
4. 連續 pop 到空，確認輸出由大到小（這就是 heapsort）

      延伸題 1：原地 heapsort

      不准用第二個陣列：pop 出來的值直接放到「陣列尾端剛空出來的那一格」。
buildHeap 之後重複「h[0] 和 h[n-1] 交換 → n 減 1 → 對 h[0] 下沉」。
結束時同一個陣列變成由小到大。
想清楚：為什麼這樣做完是「由小到大」而不是由大到小？

      延伸題 2：第 k 大的元素（經典面試題）

      串流不斷送數字進來（總量可能上億），隨時要能回答「目前第 k 大是誰」。
提示：維護一個「大小只有 k 的 min-heap」——
新數字比堆頂大才進來、擠掉堆頂；堆頂永遠就是第 k 大。
說明為什麼這裡反而要用 min-heap，以及複雜度為什麼是 O(n log k)。

      延伸題 3：合併 k 個已排序的串列

      k 條已經各自排好序的串列，要合併成一條。
把每條的開頭放進一個大小 k 的堆，每次取出最小的、補上它的下一個。
複雜度 O(N log k)，N 是總元素數。這就是外部排序／資料庫合併的核心。
