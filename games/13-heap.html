先搞懂：最大堆積（Max-Heap）到底是什麼

沒學過程式也看得懂。先把名詞和定義弄清楚，後面的遊戲才不會霧煞煞。

定義：最大堆積（Max-Heap）

DEFINITION · 最大堆積 Max-Heap
最大堆積（Max-Heap）是一棵完全二元樹，而且樹上每一個節點的值，都大於或等於它的孩子的值。

白話：資料排成一層一層、由左到右排滿的樹形，每個「爸爸」都不能輸給自己的「孩子」。只要遵守這兩條，最大的數字一定站在最上面（根），想拿最大值時看一眼就有，不用整包找。

同一個定義，換個說法內容
白話排得整整齊齊的樹，每個爸爸 ≥ 自己的孩子。
樹的說法① 形狀：完全二元樹。② 大小：對每個節點 x 和它的每個孩子 c，x 的值 ≥ c 的值。
陣列的說法
（電腦真正存的樣子）		資料存在陣列 h[0]、h[1]、……、h[n−1]，中間沒有空格。對每一個 i ≥ 1：h[(i−1)÷2] ≥ h[i]。（(i−1)÷2 就是 i 的爸爸，下面會解釋）
直接結果最大值一定是 h[0]（根）。
對照 把「≥」換成「≤」，就是最小堆積（Min-Heap）：每個爸爸 ≤ 孩子，根是最小值。兩者合稱二元堆積（Binary Heap），平常簡稱「堆積」或 heap。本關玩的全部是最大堆積，下文說 heap 時，指的都是 Max-Heap。

定義裡有好幾個沒聽過的詞——「樹」、「節點」、「孩子」、「完全二元樹」。別急，下面一個一個拆。先記住 Max-Heap 想解決的事情只有一件：

目的 一堆數字一直有人丟進來、也一直有人要拿走目前最大的。heap 讓這兩件事都很快。就像急診室：病人隨時進來，醫生每次都先看最嚴重的那位，不是看誰先到。
名字 「二元」＝每個節點最多帶兩個孩子（下面的名詞卡會講「二元樹」）。「堆積」＝像一堆疊起來的東西，最大的壓在最上面。「最大」＝根放的是最大值。

先認識這些詞（照順序讀，後面的詞會用到前面的）

資料結構 data structure
「一堆資料要怎麼擺」的規則。擺法不同，找東西、放東西的速度就差很多。heap 就是其中一種擺法。
同樣一堆衣服，摺好分格放 vs. 全塞進一個袋子，找起來速度天差地遠。
陣列 / 索引 array / index
陣列是一排連在一起、有編號的格子，每格放一個資料。格子的編號叫「索引」，從 0 開始數，所以第一格是 0 號、第二格是 1 號。
車站的置物櫃：0 號櫃、1 號櫃、2 號櫃……報號碼就能直接打開那一格。
樹 tree
一種「由上往下分岔」的擺法。最上面一個，往下分出幾個，每個再往下分……畫出來像一棵倒過來的樹。
家族族譜、公司組織圖：總經理在頂端，底下是經理，經理底下是員工。
節點 node
樹上的每一個圓圈就是一個節點，裡面裝一筆資料（在這一關就是一個數字）。
組織圖上的每一個人。
爸爸 / 孩子 parent / child
用一條線直接連起來的上下兩個節點：上面那個叫爸爸（父節點），下面那個叫孩子（子節點）。
直屬主管和他直接帶的下屬。
根 root
最上面那個節點，唯一沒有爸爸的人。在 heap 裡，根就是最大值站的位置。
公司的總經理。
葉子 leaf
沒有孩子的節點，都在樹的最底下、最邊緣。
組織圖最底層、沒有帶人的基層員工。
層 / 樹高 level / height
根是第 0 層，根的孩子是第 1 層，依此類推。樹高＝從根一路往下走到最底層，要走幾步。
族譜上的「第幾代」。
二元樹 binary tree
每個節點最多兩個孩子的樹。兩個孩子分左右，叫「左孩子」和「右孩子」。「二元」就是「最多分兩岔」的意思。
一個主管最多只能帶兩個下屬。
完全二元樹 complete binary tree
一種排得很整齊的二元樹：上面一層坐滿才能往下一層，而且每一層都從左到右依序坐、不跳位。只有最後一層可以沒坐滿，但空位只能在右邊。
電影院從第一排、從最左邊的座位開始依序入座，中間不能留空位。（名詞卡後面有完整定義和圖例）
堆積性質 heap property
heap 的大小規矩：每個爸爸 ≥ 自己的每個孩子。注意它只管「爸爸和自己的孩子」，不管左右兄弟誰大誰小，也不管隔好幾代的親戚。
每個主管的能力值都不能輸給自己帶的下屬；但兩個同事之間誰強，沒有規定。
最大堆積 / 最小堆積 max-heap / min-heap
爸爸 ≥ 孩子 → 最大堆積，根是最大值（本關玩的就是這種）。反過來爸爸 ≤ 孩子 → 最小堆積，根是最小值。兩種做法完全一樣，只是比大小的方向相反。
「最強的站頂端」或「最弱的站頂端」，看你要拿哪一種。
優先佇列 priority queue
一種需求的名字：「東西隨時放進來，每次拿出來的都是最優先的那個」。heap 是實現這個需求最常用的方法。C++ 內建的 std::priority_queue，裡面就是一個 heap。
急診室的看診順序、機場的優先登機。一般的「佇列」是先到先服務；「優先佇列」是重要的先服務。
上浮 / 下沉 sift-up / sift-down
heap 被放進或拿走東西之後，有人會站錯位置。上浮＝太大的一路往上跟爸爸換；下沉＝太小的一路往下跟孩子換。這就是本關遊戲在演的事。
新人太強一路升職（上浮）；主管不夠格一路降職（下沉）。
O(log n)、O(n) Big-O 記號
描述「資料變多時，工作量怎麼跟著變多」。n 是資料的數量。O(n)：資料多一倍，工作也多一倍。O(log n)：資料多一倍，工作只多一步——非常快。
O(n) 像從頭到尾翻每一頁找名字；O(log n) 像翻字典，每翻一次就丟掉一半。（後面有完整說明和對照表）

先定義：完全二元樹（Complete Binary Tree）

Max-Heap 的定義第一句就是「完全二元樹」，所以先把它講清楚。它是一種二元樹（每個節點最多兩個孩子），而且有規定「形狀」：

DEFINITION · 完全二元樹 Complete Binary Tree
一棵二元樹，如果除了最後一層以外，每一層都坐滿，而且最後一層的節點全部從最左邊開始、連續靠左排，就叫完全二元樹。

白話：像電影院入座——一排坐滿才能坐下一排，每一排都從最左邊的位子依序坐，中間不可以留空位。只有最後一排可以沒坐滿，空位只能在右邊。

同一個定義，換個說法內容
一層一層看第 0 層（根）最多 1 個、第 1 層最多 2 個、第 2 層最多 4 個、第 k 層最多 2k 個。除了最後一層，每層都要剛好坐滿；最後一層的人全部擠在左邊。
編號的說法
（最好用的判斷法）		從根開始，上到下、每層左到右，給每個節點依序編號 0、1、2、3……。如果 n 個節點的編號剛好是 0 到 n−1、一個都沒跳，它就是完全二元樹；中間跳號就不是。
長出新節點時新節點只能放在下一個號碼 n 的位置；要拿掉節點時只能拿最後一號 n−1。其他位置一動，就會跳號。

下面每張圖，圓圈裡的數字是那個位置的編號（從根開始，上到下、每層左到右數）。編號連續不跳就是完全二元樹，跳號就不是。先自己判斷，再看說明：

它跟 heap 有什麼關係？

  • 可以直接放進陣列。編號 0～n−1 沒有跳號，所以編號就直接當陣列的格子號碼，一格都不浪費。第 i 號的爸爸在 (i−1)÷2、左孩子在 2i+1、右孩子在 2i+2——這三條公式只有在不跳號時才成立。
  • 樹一定很矮。每往下一層，能坐的人數就翻倍，所以 n 個節點只要大約 log₂n 層：7 個人 3 層、1000 個人 10 層、100 萬人 20 層。上浮、下沉最多走樹高那麼多步，所以才快。
  • insert 放最後一格、pop 拿最後一格補洞——就是為了守住「不跳號」。
名詞規定例子
二元樹只規定每個節點最多兩個孩子，形狀隨便。上面六張圖全部都是二元樹
完全二元樹二元樹 ＋ 除最後一層外都坐滿 ＋ 最後一層靠左連續。上面三張 ✔
滿二元樹每一層都坐滿（節點數剛好是 1、3、7、15……）。只有第二張
注意 有些英文課本的 full binary tree 意思是「每個節點不是 0 個就是 2 個孩子」，跟中文「滿二元樹」不一樣。看英文資料時要留意它用哪一種定義。不管哪一種，heap 要求的都是 complete（完全）。
一棵完全二元樹有 10 個節點，它有幾層？最後一層有幾個？
前三層最多坐 1 + 2 + 4 = 7 個，剩下 10 − 7 = 3 個坐在第 4 層（第 3 層，從 0 數），擠在最左邊。所以總共 4 層，樹高 3。
接著第 11 個節點要放在哪？它是誰的孩子、左還是右？
放在下一個號碼 10。爸爸是 (10−1)÷2 = 4 號；4 號的左孩子是 2×4+1 = 9、右孩子是 2×4+2 = 10，所以它是 4 號的右孩子。
一棵二元樹只有根和它的右孩子，是完全二元樹嗎？
不是。照順序編號，第 1 號位子（根的左孩子）是空的，右孩子卻是第 2 號——跳號了。改成「根和它的左孩子」才是。

定義拆成兩個條件：缺一個就不是 Max-Heap

  1. 形狀條件——整棵樹必須是完全二元樹：一層一層、由左到右排滿，中間不准有空位。
  2. 大小條件——每個爸爸都要 ≥ 自己的孩子（最大堆積）。

同一個 heap，在電腦裡其實是一排格子

樹是畫給人看的。電腦真正存的是一個陣列：把樹上的節點從上到下、每層從左到右，依序編號 0、1、2、3……，編號就是陣列的格子號碼。因為完全二元樹沒有空位，格子剛好一格接一格排滿，一格都不浪費。

時間複雜度：O(n) 和 O(log₂ n) 差多少？用二分搜尋來理解

時間複雜度不是在量「幾秒」，而是在數「資料有 n 個時，最多要做幾步」。電腦有快有慢，但步數不會騙人。這一關會一直看到兩種：

  • 線性 O(n)：資料有幾個，就要做幾步。像在一排沒整理的考卷裡找最高分，只能一張一張翻完。
  • 對數 O(log₂ n)：每做一步，就把剩下的範圍砍掉一半，砍到只剩 1 個為止。要做的步數 = 「n 要對半切幾次才剩 1」。
資料量 n線性 O(n)對數 O(log₂ n)
88 步3 步
1,0241,024 步10 步
1,048,576（≈ 106）約 100 萬步20 步
1,000,000,000（109）約 10 億步約 30 步

資料從 8 個變成 10 億個（多了 1 億倍以上），線性的步數跟著多 1 億倍；對數的步數只從 3 變成 30。

log₂ n 是什麼？用二分搜尋（猜數字）來看

玩一個遊戲：我心裡想一個 1～8 的數字，你只能問「是不是比某個數大？」我只回答是或否。最聰明的問法是每次都問正中間——不管答案是什麼，都能排除一半。這個方法就叫二分搜尋（第 15 關整關都在玩它）：

n對半切的過程切幾次為什麼
88 → 4 → 2 → 1323 = 8
1,0241024 → 512 → 256 → … → 2 → 110210 = 1,024
1,048,576每次砍半，砍 20 次20220 = 1,048,576
109每次砍半，砍約 30 次約 30230 = 1,073,741,824 ≈ 109
log₂ n log₂ n ＝「n 要對半切幾次才剩 1」＝「2 要自己乘幾次才到 n」。反過來說：資料翻一倍，只要多切一刀。所以 1,024 個要 10 步，2,048 個也才 11 步。

這跟 Max-Heap 有什麼關係？

Max-Heap 是完全二元樹：每往下一層，能放的節點數就翻一倍（1、2、4、8……）。倒過來看，從最底層往根走，每往上一層，那一層的人數就砍一半——跟二分搜尋一模一樣。所以 n 個節點的樹，大約只有 log₂ n 層：

  • push（上浮）：新數字從最底層出發，每次跟爸爸比一下、往上一層，最多走到根——最多約 log₂ n 步。
  • pop（下沉）：補上來的數字從根出發，每次往下一層，最多走到最底層——最多約 log₂ n 步。
  • 對照：如果不用 heap，而是把數字亂放在陣列裡，每次找最大值都要整排看完——n 步。

套回上面的表：heap 裡有 10 億個數字時，放一個進去或拿走最大值，最多只要換大約 30 層；亂放的陣列每次找最大，要看 10 億個。

heap 裡有 1,024 個數字。插入一個新數字，最多要往上換幾次？
最多 10 次。1,024 個節點的完全二元樹有 11 層（第 0～10 層），最底層的人最多往上換 10 次就到根。10 正好是 log₂ 1024。
資料量從 100 萬變成 200 萬，O(n) 和 O(log₂ n) 的步數各變多少？
O(n)：從約 100 萬步變成約 200 萬步，多一倍。O(log₂ n)：從約 20 步變成約 21 步，只多 1 步——因為多一倍的資料只要多切一刀。

容易搞混的幾件事

常被搞混的東西跟 heap 一樣嗎？差在哪
排好序的陣列不一樣排好序是「每個人都知道自己第幾名」。heap 只保證「第一名在最上面」，其他人只要比自己爸爸小就好，整體看起來是亂的。例如 [50,44,48,10,26,30] 是 heap，但沒有排序。
二元搜尋樹 BST（第 11 關）不一樣BST 規定「左邊都比我小、右邊都比我大」，是左右的規矩。heap 是「上面比下面大」，是上下的規矩，左右兄弟誰大都可以。
優先佇列 priority queue相關優先佇列是「要做什麼」（每次拿最優先的），heap 是「怎麼做」（用樹＋上浮下沉）。
記憶體裡的「heap 區」只是同名C++ 用 new 要記憶體時，那塊空間也叫 heap。跟本關的資料結構完全無關，只是剛好撞名。

自我檢查（先自己想，再點開看答案）

最大堆積裡，最大值一定在哪裡？最小值呢？
最大值一定在根（陣列第 0 格）。最小值沒有固定位置，只知道（數字都不相同時）它一定是某片葉子：如果它有孩子，孩子就得比它小，那它就不是最小了。
[9, 5, 8, 1, 6] 是不是最大堆積？
不是。畫成樹：根 9，孩子 5 和 8；5 的孩子是 1 和 6。檢查每對爸爸孩子：9≥5 ✔、9≥8 ✔、5≥1 ✔——但 5 ≥ 6 不成立 ✘。這題故意設陷阱：前幾對都對，一定要每一對都檢查完。
有一個 heap 存了 100 萬個數字，拿走最大值之後重新整理好，大概要比較幾次？
大約 20 次左右（每層比一下，100 萬個節點的完全二元樹只有約 20 層）。這就是 O(log n) 的威力：資料多 100 萬倍，工作量只多二十幾步。
為什麼 heap 一定要是「完全」二元樹？隨便一棵二元樹不行嗎？
因為要存進陣列、用公式找爸爸孩子。完全二元樹一格接一格沒有空位，公式算出來的格子號碼一定對得上；如果中間有空位，陣列就得留空格，公式會指到不存在的人。另外，完全二元樹最「矮」，樹高只有 log n，上浮下沉才走得快。
準備好了 名詞都懂了，往下到 01 看怎麼玩，再到 02 親手看上浮和下沉。

你會學到什麼

  • 用陣列存樹的三條公式 —— parent=(i−1)÷2、left=2i+1、right=2i+2。為什麼「完全二元樹」剛好能這樣存、一格都不浪費。
  • 上浮 sift-up —— 新元素從尾端一路跟爸爸比大小，像新人太強一路升職，最多走 log n 層。
  • 下沉 sift-down —— 取走堆頂後，最後一格補位再往下沉；為什麼一定要跟「較大的那個孩子」交換。
  • 為什麼根一定是最大值 —— 「每個爸爸 ≥ 孩子」這條局部規矩，怎麼保證全域的最大在門口。
  • buildHeap 為什麼是 O(n) —— 從最後一個非葉子往前下沉，和逐一插入 O(n log n) 當場對比。
  • heapsort 的雛形 —— 連續取最大值，出來的序列自動由大到小。
建議順序 第 1、2 關看上浮 → 第 3 關看下沉 → 第 4 關看 heapsort 雛形 → 第 5、6 關用同一包數字對比 buildHeap O(n) 和逐一插入。

    — 按「下一步」，這裡會用白話解釋目前亮起的那一行程式在做什麼。
    整份程式逐行白話說明（寫給完全沒學過程式的你）

      這個遊戲跑的程式（完整版）

      把視覺化全部拿掉，一個能用的 max-heap 就這麼大——注意 buildHeap 只是把 pop 裡的下沉拿來重複用：

      #include <vector>
using namespace std;

int parent(int i) { return (i - 1) / 2; }   // 整數除法：小數直接捨去
int left_ (int i) { return 2*i + 1; }
int right_(int i) { return 2*i + 2; }

void siftUp(vector<int>& h, int i) {          // 上浮：insert 用
    while (i > 0 && h[parent(i)] < h[i]) {
        swap(h[parent(i)], h[i]);
        i = parent(i);
    }
}
void siftDown(vector<int>& h, int i) {        // 下沉：pop 和 buildHeap 用
    int n = h.size();
    while (true) {
        int b = i, L = left_(i), R = right_(i);
        if (L < n && h[L] > h[b]) b = L;
        if (R < n && h[R] > h[b]) b = R;
        if (b == i) break;                    // 自己最大 → 停
        swap(h[i], h[b]);
        i = b;
    }
}
void push(vector<int>& h, int x) {            // O(log n)
    h.push_back(x);                           // 放到尾端＝樹的最左下空位
    siftUp(h, h.size() - 1);
}
int pop(vector<int>& h) {                     // O(log n)
    int top = h[0];                           // 根一定是最大
    h[0] = h.back();  h.pop_back();           // 最後一格補洞 → 不會產生洞
    siftDown(h, 0);
    return top;
}
void buildHeap(vector<int>& h) {              // O(n)！第 03 段解釋為什麼
    for (int i = (int)h.size()/2 - 1; i >= 0; --i)
        siftDown(h, i);                       // 從最後一個非葉子往前
}

      遊戲頁面多出來的幾百行，全部都是為了「讓過程看得見」——教學程式和生產程式的差別就在這裡。

      03

      這個功能是怎麼做到的

      從「我要隨時拿最大值」這個需求，一路走到用陣列存樹。

      問題定義

      我們要一個「袋子」：隨時可以丟數字進去（insert），隨時可以拿走目前最大的那個（extract-max）。急診室的檢傷分類、作業系統挑下一個要跑的程式、遊戲裡挑威脅最高的敵人——全是這個需求。先看看幾種做法各要花多少力氣（n 是袋子裡的數量）：

      做法insertextract-max問題
      亂放的陣列O(1)O(n)每次拿都要整包掃一遍找最大
      排好序的陣列O(n)O(1)每次插入都要挪出位置
      堆積 heapO(log n)O(log n)兩邊都快——本頁主角

      先破除一個直覺：「想隨時拿最大，就得整包排好序」

      不用。排好序是「每個人都知道自己是第幾名」，但我們的需求只有「第一名要站在門口」——其他人愛怎麼亂站怎麼亂站。全排序是殺雞用牛刀，而且刀很貴（每次插入 O(n)）。

      • 全排序管太多 —— 第二名之後的順序根本沒人問，卻要花力氣維護。
      • 只記最大值又管太少 —— 拿走最大值之後，誰是新的最大？沒有任何線索，只好整包重掃 O(n)。
      關鍵 堆積的答案是一條局部規矩：「每個爸爸 ≥ 自己的孩子」。規矩只管相鄰兩代，卻自動保證全場最大在根——因為任何人往上追祖先，一路只會越來越大，追到頂就是根。

      為什麼可以用陣列存樹：完全二元樹沒有洞

      「完全二元樹」的意思：一層填滿才開下一層，而且每層都由左到右、不跳格。把節點按「上到下、左到右」編號 0、1、2、3…，會發現編號連續沒有空格——所以直接把編號當陣列索引，一格都不浪費，也不必存任何「指標」（記錄孩子在哪的額外欄位）。爸爸孩子的關係變成三條純數學公式。以堆 [50,44,48,10,26,30,35]（n=7）為例：

      ih[i]parent = (i−1)÷2left = 2i+1right = 2i+2
      050—（根沒有爸爸）1 → 442 → 48
      1440 → 503 → 104 → 26
      2480 → 505 → 306 → 35
      3101 → 447 ≥ n 不存在8 ≥ n 不存在
      6352 → 4813 ≥ n 不存在14 ≥ n 不存在
      反過來想 如果樹不是完全二元樹（中間缺人），照層編號就會出現空號，陣列就得留空格，公式會指到空格踩空。所以「insert 永遠放最後一格、pop 永遠拿最後一格補洞」不是隨便選的——它們是唯二不會破壞完全性的動作。

      關鍵觀察：修規矩只要走一條路徑

      insert 或 pop 之後，全場最多只有一個人站錯位置。修正它不用碰整棵樹——太強就一路往上換（上浮），太弱就一路往下換（下沉），走的是樹上的一條直線路徑，最長就是樹的高度。而 n 個節點的完全二元樹，高度只有 log₂n 層：

      節點數 n7151000100 萬
      樹高（最多走幾步）23約 10約 20
      所以 100 萬個元素，insert 或 extract 最多比較約 20 次。這就是 O(log n)：資料翻倍，工作量只加 1。

      演算法

      insert(x) —— 上浮，像新人一路升職：

      1. 放尾端 —— x 放進陣列最後一格（樹的最左下空位），完全性不破壞。
      2. 跟爸爸比 —— 爸爸在 (i−1)÷2。爸爸比我小？交換，我升上去。
      3. 重複到停 —— 直到爸爸 ≥ 我，或我已經是根（i=0）。

      extract-max —— 補洞加下沉：

      1. 取走 h[0] —— 根一定是全場最大。
      2. 最後一格補洞 —— 把 h[n−1] 搬到 h[0]，刪掉最後一格。只有這樣陣列才不會中間破洞。
      3. 往下沉 —— 補上來的人多半太小：跟左右孩子（2i+1、2i+2）比，比較大的那個孩子小就跟它換，一路沉到自己最大或變成葉子。
      最常錯 下沉時跟較小的孩子換是初學者最常犯的錯：換上來的人會比另一個孩子小，規矩馬上又破。一定要跟兩個孩子中較大的換，換上來的人才能鎮得住兩邊。

      插入 50 到 [48,44,35,10,26,30]（橘色是主角，紅色是跟它比、而且違規的那個）：

      考試在紙上追蹤時就是畫這張表。陣列由左到右就是樹的「上到下、左到右」。

      步動作上浮過程陣列結果

      這就是遊戲第 3 關。每一次都是同樣三招：取走根 → 最後一格補到根 → 下沉。下沉時「孩子在 2i+1、2i+2」：

      取出的順序 50 → 48 → 44：每次都是「剩下之中最大的」。一直 pop 到空，就是第 4 關的 heapsort。

      buildHeap 為什麼是 O(n)（直觀版）

      把 n 個數一次變成堆，有兩條路：逐一 insert（每個最多浮 log n 層 → O(n log n)），或是 buildHeap：整包放進陣列，從最後一個非葉子往前，每格做一次下沉。後者只要 O(n)，關鍵在「誰做多少工」的分配：

      哪一層（以滿樹 n=15 為例）節點數每個最多沉幾層小計
      最底層（葉子）80（不用動）0
      倒數第二層414
      倒數第三層224
      根133

      合計 11 次交換上限，比 n = 15 還少，而不是 n·log n。一般化：一半的節點是葉子完全不用動、四分之一最多沉 1 層、八分之一最多沉 2 層……全部加起來，交換次數不會超過 n（下沉每層最多比較 2 次，所以比較次數不超過 2n）。「會沉很深的人非常少，人多的那群幾乎不用動」——這就是 O(n) 的直觀理由。逐一 insert 剛好相反：人最多的最底層，每個人都可能浮 log n 層。

      「最後一個非葉子」在哪一格？

      陣列最後一格是索引 n−1，它的爸爸就是最後一個有孩子的人：(n−1−1)÷2 = (n−2)÷2。整數除法下這跟 n÷2 − 1 永遠相等（程式裡寫的是後者）。例如 n = 7：(7−2)÷2 = 2，7÷2−1 = 3−1 = 2。比它後面的格子全是葉子，天生就是合法的「一人小堆」，不用處理。

      手算一次：buildHeap([21, 64, 8, 52, 37, 90, 17])

      這就是遊戲第 5 關。n = 7，從索引 2 開始往前，每格做一次下沉：

      輪到下沉過程陣列結果
      開始整包照原樣放進來，還不是 Max-Heap[21, 64, 8, 52, 37, 90, 17]
      i = 28 的孩子在 5、6：90、17，較大是 90 → 換；8 到索引 5，是葉子，停[21, 64, 90, 52, 37, 8, 17]
      i = 164 的孩子在 3、4：52、37，都 ≤ 64，不用動[21, 64, 90, 52, 37, 8, 17]
      i = 021 的孩子 64、90，較大是 90 → 換；21 到索引 2，孩子 8、17 都 ≤ 21，停[90, 64, 21, 52, 37, 8, 17]

      總共比較 8 次、交換 2 次。同一包數字改用逐一 insert（第 6 關）會得到 [90, 52, 64, 21, 37, 8, 17]，比較 8 次、交換 4 次——長相不同，但兩個都是合法的 Max-Heap。

      別誤會 「逐一 insert 是 O(n log n)」說的是最壞情況：數字剛好由小到大送進來，每個新人都要一路浮到根。如果數字是亂序送進來，大多數人浮一兩層就停了，平均也很快。buildHeap 的好處是不管資料長怎樣，保證 O(n)。

      複雜度

      • 看最大值 O(1) —— 就在 h[0]，看一眼。
      • insert / extract-max 各 O(log n) —— 上浮、下沉都只走一條路徑，最長是樹高。
      • buildHeap O(n) —— 上面那張表。
      • heapsort O(n log n) —— buildHeap 一次 O(n)，再 pop n 次、每次 O(log n)。
      • 空間 O(n) —— 就是那個陣列本身，沒有指標、沒有額外結構。

      其實你早就用過它：std::priority_queue

      C++ 標準庫的 priority_queue 內部就是本頁的東西——一個 vector 加上浮下沉。這一關玩懂了，它就不再是黑盒子：

      #include <queue>

priority_queue<int> pq;     // 內部：vector + 上浮/下沉，就是本頁的 max-heap
pq.push(35);                // = 放尾端 + siftUp        O(log n)
pq.top();                   // = h[0]                   O(1)
pq.pop();                   // = 最後一格補洞 + siftDown O(log n)

// 想要「最小的先出來」（min-heap）？只是比較方向相反：
priority_queue<int, vector<int>, greater<int>> minpq;

// 把本頁的函式包成類別，就是自己的 priority_queue：
class MaxHeap {
    vector<int> h;                        // 唯一的成員：一個陣列！
public:
    bool empty() const { return h.empty(); }
    int  top()   const { return h[0]; }
    void push(int x);                     // 尾端 + siftUp（同上）
    int  pop();                           // 補洞 + siftDown（同上）
};

      常見誤解

      • 「heap 是排好序的陣列」 —— 錯。反例：[50,44,48,10,26,30,35] 是合法的堆，但 44 排在 48 前面。同一層之間、叔姪之間完全沒有大小規定，唯一的保證是「爸爸 ≥ 孩子」。第 5、6 關還會看到：同一包數字能做出兩個不同的堆，都合法。
      • 「h[1] 一定是第二大」 —— 錯。第二大一定在 h[1] 或 h[2]（它只輸給根，所以一定是根的孩子），但不一定在 h[1]。上面的例子第二大是 h[2]=48。
      • 「pop 之後把較大的孩子往上遞補就好，幹嘛搬最後一格」 —— 遞補會讓洞一路往下移，最後停在中間某層——陣列出現空格，完全性壞掉，三條公式全部失效。搬最後一格是為了保住「沒有洞」。
      • 「這個 heap 就是記憶體的 heap（new / malloc 的那個）」 —— 撞名而已，兩者毫無關係。本頁的 heap 是一種資料結構；記憶體的 heap 只是「動態配置區」的歷史名稱。

      程式架構與說明

      只講流程與分工，不逐行拆解。看懂這一段，你就能自己改這個遊戲。

      整體設計：先算完，再播放

      使用者按「開始」之前，整關的過程就已經全部算好了。buildSteps 把該關所有 insert / extract / buildHeap 跑完，每一步存一份堆的完整快照；畫面只負責把第 N 步畫出來。

      關卡 ops：insert / extract / build 的清單
      buildSteps(level) 把整關跑完一次
      steps[] 每一格：堆快照 + 取出序列 + 比較/交換計數
      畫面只負責把 steps[目前步數] 畫出來
      • 前進後退變成加減一 —— 不必寫「反交換」「反下沉」這種必錯的邏輯。
      • 樹和陣列永遠同步 —— 兩塊畫面讀同一份快照，想不同步都難。這正是本關的教學重點。
      • 演算法與畫面分離 —— buildSteps 裡沒有半行畫面程式碼，就是純粹的堆積演算法。
      代價 每步存一份快照，記憶體 O(步數 × n)。教學規模（十幾個元素）毫無問題，真實工程不會這樣寫。

      層主要函式負責什麼

      核心資料：一個 step 長什麼樣

      {
  kind:   // push / cmp / swap / stay / extract / movelast / popdone / …
           // → 決定顏色、徽章、歷程標籤
  focus:  // 主角在陣列哪一格 → 樹和陣列同時亮橘框
  other, other2: // 一起被比較的格子（爸爸，或左右孩子）→ 虛線框
  heap:   // 這一步之後整個堆的快照 [{v:值, id:顏色編號}, …]
  out:    // 到目前為止取出的值 → 「取出的值」面板
  cmp, swp: // 累計比較／交換次數 → 統計面板（第 5、6 關對比用）
  line:   // C++ 程式要高亮第幾行
  title, msg: // 說明面板的標題與內文
  quiz:   // 闖關題 {q, opts, ans}；沒有這個欄位就不出題
}

      自己動手：給 AI 的 Prompt

      用 C++ 的 vector<int> 從零實作一個 max-heap，不可以用 std::priority_queue。

需要的函式：
- void push(vector<int>& h, int x)   // 放到尾端，再上浮
- int  pop(vector<int>& h)           // 取 h[0]，最後一格補洞，再下沉
- void buildHeap(vector<int>& h)     // O(n)：從最後一個非葉子往前逐一下沉

要求：
1. 索引從 0 開始：parent=(i-1)/2、left=2i+1、right=2i+2
2. 下沉時一定跟「較大的那個孩子」交換 —— 並說明跟較小的換為什麼會壞掉
3. 用 [21, 64, 8, 52, 37, 90, 17] 測 buildHeap，印出結果，
   再寫一個 isHeap() 檢查每個 h[i] 都 >= 它的孩子
4. 連續 pop 到空，確認輸出由大到小（這就是 heapsort）

      延伸題 1：原地 heapsort

      不准用第二個陣列：pop 出來的值直接放到「陣列尾端剛空出來的那一格」。
buildHeap 之後重複「h[0] 和 h[n-1] 交換 → n 減 1 → 對 h[0] 下沉」。
結束時同一個陣列變成由小到大。
想清楚：為什麼這樣做完是「由小到大」而不是由大到小？

      延伸題 2：第 k 大的元素（經典面試題）

      串流不斷送數字進來（總量可能上億），隨時要能回答「目前第 k 大是誰」。
提示：維護一個「大小只有 k 的 min-heap」——
新數字比堆頂大才進來、擠掉堆頂；堆頂永遠就是第 k 大。
說明為什麼這裡反而要用 min-heap，以及複雜度為什麼是 O(n log k)。

      延伸題 3：合併 k 個已排序的串列

      k 條已經各自排好序的串列，要合併成一條。
把每條的開頭放進一個大小 k 的堆，每次取出最小的、補上它的下一個。
複雜度 O(N log k)，N 是總元素數。這就是外部排序／資料庫合併的核心。
