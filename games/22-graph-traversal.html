Game 22 · Graph Traversal

圖的走訪 DFS／BFS

第 21 關把校園地圖存成了一張圖。這一關要把整張圖「逛一遍」：從一個頂點出發，每個走得到的頂點都剛好拜訪一次。兩種逛法——DFS 一條路走到底再退回，BFS 一圈一圈往外擴——差別只在待辦清單用的是堆疊還是佇列。

先搞懂：圖的走訪（DFS／BFS）到底是什麼

沒學過程式也看得懂。先把名詞和定義弄清楚，後面的遊戲才不會霧煞煞。

定義：圖的走訪（Graph Traversal）

DEFINITION · 走訪 Traversal
從一個起點出發，沿著邊走，把所有走得到的頂點都拜訪剛好一次——不漏掉、也不重複。

「拜訪」就是輪到它的時候做事，例如把它的名字記下來。記下來的先後，就叫走訪順序。最常用的兩種走法是 DFS（深度優先）和 BFS（廣度優先）。

同一個定義，換個說法內容
白話拿著地圖把校園逛完：能走到的每棟樓都進去一次，進過的就不再進。
兩種走法DFS：一條路一直走到底，走不下去才退回上一個岔路口換路。BFS：先把離起點 1 步的都走完，再走 2 步的、3 步的……像水波一圈一圈往外擴。
需要的三樣東西① visited 標記：記住誰已經來過。② 待辦清單：DFS 用堆疊（或遞迴），BFS 用佇列。③ order：記下拜訪順序。
做完的結果一串走訪順序，加上一棵走訪樹（每個頂點是從誰那裡被發現的）。走不到的頂點不會出現——它們在另一座「島」上。
目的 很多問題的第一步都是「把圖逛一遍」：從 A 走得到 B 嗎？地圖分成幾座島？迷宮最少幾步走出去？比喻：新生第一週拿著校園地圖，想把每棟樓都去一次。沒有規則亂走，會在同一條環狀步道上一直繞；照 DFS 或 BFS 的規則走，保證每棟剛好去一次就收工。
先備 這一關用到：第 21 關「圖的基本概念」（頂點、邊、鄰居、鄰接串列）、第 18 關「佇列」（先進先出）、第 04 關「呼叫堆疊」（後進先出、遞迴）。第 07 關的迷宮其實就是一張圖——每一格是頂點、相鄰兩格之間有邊——那裡的 BFS／DFS，這一關搬到一般的圖上。

先認識這些詞（照順序讀，後面的詞會用到前面的）

頂點、邊、鄰居 vertex / edge / neighbor
第 21 關學過：頂點是地點，邊是連接兩個地點的路，有邊直接相連的兩個頂點互為鄰居。這一關的圖都是無向圖，路可以雙向走。
建築物、步道、隔壁棟。
鄰接串列 adjacency list
每個頂點一列，列出它所有的鄰居。本站規定鄰居一律照字母順序排，走訪順序才會唯一。
每棟樓門口貼一張「隔壁有哪幾棟」的告示。
走訪 traversal
從起點出發，把走得到的每個頂點都拜訪剛好一次。
把校園每棟樓都逛過一次。
起點 start / source
走訪開始的那個頂點。同一張圖換一個起點，順序就不一樣。這一關常用 D 系館當起點。
從哪棟樓開始逛。
visited 標記 visited
每個頂點一個「來過了沒」的記號，一開始全是「沒有」。發現它的當下就打勾，之後再碰到就跳過，不再處理第二次。
逛過的樓在地圖上打勾。
佇列 queue · FIFO
先進先出：從後面排進去，從前面出來。BFS 用它當待辦清單。（第 18 關）
餐廳排隊，先來的先點餐。
堆疊 stack · LIFO
後進先出：最後放上去的最先拿走。DFS 用它記住「走到一半、等一下要回來的地方」。（第 01、04 關）
疊盤子，最上面那個先拿。
遞迴 recursion
一個函式在做事的途中呼叫自己去處理一個小一點的問題。電腦會用呼叫堆疊記住每一層做到哪，做完一層就退回上一層接著做。
「逛 B」逛到一半，先去「逛 A」；逛完 A 再回來把 B 剩下的逛完。
DFS 深度優先 depth-first search
看到一個還沒去過的鄰居就馬上走過去，一路走到底；走不下去才退回上一個頂點，看它還有沒有別的鄰居。用遞迴（或自己準備的堆疊）寫。
走迷宮時右手扶牆，一條路走到死巷才回頭。
BFS 廣度優先 breadth-first search
先把起點的鄰居全部排進佇列，再一個一個拿出來、把它們的新鄰居排到後面。結果是離起點近的一定先被走到。
石頭丟進池塘，水波一圈一圈往外。
走訪順序 visit order
頂點被拜訪（記下來）的先後。同一張圖、同一個起點、同一個鄰居順序，結果才唯一。
逛樓的打卡紀錄。
距離（邊數） hops
從起點出發最少要經過幾條邊。BFS 會順便算出來：第 1 圈距離 1，第 2 圈距離 2……注意它只數幾條邊，不管權重。
「轉幾次車」，不是「花幾分鐘」。
走訪樹 / parent traversal tree
每個頂點（除了起點）記住它是從誰那裡被發現的，這叫 parent。把這些「發現用的邊」畫出來，剛好是一棵樹，遊戲裡畫成綠色粗線。
每個新生記下「是誰帶我認識這棟樓的」。
連通元件 connected component
彼此走得到的頂點圍成的一群。一張圖可能分成好幾群，群和群之間沒有任何路。從一個起點走訪，只會逛完自己這一群。
好幾座島，島和島之間沒有橋。
O(V+E) 時間複雜度
V 是頂點數、E 是邊數。O(V+E) 的意思是：每個頂點處理一次、每條邊從兩頭各看一次，工作量跟「頂點數＋邊數」成正比。
每棟樓進去一次，每條步道從兩頭各看一眼。

為什麼一定要 visited：樹不用，圖要

第 12 關走訪樹的時候，從來不用記「來過沒」：樹沒有環，從根一路往孩子走，永遠回不到走過的地方。圖不一樣——A、B、C 三個點互相連成一個環，沿著邊走會繞回原處：

關鍵 visited 要在發現的當下就打勾（BFS 放進佇列時、DFS 一進入頂點時），不要等到「拿出來處理」才打勾——否則同一個頂點會被不同鄰居重複排進待辦清單好幾次。第 07 關的迷宮也是這樣做的。

看圖走一次：從 D 出發，DFS 和 BFS 各走出什麼

鄰居照字母順序看。#k 是第幾個被拜訪，距 d 是離 D 幾條邊；綠色粗線是走訪樹（誰發現了誰）。

比較DFS 深度優先BFS 廣度優先
待辦清單堆疊（或遞迴的呼叫堆疊），後進先出佇列，先進先出
走的樣子一條路鑽到底，再退回換路一圈一圈往外擴
走訪樹的形狀又細又長（D→B→A→C→E→F 一條線）又矮又寬（D 底下直接掛 4 個）
順便得到「有沒有路」、哪裡有環每個頂點離起點最少幾條邊

這是「從 D 出發」的 BFS 順序嗎？

判斷規則只有一條：BFS 一定先走完距離 1 的全部，才輪到距離 2（同一圈裡誰先誰後，要看鄰居排的順序）。先自己判斷，再看說明：

連通元件：一張圖有幾座島？

在校園旁邊再加上 G 碼頭–H 海洋館（兩棟之間有路），和孤零零的 I 燈塔。從 D 出發不管用 DFS 或 BFS，都只會逛完 A～F，G、H、I 走不到：

數島的方法：從 A 開始把每個頂點看一遍，遇到還沒打勾的，就代表發現了一座新島——島數加 1，從它做一次走訪，把整座島打勾。之後再遇到這座島的頂點都已打勾，直接跳過。A 開出第 1 座、G 開出第 2 座、I 開出第 3 座，答案是 3。

容易搞混的幾件事

常被搞混的東西跟這一關一樣嗎？差在哪
第 12 關「樹的走訪」（前序、中序、後序）親戚樹的前序走訪就是從根做 DFS。樹沒有環，所以不用 visited；圖有環，一定要。
第 07 關的迷宮 BFS／DFS一樣迷宮的每一格是頂點、上下左右相鄰是邊。這一關把「上下左右」換成鄰接串列，演算法一模一樣。
BFS 的「距離」＝ 最短路徑？只對一半BFS 算的是最少幾條邊。路有長短（權重）時，邊最少不等於分鐘最少，要用第 17 關 Dijkstra。
「DFS 的順序只有一種」不對鄰居的排列順序不同，DFS 和 BFS 的結果都會不同，而且都算對。規定鄰居照字母排，答案才唯一。
「走訪會走過所有頂點」不一定只走得到同一個連通元件裡的。要全部走完，得對每個沒打勾的頂點再走一次。

自我檢查（先自己想，再點開看答案）

從 F 出發做 BFS（鄰居照字母順序），順序是什麼？每個頂點離 F 幾條邊？
F, D, E, B, C, A。F 的鄰居 D、E（距離 1）；D 帶出 B、C（距離 2）；E 的鄰居 C、D、F 都已打勾；B 帶出 A（距離 3）。
從 F 出發做 DFS（遞迴、鄰居照字母順序），順序是什麼？
F, D, B, A, C, E。F→D（F 的第一個鄰居）→B（D 的第一個鄰居）→A→C（A 的鄰居 B 已走過，下一個 C）→E（C 的鄰居 A、B、D 都走過）。遊戲第 3 關就是這一題。
從 A 出發，BFS 和 DFS 的順序都是 A, B, C, D, E, F。所以兩個演算法在這裡一樣？
順序剛好一樣，走法不一樣。BFS 的走訪樹是 A 掛 B、C，B 掛 D，C 掛 E，D 掛 F（距離 0,1,1,2,2,3）；DFS 的走訪樹是 A→B→C→D→E→F 一整條線。所以這一關改用 D、F 當起點，差別才看得出來。
如果 BFS 改成「拿出來的時候才打勾」，從 D 出發會發生什麼？
D 拿出來時，B、C、E、F 都還沒打勾，全部排進佇列；B 拿出來時，C 還沒打勾（還在排隊），C 會被排第二次……最後順序還是對的（第二次拿出來時發現打過勾就跳過），但佇列塞了一堆重複的東西。正確作法是放進去的當下就打勾。

你會學到什麼

  • BFS ＝ 佇列 —— 一圈一圈往外，順便算出每個頂點離起點最少幾條邊。
  • DFS ＝ 遞迴（呼叫堆疊） —— 一條路走到底，走不下去就退回上一層。
  • visited 為什麼不能少 —— 圖有環，沒有它會繞圈繞到天荒地老（第 5 關親眼看）。
  • 走訪樹 —— 每個頂點記住 parent，「發現用的邊」剛好組成一棵樹。
  • 連通元件 —— 對每個沒打勾的頂點開一次走訪，開了幾次就有幾座島。
  • O(V+E) —— 每個頂點進出一次、每條邊兩頭各看一次。

      這個遊戲跑的程式（完整版）

      把視覺化全部拿掉，就是下面這些。頂點用編號 0～5 代表 A～F，鄰接串列每一列都照字母順序排好。DFS 用的是遞迴版本（遊戲裡的「呼叫堆疊」就是電腦替遞迴準備的那個堆疊）：

      #include <iostream>
#include <vector>
#include <queue>
using namespace std;

vector<bool> visited;                // visited[x]：x 被發現（打勾）了沒
vector<int> order, dist, parent;     // 走訪順序、BFS 距離（幾條邊）、從誰發現的

void bfs(const vector<vector<int>>& adj, int s) {
    queue<int> q;
    visited[s] = true; dist[s] = 0; q.push(s);
    while (!q.empty()) {
        int u = q.front(); q.pop();
        order.push_back(u);
        for (int v : adj[u]) {
            if (visited[v]) continue;
            visited[v] = true; dist[v] = dist[u] + 1; parent[v] = u;
            q.push(v);
        }
    }
}

void dfs(const vector<vector<int>>& adj, int u) {
    visited[u] = true; order.push_back(u);
    for (int v : adj[u]) {
        if (visited[v]) continue;
        parent[v] = u;
        dfs(adj, v);
    }
}

int countComponents(const vector<vector<int>>& adj, bool useBFS) {
    int comp = 0;
    for (int s = 0; s < (int)adj.size(); s++) {
        if (visited[s]) continue;
        comp++;
        if (useBFS) bfs(adj, s); else dfs(adj, s);
    }
    return comp;
}

void reset(int n) {                     // 每次重新走訪前，全部清空
    visited.assign(n, false); order.clear();
    dist.assign(n, -1); parent.assign(n, -1);
}

int main() {
    // 0=A 校門 1=B 圖書館 2=C 餐廳 3=D 系館 4=E 宿舍 5=F 體育館
    vector<vector<int>> adj = {
        {1, 2},          // A: B C
        {0, 2, 3},       // B: A C D
        {0, 1, 3, 4},    // C: A B D E
        {1, 2, 4, 5},    // D: B C E F
        {2, 3, 5},       // E: C D F
        {3, 4}           // F: D E
    };
    const char* name = "ABCDEFGHI";

    reset(6); bfs(adj, 3);                          // 從 D 出發
    for (int x : order) cout << name[x] << ' ';     // D B C E F A
    cout << '\n';

    reset(6); dfs(adj, 3);
    for (int x : order) cout << name[x] << ' ';     // D B A C E F
    cout << '\n';

    adj.push_back({7});                             // 6=G 碼頭：鄰居 H
    adj.push_back({6});                             // 7=H 海洋館：鄰居 G
    adj.push_back({});                              // 8=I 燈塔：沒有鄰居
    reset(9);
    cout << countComponents(adj, true) << '\n';     // 3
}

      03

      這個功能是怎麼做到的

      一個待辦清單、一份 visited 標記，換掉清單的種類就從 BFS 變 DFS。

      問題定義

      給一張無向圖（V 個頂點、E 條邊，用鄰接串列存）和一個起點 s，列出所有從 s 走得到的頂點，每個剛好一次。延伸問題：整張圖有幾個連通元件？每個頂點離 s 最少幾條邊？

      破除錯誤直覺

      直覺 1：「沿著邊一直走，總會走完吧？」

      圖有環的話不會。從 K 出發、沒有 visited 的 BFS：K 把 L、N 排進去，L 又把 K 排回來，K 再把 L、N 排回來……佇列只會越來越長（遊戲第 5 關前半段實際跑給你看：拿出 6 個之後佇列已經有 7 個在排）。visited 是「一定會結束」的保證：每個頂點只會被打勾一次、只會進待辦清單一次。

      直覺 2：「DFS 或 BFS 的答案是固定的」

      不是。演算法只規定「先處理誰的鄰居」，沒規定同一個頂點的鄰居先看哪個。從 D 出發，D, B, C, E, F, A 和 D, C, B, E, F, A 都是正確的 BFS 順序。考試和本站都規定「鄰居照字母（或編號）由小到大」，答案才唯一。

      直覺 3：「用堆疊把鄰居照字母順序推進去，就是照字母順序的 DFS」

      堆疊後進先出：照 B, C, E, F 推進去，最先拿出來的是 F。從 D 出發會得到 D, F, E, C, B, A——這也是一個合法的 DFS，但不是遞迴版的 D, B, A, C, E, F。想要一樣，就要反過來推（見下面的演算法 3）。

      關鍵觀察

      • 兩種走法是同一個模板 —— 「從待辦清單拿一個 → 看它的鄰居 → 沒打勾的打勾、放進清單」。清單是佇列就是 BFS，是堆疊就是 DFS。第 07 關說過：差別只在「拿出來」那一行。
      • BFS 一圈一圈 —— 佇列裡永遠是「距離 d 的在前、距離 d+1 的在後」，最多只有兩種距離。所以第一次發現某個頂點時，用的一定是最少的邊數。
      • DFS 一路到底 —— 呼叫堆疊從底到頂，剛好是「從起點走到現在這裡的那條路」。退回，就是把最上面那層拿掉。
      • 發現就打勾 —— 每個頂點只會被打勾一次，所以每個頂點只會進待辦清單一次。這是 O(V+E) 的關鍵。

      演算法 1：BFS（佇列）

      1. 起點打勾、距離 0、放進佇列。
      2. 佇列不是空的就重複：從前面拿出 u，把 u 記進順序。
      3. 照順序看 u 的每個鄰居 v：打過勾就跳過；沒打過勾 → 打勾、距離 = u 的距離 + 1、parent = u、排到佇列後面。

      演算法 2：DFS（遞迴）

      1. dfs(u)：u 打勾，記進順序。
      2. 照順序看 u 的每個鄰居 v：打過勾就跳過；沒打過勾 → 記下 parent[v] = u，立刻呼叫 dfs(v)。
      3. dfs(v) 整個做完回來，才接著看 u 的下一個鄰居。鄰居全部看完，dfs(u) 結束，退回呼叫它的那一層。

      演算法 3：DFS（自己準備堆疊，不用遞迴）

      遞迴太深（例如 100 萬個頂點排成一條線）可能把電腦的呼叫堆疊撐爆，這時改用自己的 stack。要得到跟遞迴一樣的順序，有兩個細節：拿出來時才打勾（同一個頂點可能被推進去好幾次，拿出來發現打過勾就丟掉），以及鄰居反過來推。

      void dfsIter(const vector<vector<int>>& adj, int s) {
    stack<int> st;
    st.push(s);
    while (!st.empty()) {
        int u = st.top(); st.pop();
        if (visited[u]) continue;                  // 推過好幾次的，第二次起直接丟掉
        visited[u] = true; order.push_back(u);
        for (int k = (int)adj[u].size() - 1; k >= 0; k--)   // 反過來推：字母小的最後推、最先拿
            if (!visited[adj[u][k]]) st.push(adj[u][k]);
    }
}

      從 D 出發，它也得到 D, B, A, C, E, F。不管哪張圖、從哪個起點出發，這個版本走出來的順序都跟遞迴版一模一樣（遊戲用的是遞迴版）。

      呼叫堆疊左邊是最底層（最早呼叫的），右邊是正在做的那一層：

      步呼叫堆疊發生什麼順序
      1[D]dfs(D)：D 打勾。第一個鄰居 B 沒打勾 → 呼叫 dfs(B)D
      2[D, B]dfs(B)：第一個鄰居 A 沒打勾 → dfs(A)D B
      3[D, B, A]dfs(A)：B 打過；C 沒打勾 → dfs(C)D B A
      4[D, B, A, C]dfs(C)：A、B、D 打過；E 沒打勾 → dfs(E)D B A C
      5[D, B, A, C, E]dfs(E)：C、D 打過；F 沒打勾 → dfs(F)D B A C E
      6[D, B, A, C, E, F]dfs(F)：D、E 都打過 → 結束，退回 ED B A C E F
      7[D, B, A, C, E] → … → [ ]E 的鄰居看完 → 退回 C → 看完 → 退回 A → 看完 → 退回 B：C、D 打過 → 退回 D：C、E、F 打過 → 全部結束D B A C E F

      走訪樹：D–B、B–A、A–C、C–E、E–F，一整條線。最深的時候堆疊有 6 層。

      複雜度：O(V+E)，但前提是鄰接串列

      • 每個頂點 O(1) 次 —— 打勾一次、進出待辦清單一次，合計 O(V)。
      • 每條邊 2 次 —— 無向邊 u–v 會在看 u 的鄰居時看一次、看 v 的鄰居時再看一次。所有鄰居串列加起來長度是 2E（第 21 關：度數總和 = 2 × 邊數），合計 O(E)。
      • 鄰接矩陣會變成 O(V²) —— 用矩陣存時，要找 u 的鄰居得把那一整列 V 格看完，不管實際只有幾個鄰居。V 個頂點各看一列，就是 V × V。
      • 額外空間 O(V) —— visited、dist、parent 各 V 格；佇列或堆疊最多 V 個。
      圖的大小鄰接串列 O(V+E)鄰接矩陣 O(V²)

      城市路網：V = 100 萬、E = 300 萬約 700 萬次1 兆格（1012）

      常見誤解

      • 「visited 等拿出來處理時再打勾也一樣」 —— BFS 這樣寫，同一個頂點會被重複排進佇列；順序也許還對，但佇列變大、白做很多事。放進去的當下就打勾。（只有演算法 3 那種堆疊版 DFS，為了順序跟遞迴一樣，才刻意在拿出來時打勾。）
      • 「BFS 找到的就是最短路徑」 —— 只有每條邊都一樣長（只數邊數）時才對。校園步道有 1 分鐘也有 10 分鐘的，要用第 17 關 Dijkstra。例如從 D 到 C：BFS 說 1 條邊（D–C 直走，8 分鐘），但 D→B→C 雖然 2 條邊，只要 5 + 1 = 6 分鐘。
      • 「BFS 比 DFS 快」 —— 兩個都是 O(V+E)。差別在順序和用途，不在速度。
      • 「從一個起點走訪就會走完整張圖」 —— 只會走完起點所在的連通元件。
      • 「DFS 一定要用遞迴」 —— 不用，演算法 3 就是用自己的堆疊。遞迴只是借用電腦的呼叫堆疊（第 04 關）。
      下一關 會走訪了，接下來處理有方向的圖：選課有先修、做事有先後，怎麼排出一個不違反任何先後關係的順序？→ 第 23 關「拓撲排序」（會用到入度和佇列，跟這一關的 BFS 很像）。
