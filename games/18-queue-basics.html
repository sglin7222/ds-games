佇列排隊入門

早餐店排隊：新來的人排到最後面，櫃台永遠先服務排最前面的人。佇列（queue）就只有這一條規則。這一關只練五個最基本的動作——push、front、pop、size、empty。往後每一關用到佇列，都是這五個動作的組合。

你會學到什麼

  • 佇列＝排隊（FIFO） —— 先進先出（First In First Out）：先來的人先被服務。整個佇列就這一條規則。
  • 兩個端點各管一件事 —— 隊尾只能進、隊頭只能出。不能插隊，也不能從中間離開。
  • 五個基本動作 —— push（進場）、front（看隊頭）、pop（離場）、size（幾個人）、empty（空了嗎）。全部學會就畢業了。
  • front 只看、pop 只走 —— C++ 的 pop() 不會告訴你走的是誰。想知道，要先 front() 再 pop()。
  • 空佇列不能 front／pop —— 沒有人可以看、也沒有人可以走。動手之前先問 empty()。
  • 跟堆疊剛好相反 —— 同樣放進 1、2、3：佇列拿出來是 1、2、3，堆疊拿出來是 3、2、1。
  • 複雜度 O(1) —— 五個動作都是「固定幾下」就做完，跟隊伍多長無關。
建議順序 先用演示模式玩「暖身」和「front 只是看」；再玩「陷阱：空佇列」看空的時候會怎樣；然後切自由練習自己亂按一輪；最後用闖關模式挑戰「魔王」。

      一支完整的小程式：把五個動作串起來

      上面的面板是「動作對照表」。真的寫成一支會印出結果的程式，長這樣——可以整段貼到編譯器裡跑：

      #include <iostream>
#include <queue>
using namespace std;

int main() {
    queue<int> q;                 // 一條空的隊伍

    q.push(1);                    // 1 號來排隊
    q.push(2);
    q.push(3);                    // 隊伍：1 2 3（1 在最前面）

    cout << q.front() << "\n";    // 印出 1：只是看，1 號還在隊伍裡
    cout << q.size()  << "\n";    // 印出 3

    q.pop();                      // 1 號離場，隊伍：2 3
    cout << q.front() << "\n";    // 印出 2：隊頭換人了

    while (!q.empty()) {          // 只要還有人，就繼續叫號
        cout << q.front() << " "; // 先看是誰
        q.pop();                  // 再請他離開
    }                             // 印出 2 3
    return 0;
}

      最後那個 while (!q.empty()) 迴圈——「只要還有人，就看隊頭、請他走」——是佇列最常見的用法。後面的迷宮 BFS、油漆桶填充，骨架全是這三行。

      03

      這個功能是怎麼做到的

      從「排隊」這件每天都在做的事，走到五個動作各自的規則與陷阱。

      問題定義

      佇列（queue）是一種放資料的容器，規則只有一條：先放進去的，先拿出來。這叫先進先出（FIFO，First In First Out），跟排隊一模一樣。它只提供五個動作：

      C++ 寫法做什麼排隊的說法會改變隊伍嗎
      q.push(x)把 x 放到隊尾新顧客排到最後面會（多一個人）
      q.front()回傳隊頭的值看一眼排最前面的是誰不會
      q.pop()移除隊頭排最前面的人離場會（少一個人）
      q.size()回傳元素個數數一數現在排了幾個人不會
      q.empty()回傳是否為空問：隊伍是空的嗎？不會

      其實還有第六個 q.back()（看隊尾是誰），用法跟 front() 一樣、但很少用到。記住上面五個就夠了。

      先破除一個直覺：「限制這麼多，不如用陣列自己管」不行

      佇列看起來很「殘廢」：只能從尾巴放、只能從頭拿，連中間有誰都不給看。直接用陣列、想動哪格動哪格不是更自由嗎？問題就出在「自由」：

      • 可以插隊，順序就不保證了 —— 只要有一行程式把新資料塞到前面，「先來的先處理」這個承諾就破功。印表機如果讓後送的文件插隊，你的報告可能永遠印不出來。
      • 可以從中間拿，就得自己記「下一個輪到誰」 —— 多一個要維護的變數，就多一個寫錯的地方。佇列把這件事包起來：下一個永遠是 front()，不用想。
      關鍵 限制就是保證。佇列只開放兩個端點，所以任何人拿到一個佇列，都能確定「拿出來的順序＝放進去的順序」——不必檢查別人有沒有偷插隊。

      關鍵觀察：進場順序＝離場順序

      把 1、2、3 依序放進去，再全部拿出來。佇列和堆疊（疊盤子，只能從最上面拿）的結果剛好相反：

      容器放進去的順序拿出來的順序規則生活比喻
      佇列 queue1 2 31 2 3先進先出 FIFO排隊買早餐
      堆疊 stack1 2 33 2 1後進先出 LIFO疊盤子

      遊戲畫面下方的「離場順序」那一列，就是用來讓你親眼確認這件事的：不管中間怎麼穿插進場、離場，那一列的號碼永遠是由小到大。

      所以 需要「公平、照順序」的地方就用佇列：印表機的列印工作、客服的來電等候、鍵盤打字的緩衝區、聊天訊息的傳送順序。

      五個動作，各自的規則

      1. push(x)（進場） —— x 排到隊尾。隊頭是誰不受影響（除非原本是空的，那 x 自己就是隊頭）。
      2. front()（看隊頭） —— 告訴你排最前面的是誰。只看不動：連續呼叫十次，答案都一樣，隊伍也不會少人。
      3. pop()（離場） —— 隊頭離開，後面的人遞補。走的永遠是目前最早來的那位。
      4. size()（幾個人） —— 回傳現在的人數。
      5. empty()（空了嗎） —— 沒有人就回傳 true（真），有人就回傳 false（假）。
      最常漏 C++ 的 pop() 不回傳任何東西。int x = q.pop(); 是編譯錯誤。「拿走隊頭並且知道他是誰」要寫成兩行：先 int x = q.front(); 再 q.pop();。

      邊界情況：空的佇列

      隊伍裡沒有人的時候，front() 沒有人可以看、pop() 沒有人可以走。C++ 在這裡不會好心提醒你——它不檢查，直接去讀一塊不存在的資料。結果可能是印出亂七八糟的數字，也可能整支程式當掉。這種「規則沒說會發生什麼事」的情況叫未定義行為，是最難抓的一種錯。

      所以規矩是：動手之前先問 empty()。

      if (!q.empty()) {          // 「!」是「不」：如果隊伍「不是空的」
    int who = q.front();   // 才可以看
    q.pop();               // 才可以請人走
}
      遊戲裡 玩「陷阱：空佇列」那一關：對空隊伍做 pop 和 front 時，程式面板亮的是 if (!q.empty()) 那一行——檢查把危險的動作擋下來了，什麼事都沒發生。

      手算一次

      考試要在紙上追蹤佇列時，就是畫這張表。先蓋住右邊三欄自己算，再對答案。

      步動作回傳隊伍（隊頭 → 隊尾）size
      0queue<int> q;—（空）0
      1q.push(1)—11
      2q.push(2)—1 22
      3q.push(3)—1 2 33
      4q.front()11 2 33

      注意第 4 步和第 6 步：front() 那兩列，隊伍和 size 都沒有變。會讓隊伍變動的只有 push 和 pop。

      複雜度

      • 五個動作都是 O(1) —— O(1) 的意思是「不管隊伍裡有 3 個人還是 300 萬個人，做一次都是固定幾個步驟」。push 只碰隊尾、front 和 pop 只碰隊頭，從來不需要把整條隊伍走一遍。
      • 空間 O(n) —— 隊伍裡有 n 個人，就占 n 份記憶體。std::queue 會自己長大，不必事先說要幾格。

      常見誤解

      • 「front() 會把人拿走」 —— 不會，它只是看。玩「front 只是看」那一關：連續 front 三次，隊伍一個人都沒少。
      • 「pop() 會告訴我走的是誰」 —— C++ 的 pop() 不回傳值。要先 front() 抄下來，再 pop()。（別的語言不一定，例如 Python 的 popleft() 會回傳——換語言時要重新確認。）
      • 「push 是放到最前面」 —— 佇列的 push 是排到隊尾。容易跟堆疊搞混：堆疊的 push 是放到「頂端」，而且下一個拿的就是它；佇列新來的人要等前面全部走完才輪得到。
      • 「可以用 q[1] 看第二個人」 —— 不行，std::queue 沒有 [ ]。它故意只給你看隊頭和隊尾。真的需要看中間，代表你要的不是佇列。
      • 「對空佇列 pop，頂多沒事發生」 —— 是未定義行為，可能當場當掉、也可能默默把資料弄壞。永遠先檢查 empty()。

      學會了，然後呢

      這五個動作是後面好幾關的共同基礎：

      • 06 約瑟夫問題 —— 「把隊頭的人移到隊尾」＝ front、pop、push 連做。圍成一圈報數，其實就是一條一直轉的佇列。
      • 07 迷宮 BFS —— 用本頁那個 while (!q.empty()) 迴圈走迷宮，佇列保證「近的格子先處理」，所以找到的一定是最短路。
      • 09 環形佇列 —— 打開 std::queue 的蓋子，自己用陣列把佇列做出來。

      程式架構與說明

      只講流程與分工，不逐行拆解。看懂這一段，你就能自己改這個遊戲。

      整體設計：先算完，再播放

      一段操作劇本就是一個字串，每個字元是一個動作。使用者按「下一步」之前，整段劇本就已經全部算好了。

      操作劇本 "+++f-f--"（+ 進場、- 離場、f 看隊頭、s 人數、e 空嗎）
      buildSteps(ops) 把整段劇本跑完一次
      steps[] 每一格是「當下整條隊伍 + 已離場名單」的完整快照
      畫面只負責把 steps[目前步數] 畫出來

      為什麼這樣設計

      • 前進後退變成加減一 —— 不必寫「反向 pop」這種容易錯的東西，倒帶就是把步數減一。
      • 自由練習不用另外寫一套 —— 每按一個按鈕，就是在劇本字串尾巴加一個字元，然後整段重算、跳到最後一步。「上一步」之後再按新動作，就把後面的劇本剪掉重接。
      • 演算法和畫面完全分離 —— buildSteps 裡沒有半行畫面程式碼。
      代價 每一步都存一份整條隊伍的快照，而且自由練習每按一次就整段重算。教學規模（幾十步）完全沒問題，真實工程不會這樣寫——真實版本只需要當下狀態。

      核心資料：一個 step 長什麼樣

      整個程式就靠這個物件串起來。每個欄位都是為了餵給某一塊畫面：

      {
  kind:  // start / push / front / pop / size / isempty / err / done → 顏色、徽章、log 標籤
  what:  // kind 是 err 時：被擋下來的是 "front" 還是 "pop"
  val:   // 這一步進場、離場或被看到的顧客號碼
  hit:   // 要特別標示隊伍裡的第幾個人（沒有就是 -1）
  q:     // 動作「後」整條隊伍的快照，q[0] 是隊頭 → 走道直接畫這個
  out:   // 到目前為止的離場順序 → 「離場順序」那一列
  ret:   // 這個動作回傳了什麼（給側欄顯示的文字）
  line:  // 程式面板要高亮第幾行
  title, msg: // 說明面板的標題與內文
}

      遊戲裡的佇列就是一個 JavaScript 陣列：push 用 q.push(v)、離場用 q.shift()。shift() 其實會把後面每個元素往前搬一格（O(n)），所以這只是教學用的替身——真正 O(1) 的做法在 09 環形佇列那一關。
