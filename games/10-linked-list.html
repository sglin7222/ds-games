怎麼玩

畫面上是一列火車：每個方塊是一節節點（車廂），左格放數字、右格是 next 指標（車鉤），箭頭鉤向下一節；head 是記著「第一節在哪」的指標樁，∅（nullptr）代表「後面沒有了」。演到一半的 cur、prev、new 指標會用彩色標籤掛在車廂上方。

演示模式

  1. 從上方挑一個關卡：開頭插入、中間插入、刪除、搜尋⋯⋯
  2. 按 下一步 一格一格走，看指標一根一根改。
  3. 第 3 關是反例：故意把兩行順序接反，親眼看斷鏈。
  4. 隨時 上一步 倒回去，反覆看不懂的地方。

闖關模式

  1. 每個關鍵步驟先不給答案，由你選：下一步該改哪根指標？
  2. 答對得分，連續答對額外加分；答錯立刻解釋為什麼。
  3. 一關結束會結算正確率，可以直接跳下一關。
操作 鍵盤 → 下一步、← 上一步、空白鍵 播放／暫停。

你會學到什麼

  • 節點＝值＋指標 —— 一節車廂裝兩樣東西：貨物（val）和下一節的地址條（next）。串列的一切操作都只是在改地址條。
  • 先接後斷的鐵律 —— 插入時新節點的 next 要先指向下一個，才能改前一個的 next。順序反了，後半段串列沒人記得，當場變垃圾（memory leak）。
  • 刪除前要先記住 —— 改指標之前先用 cur 抄下要刪節點的地址，否則永遠還不了那塊記憶體。
  • 串列 vs 陣列的交換條件 —— 陣列中間插入要整段往後搬 O(n)；串列只改兩根指標 O(1)，但找位置要 O(n) 一節一節走。
  • nullptr 是安全網 —— 走訪的迴圈條件 c != nullptr 少寫一個，程式就在串列尾端當掉。
  • 複雜度 —— 搜尋 O(n)；已知前一節點時插入／刪除 O(1)。
建議順序 先玩第 1、2 關把「先接後斷」走順，再玩第 3 關反例：接反了——那一關的斷鏈畫面，是這一頁最值得記住的東西。

      這個遊戲跑的程式（完整版）

      把教學用的視覺化全部拿掉，鏈結串列的本體就是這樣——一個 struct 加四個小函式：

      #include <iostream>
using namespace std;

struct Node { int val; Node* next; };      // 車廂：貨物 + 車鉤

Node* pushFront(Node* head, int x) {       // 開頭插入，回傳新的 head
    Node* nu = new Node{x, nullptr};
    nu->next = head;                        // 先接：鉤住原本的第一節
    return nu;                              // 新車廂就是新的頭
}
Node* insertAfter(Node* p, int x) {        // 在 p 後面插入 x
    Node* nu = new Node{x, nullptr};
    nu->next = p->next;                     // 先接右邊
    p->next  = nu;                          // 後改左邊 —— 順序不能反！
    return nu;
}
void removeAfter(Node* p) {                // 刪掉 p 的下一節
    Node* cur = p->next;                    // 先記住，等下才刪得到
    p->next = cur->next;                    // 跳過它
    delete cur;                             // 歸還記憶體，忘了就漏
}
Node* find(Node* head, int x) {            // 搜尋：只能一節一節走
    for (Node* c = head; c != nullptr; c = c->next)
        if (c->val == x) return c;
    return nullptr;                         // 走完了，查無此人
}

int main() {
    Node* head = new Node{20, nullptr};    // 20
    head = pushFront(head, 10);            // 10 → 20
    insertAfter(head, 15);                 // 10 → 15 → 20
    removeAfter(head);                     // 10 → 20
    Node* hit = find(head, 20);            // 拿到 20 那節的地址
}

      三十行不到。遊戲頁面多出來的幾百行，全部都是為了「讓指標的動作看得見」——這是教學程式和生產程式的差別。

      03

      這個功能是怎麼做到的

      從「什麼是鏈結串列」走到「為什麼先接後斷是鐵律」，每一步為什麼非要不可。

      問題定義：什麼是鏈結串列

      陣列是一排連續的格子，第 i 格在哪裡用算的就知道。鏈結串列反過來：節點散落在記憶體各處，每個節點除了值，還帶一根 next 指標——一張寫著「下一節在哪」的地址條。整條串列唯一的入口是 head。想像一列火車：車廂（節點）不必停在一起，只要車鉤（指標）一節鉤一節，列車就是完整的。

      兩種結構是一組交換條件，沒有誰全面比較好：

      操作陣列鏈結串列白話
      讀第 i 個元素O(1)O(n)陣列用算的；串列只能一節一節走過去
      在開頭插入O(n)O(1)陣列要整排往後搬；串列改兩根指標
      在已知節點後插入O(n)O(1)陣列要搬移後半段；串列改兩根指標
      刪除已知節點的下一節O(n)O(1)陣列要整段往前補；串列改一根指標
      搜尋某個值O(n)O(n)都要一個一個看（陣列排序後可二分，串列不行）
      記憶體連續一整塊散落，每節多付一根指標串列用空間換「不搬移」的自由

      先破除一個直覺：「兩行順序無所謂吧」

      插入要改兩根指標：新節點的 next、前一節的 next。很多人覺得「反正兩行都要做，先做哪行不都一樣」。在紙上看起來一樣，在記憶體裡是生與死的差別。

      • 指標是唯一的線索 —— 單向串列裡，後半段串列只有前一節的 next 記得。你沒有在任何別的地方抄過它的地址。
      • 先改前一節的 next ＝ 放手 —— 那一瞬間，後半段就沒有任何指標指著它了。不是「等下再接回來」，是再也找不到了——你連它的地址都不知道。
      • 編譯器不會救你 —— 兩種順序在語法上都完全合法。程式不會當掉、不會報錯，只是安靜地把記憶體漏掉（memory leak）。
      關鍵 改任何一根指標之前先問：「它現在指著的東西，還有沒有別根指標記得？」沒有，就不准改。這一句話就是整頁的核心。

      關鍵觀察：先讓新節點「有兩隻手」

      先做 newNode->next = cur->next 之後，右半段串列同時被兩根指標記著（舊的 cur->next、新的 newNode->next）。這時再改 cur->next，右半段仍然被新節點牽著——列車從頭到尾沒有斷過一秒。刪除同理：先用 cur 抄下要刪節點的地址，再改指標，最後才 delete。

      所以 「先接、後斷」不是背口訣，是「任何時刻每段串列至少要有一根指標記得」這條原則推出來的必然結果。

      演算法

      在節點 p 後面插入 x（已經走到 p 的情況下）：

      1. new Node —— 向記憶體要一節新車廂，裝上 x，next 先設 nullptr。
      2. 先接 —— nu->next = p->next：新車廂鉤住 p 原本的下一節。
      3. 後斷（改接） —— p->next = nu：p 的車鉤改鉤新車廂。完成。

      刪除 p 的下一節：

      1. 先記住 —— cur = p->next：抄下要刪節點的地址。
      2. 跳過 —— p->next = cur->next：列車繞過它。
      3. 歸還 —— delete cur：把記憶體還給系統。
      最常漏 刪除的第 3 步 delete 是初學者最常忘的一行。C++ 不會自動回收——指標改完列車是通了，但那節車廂會永遠漂在記憶體裡。

      手算一次：在 10 → 20 → 30 的 20 後面插入 25

      考試要你在紙上追蹤時，就是畫這張表。先看正確順序：

      步動作20 的 next25 的 next從 head 看到的列車
      0初始→30（還沒出生）10→20→30
      1new Node(25)→30∅10→20→30（25 漂在旁邊）
      225->next = 20->next→30→3010→20→30（30 被兩根指標記著）
      320->next = 25→25→3010→20→25→30 ✓

      再看接反的順序——就是遊戲第 3 關演的災難：

      步動作20 的 next25 的 next發生什麼事
      1'20->next = 25（先斷！）→25∅30 從此沒人記得 —— 斷鏈、漏記憶體
      2'25->next = 20->next→25→2520->next 已是 25，等於 25 自己鉤自己 → 無限迴圈

      一模一樣的兩行程式，只是對調順序：一邊是完美插入，一邊是斷鏈＋自鉤迴圈。這張對照表值得多看一分鐘。

      複雜度

      • 插入／刪除 O(1) —— 已知前一節點時，只改固定幾根指標，跟串列多長無關。這是串列的看家本領。
      • 搜尋／走到第 i 個 O(n) —— 節點散落各處，沒有「跳到中間」這種事，只能沿車鉤一節一節走。連二分搜尋都救不了它——二分需要隨機存取。
      • 空間 O(n) —— n 個節點，每節多付一根指標的空間；此外節點分散，對 CPU 快取不友善，實務上常比理論值更慢。

      常見誤解

      • 「串列比陣列快」 —— 不一定。只有「頻繁在中間插入刪除、又已經站在正確位置」時才佔便宜；搜尋、遍歷、隨機讀取都是陣列贏。
      • 「cur++ 可以走到下一個節點」 —— 錯。那是陣列的直覺。節點地址不連續，走訪只能 cur = cur->next。
      • 「改完指標，節點就消失了」 —— 錯。節點只是「沒人指著」，記憶體還被佔著。C++ 要自己 delete；忘了就是 memory leak。
      • 「delete 之後那個指標還能用」 —— 錯。delete 後指標變成懸空指標（dangling pointer），再讀它是 use-after-free，典型當機來源。
      • 「先斷再接，等下接回來就好」 —— 錯。單向串列放手就是永別，第 3 關親眼看過就懂。

      整體設計：先算完，再播放

      關卡腳本 insertAfter(20, 25)
      buildSteps(level) 模擬記憶體，跑完整段操作
      steps[] 每一格是節點＋指標的完整快照
      畫面只負責把 steps[目前步數] 畫出來
      • 前進後退變成加減一 —— 不必寫「反向插入」「反向刪除」這種必錯的邏輯。

      自己動手：給 AI 的 Prompt

      把下面這段丟給任何 AI（或自己寫），做出來你就真的會鏈結串列了：

      用 C++ 從零實作單向鏈結串列，只准用 struct Node { int val; Node* next; };
不准用 std::list、std::vector 或陣列存節點。

實作以下函式，每個函式前先用註解寫清楚「會改到哪幾根指標、順序為什麼」：
1. pushFront(head, x)     // 開頭插入，回傳新 head
2. insertAfter(p, x)      // 先接後斷；並回答：兩行對調會發生什麼？
3. removeAfter(p)         // 先記住、再跳過、最後 delete
4. removeFront(head)      // 回傳新 head；注意 delete 與移動 head 的順序
5. find(head, x)          // 找不到回傳 nullptr
6. printList(head)        // 印成 10 -> 20 -> 30 -> NULL
7. freeAll(head)          // 整條歸還，一節都不能漏

要求：
- main() 依序演示：建 3 節 → 頭插 → 中插 → 刪中 → 刪頭 → 搜尋，
  每一步之後都 printList
- 用 -fsanitize=address（或 valgrind）編譯執行，證明沒有 memory leak
- 最後回答兩題：
  a. insertAfter 的兩行指標如果對調，會漏掉哪些節點？為什麼編譯器不報錯？
  b. freeAll 為什麼要先記住 next 才能 delete？寫錯會怎樣？

      延伸挑戰一：反轉串列

      寫 reverse(head)：把 10 -> 20 -> 30 反轉成 30 -> 20 -> 10。
限制：不准 new 任何新節點，只准改 next 指標，O(n) 時間、O(1) 空間。

提示：需要三根指標 prev / cur / nxt 一起往前爬。
每一圈先用 nxt 記住 cur->next（先記住！），再把 cur->next 扳向 prev。
畫出每一圈三根指標的位置——這題是面試最愛，畫得出來就寫得出來。

      延伸挑戰二：雙向串列

      把 Node 加上 Node* prev，做成雙向鏈結串列。
重寫 insertAfter 和 remove：現在每次要改四根指標，
一樣先想清楚「改的順序」——哪幾步之間誰可能沒人記得？

回答：多付一根指標的空間，換到了什麼能力？
（提示：刪除自己、往回走、O(1) 刪尾）

      延伸挑戰三：用串列重做約瑟夫環

      玩過第 6 關約瑟夫環的話：把最後一節的 next 接回第一節，串列就成了「環」。
用環形串列重解約瑟夫問題：n 個人報數到 k 出局。

比較：用陣列模擬每刪一人要 O(n) 搬移或跳格，
用環形串列刪人只要 removeAfter —— O(1)。
量測 n = 100000, k = 3 時兩種做法的時間差。
