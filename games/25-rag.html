RAG 校園問答

AI 不知道海大餐廳幾點開，卻可能一本正經地亂答。RAG 的做法是：先去資料裡找出最相關的幾段，再請 AI 只根據這幾段回答。「找」的那一步，用的就是你學過的陣列和堆積。

00

先搞懂：RAG 到底是什麼

沒學過程式也看得懂。先把名詞和定義弄清楚，後面的遊戲才不會霧煞煞。

一句話定義

DEFINITION · 定義
RAG 是先檢索相關資料，再把資料交給語言模型，讓它根據資料回答的做法。

白話補一句：把閉卷考變成開書考。模型不必背下所有資料，只要會看你翻給它的那幾頁。

目的語言模型沒讀過你們學校的規定，也不知道昨天才改的事。RAG 讓它能回答自己沒學過的資料，還能指出答案出自哪一段。

先認識這些詞（照順序讀，後面的詞會用到前面的）

語言模型 LLM
讀過大量文字、會接著寫出下一段話的程式。ChatGPT、Claude 都是。
像一個讀過很多書、但沒帶書進考場的學生。
幻覺 hallucination
模型不知道答案，卻講出一段聽起來合理的錯誤內容。
考試不會寫，還是把答案卷寫得滿滿的。
文件塊 chunk
把長文件切成的一小段。檢索時一次拿一段，不拿整份。
不是把整本書交給學生，而是翻到有用的那一頁。
向量 vector
一串數字，就是一個陣列。每一格代表一個特徵。
像體檢表：身高、體重、視力，幾個數字描述一個人。
嵌入 embedding
把一段文字變成向量。意思接近的文字，會變成接近的向量。
幫每段文字在地圖上標座標，主題相近的就住得近。
相似度 cosine similarity
用一個數字表示兩個向量多接近。本關的分數在 0 到 1 之間，越大越像。
比較兩個人走的方向：同方向 1 分，完全不同方向 0 分。
前 k 名 top-k
分數最高的 k 段文字。k 是我們自己決定的數字。
班上取前三名，不必把全班從頭排到尾。
提示詞 prompt
實際送給模型的文字：規則＋找到的資料＋使用者的問題。
開書考的考卷：作答規則、參考資料、題目都印在上面。

看圖判斷：哪些是 RAG？

容易搞混的幾件事

常被搞混的東西一樣嗎？差在哪
RAG 和搜尋引擎不一樣搜尋把資料列給你看。RAG 多一步，由模型讀過資料後寫出回答。
RAG 和再訓練模型不一樣再訓練會改變模型本身。RAG 不動模型，只換餵給它的資料，資料更新時改資料就好。
向量比對和關鍵字比對不一樣關鍵字要字面相同才找得到。向量比的是意思，「肚子餓」也能找到「午餐」。
找到相關資料和資料裡有答案不一樣分數高只代表主題接近。第 5 關的問題就找得到宿舍規定，但規定裡沒寫答案。

自我檢查（先自己想，再點開看答案）

學校昨天改了圖書館的開放時間，RAG 系統要重新訓練模型嗎？
不用。更新那段文件和它的向量就好，模型本身不動。這是 RAG 最大的好處之一。
用了 RAG，模型就不會答錯了嗎？
不是。找錯資料、沒找到關鍵的那段、或模型讀錯，都可能答錯。RAG 能減少亂編，也讓人能回頭查證，但不保證正確。
為什麼不把全部資料都貼給模型？
資料一多就放不下，就算放得下也又慢又貴，無關的內容還可能干擾回答。所以先挑出最相關的 k 段。

  2. 答對得分、連對加分；答錯立刻解釋理由。

你會學到什麼

  • RAG 的流程 —— 切塊、向量化、檢索、組提示詞、生成回答。
  • 向量與相似度 —— 文字怎麼變成陣列，餘弦相似度怎麼算。
  • 用大小為 k 的最小堆積取前 k 名 —— 為什麼堆頂放最低分，而不是最高分。
  • k 怎麼影響答案 —— k 太小會漏掉資料，太大會混入雜訊。
  • 相似度門檻 —— 找不到就說找不到，不要硬答。
  • RAG 的極限 —— 找到相關資料，不代表資料裡有答案。
建議順序 第 1 關看完整流程 → 第 2 關比較字面和意思 → 第 4、5 關看「找不到」的兩種情況 → 第 6、7 關比較 k=1 和 k=2。
注意 本關的校園資料是教學用的虛構內容，不是學校的真實規定。本頁也沒有連到真的語言模型，回答是為了示範而預先寫好的。

      這個遊戲跑的程式（完整版）

      把視覺化全部拿掉，檢索就這麼短。只有 embed 和 llm 要靠模型，其他都是本課學過的資料結構。

      #include <bits/stdc++.h>
using namespace std;
typedef pair<double,int> P;                  // (分數, 文件編號)
const double THRESHOLD = 0.30;               // 最高分低於門檻就不回答

double cosine(const vector<double>& a, const vector<double>& b) {
    double dot = 0, na = 0, nb = 0;
    for (size_t i = 0; i < a.size(); i++) {
        dot += a[i] * b[i];                  // 對應的格子相乘再加總
        na += a[i] * a[i];
        nb += b[i] * b[i];
    }
    if (na == 0 || nb == 0) return 0;        // 全部是 0 的向量沒有方向
    return dot / (sqrt(na) * sqrt(nb));
}

vector<P> retrieve(const vector<double>& q, const vector<vector<double>>& docs, int k) {
    priority_queue<P, vector<P>, greater<P>> pq;   // 最小堆積：堆頂是目前第 k 名
    for (int i = 0; i < (int)docs.size(); i++) {
        double s = cosine(q, docs[i]);
        if ((int)pq.size() < k) pq.push({s, i});     // 還沒滿，直接放
        else if (s > pq.top().first) {               // 比第 k 名高，才換掉它
            pq.pop();
            pq.push({s, i});
        }
    }
    vector<P> top;
    while (!pq.empty()) { top.push_back(pq.top()); pq.pop(); }
    reverse(top.begin(), top.end());         // 改成由高到低
    return top;
}

      手算一次餘弦相似度

      只看三個主題：吃、時間、書。問題向量 q＝(1, 1, 0)，文件向量 d＝(1, 0, 1)。

      步驟算式結果
      內積：對應格子相乘再相加1×1 + 1×0 + 0×11
      q 的長度√(1² + 1² + 0²)√2
      d 的長度√(1² + 0² + 1²)√2
      相似度＝內積 ÷ 兩個長度相乘1 ÷ (√2 × √2)0.5
      重點除以長度，是為了比「方向」而不是「大小」。長文件的數字通常比較大，但不代表比較相關。

      為什麼前 k 名要用最小堆積

      我們要留下分數最高的 k 筆，堆頂卻放最低分。因為新資料來時，只需要和「目前第 k 名」比；它就是最容易被換掉的那一筆，放在堆頂一眼就看得到。

      做法時間額外空間說明
      全部排序再取前 kO(N log N)O(N)把用不到的名次也排好了
      大小為 k 的最小堆積O(N log k)O(k)k 通常很小，堆積很淺

      RAG 的環節用到的結構對應關卡

      用文件編號取回原文雜湊表，平均 O(1)16 雜湊表

      複雜度

      • 時間 O(N·d + N log k) —— N 段文件各算一次 d 維相似度，每段最多動一次大小為 k 的堆積。
      • 空間 O(N·d) —— 所有向量都要存。100 萬段、每段 768 維、每格 4 位元組，大約 3 GB。
      • 資料很多時 —— 逐段比對太慢，真實系統會用近似最近鄰搜尋：只看一部分的點，換來速度，代價是偶爾漏掉真正的第一名。

      常見誤解

      • 「用了 RAG 就不會有幻覺」 —— 第 5 關就是反例。系統找到了宿舍資料，資料卻沒有答案，所以還要靠提示詞要求模型「資料沒寫就說不知道」。
      • 「k 越大越好」 —— 第 1 關的第二名是體育館，和餐廳無關。k 太大只會塞進更多雜訊，還更花錢。
      • 「分數最高的就是答案」 —— 第 6 關的第一名只有圖書館，要回答問題還需要宿舍那段。
      • 「文件切得越細越好」 —— 切太細會把一句完整的規定切斷，切太粗又會混進無關內容。

      這一關的向量是手做的

      真實的 embedding 由模型算出，常有幾百到幾千維，而且每一維沒有人看得懂的意思。為了看清楚，本關改成 8 個主題，每個主題有一張同義詞表，算一段文字命中幾個詞。

      代價同義詞表沒列到的詞就認不得，這點比真正的 embedding 差很多。「自己問」時如果問題完全沒命中，向量就會全部是 0。
