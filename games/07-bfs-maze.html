Game 07 · BFS vs DFS

迷宮 BFS 對 DFS

同一份程式碼，只改「取出元素」那一行 —— 用佇列就變成一圈一圈擴散的 BFS，用堆疊就變成一路鑽到底的 DFS。這是整個課程裡「換一個資料結構，行為就完全不同」最清楚的一次示範。

01

怎麼玩・你會學到什麼

重點是「同一個迷宮跑兩次」，不是跑一次就好。

怎麼玩

  1. 按 隨機迷宮 產生一張圖，或用滑鼠拖曳畫牆自己設計。
  2. 上方大開關選 Queue → BFS 或 Stack → DFS。
  3. 按 開始搜尋，看橘色的「待處理格子」怎麼往外長。
  4. 記下結果的路徑長度和走訪格數。
  5. 關鍵步驟：不要重新產生迷宮，直接切到另一個演算法再跑一次，比較兩組數字。
看形狀 BFS 的橘色區域像水波紋，均勻往外推；DFS 像一條蛇，細細長長鑽到底再回頭。這個形狀差異就是 FIFO 和 LIFO 的差別長出來的樣子。

滑鼠模式可以切換畫牆、擦除、移動起點與終點。改動任何東西都會自動重設搜尋。

你會學到什麼

  • BFS 與 DFS 只差一個資料結構 —— 程式碼其他部分一字不改，換容器就換演算法。
  • 為什麼 BFS 保證最短路徑 —— 因為它嚴格按「距離由近到遠」的順序走訪。
  • 為什麼 DFS 不保證 —— 它會先一路衝到底，第一次碰到終點時可能繞了一大圈。
  • 搜尋的三件套 —— frontier（待處理）、seen（已排隊過）、parent（從哪來的），少一個就會出錯。
  • 為什麼要在放入時就標記 seen —— 這是最多人寫錯的一行，會讓同一格被重複排隊。
  • 怎麼把路徑還原出來 —— 從終點沿著 parent 一路回溯到起點。
  • 空間複雜度的差別 —— BFS 存「最寬那一層」，DFS 存「最深那條路」。
建議順序 先用 清空 做一個沒有牆的空白場地跑 BFS —— 你會看到一個完美的菱形波紋，那就是「距離相同的格子同時被走訪」。看懂這個，就懂為什麼 BFS 是最短路徑。

    整份程式逐行中文說明

      這個遊戲跑的程式（完整版）

      你按「單步」跑的就是這一段。把 front()/pop_front() 改成 back()/pop_back()，就是上面那顆開關做的事。while 迴圈自然結束（frontier 空了還沒碰到終點）就是「走不到終點」的情況：

      #include <deque>
#include <vector>
using namespace std;

// grid[r][c] == 1 是牆。回傳起點到終點的最短步數，找不到回傳 -1。
int bfs(const vector<vector<int>>& grid, int sr, int sc, int gr, int gc) {
    int R = grid.size(), C = grid[0].size();
    deque<pair<int,int>> frontier = {{sr, sc}};
    vector<vector<int>> dist(R, vector<int>(C, -1));   // -1 = 還沒 seen 過
    dist[sr][sc] = 0;
    int dr[] = {-1, 1, 0, 0}, dc[] = {0, 0, -1, 1};

    while (!frontier.empty()) {
        auto [r, c] = frontier.front(); frontier.pop_front();
        // ↑ 改成 back() + pop_back() 就變 DFS —— 整支程式只差這一行
        if (r == gr && c == gc) return dist[r][c];
        for (int i = 0; i < 4; i++) {
            int nr = r + dr[i], nc = c + dc[i];
            if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;
            if (grid[nr][nc] == 1 || dist[nr][nc] != -1) continue;
            dist[nr][nc] = dist[r][c] + 1;             // 放進去的當下就標記
            frontier.push_back({nr, nc});
        }
    }
    return -1;                             // frontier 空了還沒碰到終點
}
// 要畫出路徑就再開一個 parent[][]，從終點沿 parent 一路走回起點（見第 03 段）
      03

      這個功能是怎麼做到的

      一個模板，兩種演算法。

      問題定義

      給一張格子地圖，有起點、終點和牆。每次只能往上下左右移動一格，不能穿牆。找出一條從起點到終點的路 —— 而且最好是最短的那條。

      通用搜尋模板

      BFS 和 DFS 是同一個模板。整段程式碼只有一行不一樣：

      deque  frontier = { 起點 };    // 待處理：知道可以走、但還沒展開的格子
set    seen     = { 起點 };    // 已經排過隊的格子（避免重複）
map    parent;                // 每一格是從哪一格走過來的

while (!frontier.empty()) {
    cur = frontier.front();  frontier.pop_front();   // ← 佇列（FIFO）→ BFS
    cur = frontier.back();   frontier.pop_back();    // ← 堆疊（LIFO）→ DFS

    if (cur == 終點) break;

    for (nb : cur 的四個鄰居)
        if (nb 不是牆 && !seen.count(nb)) {
            seen.insert(nb);             // 注意：放進去的當下就標記
            parent[nb] = cur;
            frontier.push_back(nb);
        }
}
      整題重點 兩個演算法的差別只有取出的那一行。放進去的方式一樣、判斷條件一樣、記錄方式一樣。換掉容器，行為就整個改變 —— 這就是「選對資料結構」的威力。

      搜尋的三件套，少一個就出錯

      名稱裝什麼拿掉會怎樣
      frontier 已經知道可以走、但還沒去展開鄰居的格子 沒有待辦清單，程式不知道下一步要去哪
      seen 所有曾經放進 frontier 的格子 會在原地來回無限繞圈，永遠跑不完
      parent 每一格是從哪一格走過來的 找得到終點，但畫不出路徑，只知道有路不知道路在哪
      最常寫錯 很多人把 seen.add() 寫在取出的時候，而不是放進去的時候。這樣同一格會被不同鄰居重複塞進 frontier 好幾次，容器爆大、速度變慢，路徑長度也可能算錯。放進去的當下就標記，這是對的寫法。

      為什麼 BFS 保證是最短路徑

      把 frontier 想成一圈水波。用佇列（先進先出）時，會發生一件很整齊的事：

      • 第 1 輪：處理所有距離 1 的格子。
      • 第 2 輪：處理所有距離 2 的格子。
      • 第 d 輪：處理所有距離 d 的格子。

      因為佇列永遠先吐出比較早放進去的東西，而距離小的一定比距離大的早放進去，所以 BFS 是嚴格按照距離由近到遠走訪的。

      所以 當 BFS 第一次碰到終點時，那個距離一定是最小的 —— 因為所有更近的格子都已經檢查過了，如果有更短的路早就找到了。這就是「保證最短」的完整理由。

      在上面的遊戲按「清空」做一片空地再跑 BFS，你會看到一個完美的菱形往外長。菱形的每一圈就是「距離相同」的所有格子。

      為什麼 DFS 不保證

      堆疊永遠吐出最晚放進去的，所以程式會一頭鑽進最新發現的方向，一路走到不能走為止，才回頭試別的分岔。

      它找得到路（只要有路就一定找得到），但第一次碰到終點時走的那條，很可能是繞了一大圈的路。用同一個迷宮跑兩次，看「路徑長度」那個數字的差距，就很有感覺。

      佇列 → BFS 廣度優先

      • 像水波紋，均勻一圈一圈擴散
      • 保證最短路徑（每步成本相同時）
      • 記憶體較大：要存整圈的邊界
      • 用途：最短路徑、社群「幾度分隔」、西洋棋馬走日最少步數

      堆疊 → DFS 深度優先

      • 像一條蛇，一路鑽到底再回頭
      • 不保證最短，可能繞很大一圈
      • 記憶體較小：大致只存一條路徑
      • 用途：判斷「有沒有路」、拓撲排序、解數獨、迷宮生成

      怎麼把路徑還原出來

      搜尋過程中並沒有記錄「路徑」，只記錄了每一格的上一格。找到終點之後，從終點沿著 parent 一路往回走，走到起點為止，再把整串反過來，就是路徑。

      vector<Cell> path;
Cell cur = 終點;
while (cur != 起點) {
    path.push_back(cur);
    cur = parent[cur];
}
path.push_back(起點);
reverse(path.begin(), path.end());

      這招叫回溯父節點，在最短路徑、樹的走訪、遊戲 AI 裡到處都會再遇到。

      複雜度

      比較項目佇列（BFS）堆疊（DFS）
      取出的元素最早放進去的（FIFO）最晚放進去的（LIFO）
      擴散形狀圓形／菱形波紋細長蛇形
      最短路徑保證不保證
      時間複雜度O(V + E)O(V + E)
      空間複雜度O(最寬那一層)O(最深那條路)
      C++ 實作deque::pop_front()deque::pop_back()

      兩者時間複雜度相同 —— 最壞情況都要看過每一格和每一條邊。差別在順序，以及順序帶來的最短性保證。

      常見誤解

      • 「BFS 比 DFS 快」 —— 不一定。兩者都是 O(V+E)。BFS 常常走訪比較多格子（因為它把整圈都攤開），只是它換到了「最短」這個保證。
      • 「DFS 一定要用遞迴」 —— 不用。這個遊戲的 DFS 就是用一個明確的堆疊寫成迴圈。遞迴版本只是借用了系統的呼叫堆疊而已（見 04 呼叫堆疊）。
      • 「seen 和 frontier 是同一件事」 —— 不是。frontier 是「還沒展開」，seen 是「曾經排過隊」。已經處理完的格子還在 seen 裡，但早就不在 frontier 裡了。
      • 「每格成本不同時 BFS 也保證最短」 —— 不保證。那要換成 Dijkstra，把佇列升級成優先佇列。BFS 的保證建立在「每一步成本都是 1」上。
      04

      程式架構與說明

      只講流程與分工，不逐行拆解。

      整體設計：一個模板，一個開關

      本頁只寫了一份搜尋程式。演算法切換不是切換兩段程式碼，而是切換一個布林值：

      var cur = useQueue ? frontier.shift() : frontier.pop();
//                  ↑ 取隊頭 O(n)*      ↑ 取堆疊頂端 O(1)

      * JavaScript 的 shift() 其實是 O(n)。教學用的格子數很小所以無所謂，但正式實作要用真正的 deque 或環形佇列 —— 這正是 06 約瑟夫問題 講的那件事。

      為什麼這樣寫 寫成兩份程式碼，學生會以為 BFS 和 DFS 是兩個不同的演算法。寫成一份加一個開關，才看得出來它們本來就是同一個演算法。

      模組分工

      層主要函式負責什麼
      地圖genMaze / clearWalls
      paint      		產生與編輯迷宮。任何改動都會呼叫 resetSearch()。
      搜尋狀態resetSearch把 frontier、seen、parent 三件套歸零。
      演算法oneStep核心。取出一格、檢查是否到終點、把鄰居排進去。
      路徑還原buildPath從終點沿 parent 回溯，並和裁判答案比對。
      裁判bfsShortest獨立跑一次純 BFS 算真正的最短距離，用來判定 DFS 差幾步。
      畫面render依 grid、seen、frontier、pathCells 決定每一格的顏色。
      誠實說明 bfsShortest() 是只為了教學而存在的裁判，不是演算法的一部分。它偷偷再跑一次標準 BFS，好讓畫面能顯示「你的 DFS 比最短多了幾步」。真實程式裡不會有這個函式。

      核心：oneStep() 的流程

      frontier 是空的嗎？
      cur ← 取出一格 useQueue ? shift() : pop()
      cur 是終點嗎？ 是 → buildPath() 收工
      出界？跳過
      是牆？跳過
      seen 過？跳過
      都不是標記 seen、記 parent、放進 frontier
      render()

      四個鄰居各跑一次這個判斷。三個「跳過」的條件順序可以互換，但都必須存在。

      一個彩蛋：產生迷宮也用了堆疊

      genMaze() 用的是「隨機深度優先挖路」：從一格出發，隨機挑一個還沒挖過的方向鑽進去，鑽不動了就 pop() 退回上一格再試別的方向。

      換句話說 —— 這一頁用堆疊產生迷宮，然後用佇列或堆疊去解它。同一個資料結構，在同一個檔案裡出現了兩種完全不同的用途。

      挖完之後程式還會隨機打通約 30 面牆，製造多條路徑 —— 不這樣做的話迷宮只有唯一解，BFS 和 DFS 會找到同一條路，就比較不出差別了。
