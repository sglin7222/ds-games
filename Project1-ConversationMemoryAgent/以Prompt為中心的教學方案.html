以 Prompt 為中心的資料結構教學

用 AI Prompt 來學習、設計、實現、優化

核心理念：
每個學習階段都有對應的 Prompt 模板
學生通過對話 Claude 來完成任務
不背概念，用 Prompt 直接做事

教學方法：5 類 Prompt 模板

1️⃣ 理解類 Prompt：問 AI 為什麼

📚 Skill：理解資料結構

何時使用： 課堂開始，想理解一個新的資料結構

你是資料結構講師。用簡單的例子解釋 Stack。 不要講 Python 語法，講： - 為什麼叫「棧」？真實生活的例子？ - 什麼時候用 Stack 而不是列表？ - Stack 最重要的性質是什麼？ 用日常語言，不要用術語。
✅ 學生說： 複製上面的 prompt 發給 Claude
Claude 回答： 用自助餐盤子的例子解釋 LIFO...
學生收穫： 深層理解，不是死記

2️⃣ 設計類 Prompt：告訴 AI 你要什麼

🎯 Skill：設計資料結構接口

何時使用： 要實現一個資料結構前，先設計它

我要設計一個 Stack 類。請幫我： 1. 列出 Stack 需要的所有操作（方法） 2. 每個方法的時間複雜度應該是多少？ 3. 邊界情況有哪些？（空棧、單元素...） 4. 內部怎樣存儲數據最有效？ 用表格列出方法名、功能、時間複雜度。
✅ 學生的好處： 不是盲目寫代碼，而是先有清晰的設計

3️⃣ 實現類 Prompt：讓 AI 寫代碼

💻 Skill：實現資料結構

何時使用： 設計好了，開始寫代碼

用 Python 實現一個 Stack 類。 需求： - 方法：push、pop、peek、is_empty、size - push/pop 時間複雜度必須是 O(1) - 內部用 list 存儲 - 每個方法都有完整的文檔字符串 - 邊界情況的處理（空棧時 pop 應該返回 None） 給我完整可運行的代碼。
✅ 流程：
1. 複製 prompt → 2. Claude 給代碼 → 3. 粘貼到編輯器 → 4. 測試

4️⃣ 應用類 Prompt：用資料結構解決問題

🚀 Skill：應用資料結構

何時使用： 會用 Stack 後，用它去做真實的事

用剛才的 Stack 實現一個 TextEditor 類。 功能： - type(text)：鍵入文本 - undo()：撤回最後一次編輯 - get_content()：取得當前內容 需要用 Stack 存儲編輯歷史。 完整代碼，包括測試。
- 第 1 頁 -

5️⃣ 審查類 Prompt：讓 AI 幫你改進代碼

🔍 Skill：代碼審查和優化

何時使用： 代碼寫完了，要改進

幫我審查這段代碼： [粘貼你的代碼] 檢查點： 1. 有 bug 嗎？邊界情況處理得對嗎？ 2. 時間複雜度對嗎？ 3. 代碼清晰嗎？有冗餘嗎？ 4. 能優化嗎？有更好的方案嗎？ 5. 文檔字符串夠清楚嗎？ 逐項評論。
✅ 典型對話：
學生： 「這個 pop 方法有什麼問題嗎？」
Claude： 「如果棧是空的會報錯...」
學生： 「改一下。」
Claude： [改進的代碼]

完整的一週流程

階段 用什麼 Prompt 學生做什麼 時間
理解 理解類 Prompt 與 Claude 討論 Stack 是什麼 30 分鐘
設計 設計類 Prompt 讓 Claude 幫你設計接口 30 分鐘
實現 實現類 Prompt 複製 prompt，得到代碼 30 分鐘
應用 應用類 Prompt 用 Stack 做一個應用 1 小時
審查 審查類 Prompt 讓 Claude 評論你的代碼 1 小時

6 週完整 Prompt 教學計劃

第 1-2 週：Stack（棧）- Prompt 模板集合

課堂流程： 理解 → 設計 → 實現 → 應用 → 審查

📚 Prompt 1：理解 Stack

你是大學教授。用非技術性語言解釋 Stack： - 盤子堆棧的例子 - 為什麼後進先出很重要 - 生活中哪些東西像 Stack - Stack 和 Queue 的區別（用日常例子） 不要講代碼，講概念。

🎯 Prompt 2：設計 Stack 接口

請為 Stack 設計一個完整的接口。 輸出格式： 表格，包括： - 方法名稱 - 功能描述 - 參數和返回值 - 時間複雜度 - 邊界情況 要求：push、pop、peek、size、is_empty。

💻 Prompt 3：實現 Stack

用 Python 實現 Stack 類： [上面的設計表格] 要求： - 實現所有方法 - 時間複雜度必須符合設計 - 完整的文檔字符串 - 邊界情況：空棧時 pop() 返回 None - 可運行的代碼

🚀 Prompt 4：應用場景 1 - 撤回功能

用 Stack 實現一個 EditHistory 類： 功能： - add_edit(text)：記錄編輯 - undo()：撤回最後編輯 - get_current()：取得當前內容 例子： editor.add_edit("Hello") → "Hello" editor.add_edit(" World") → "Hello World" editor.undo() → "Hello" 完整代碼 + 測試。

🚀 Prompt 5：應用場景 2 - 括號匹配

用 Stack 實現括號匹配函數： def is_balanced(s: str) -> bool: 檢查括號是否匹配 "{[()]}" → True "{[(])}" → False 用 Stack 實現，不用其他方法。 完整代碼 + 測試。

🔍 Prompt 6：審查代碼

審查我的 Stack 實現： [粘貼你的代碼] 檢查： 1. 有 bug 嗎？ 2. 邊界情況處理得對嗎？ 3. 時間複雜度對嗎？ 4. 代碼清晰度如何？ 5. 能優化嗎？ 逐項評論，給出改進建議。

✅ 第 1-2 週結果： 完全理解 Stack，寫過 3 個應用，代碼被審查過

- 第 3 頁 -

第 2-3 週：Queue（佇列）- 同樣的 Prompt 模式

📚 Prompt 1：理解 Queue

解釋 Queue（佇列）： - 銀行排隊的例子 - 為什麼先進先出很重要 - Queue vs Stack 的區別 - 真實應用：消息隊列、任務隊列、BFS - 為什麼 Queue 用 deque 而不是 list 用日常語言，不要代碼。

🎯 Prompt 2：設計 Queue 接口

為 Queue 設計接口： - enqueue（入隊） - dequeue（出隊） - peek - size - is_empty 表格格式，包括時間複雜度。

💻 Prompt 3：實現 Queue

用 Python 實現 Queue： - 內部必須用 deque（不能用 list） - enqueue/dequeue 時間複雜度是 O(1) - 完整的文檔字符串 - 邊界情況處理

🚀 Prompt 4：應用場景 1 - 任務隊列

用 Queue 實現 TaskQueue 和 TaskScheduler： TaskQueue：管理待執行任務 TaskScheduler：依次執行任務 例子： scheduler.submit("分析", data) scheduler.submit("保存", data) scheduler.process_all() // 按順序執行 完整代碼 + 測試。

🚀 Prompt 5：應用場景 2 - BFS 算法

用 Queue 實現 BFS（廣度優先搜尋）： def bfs(graph, start): 用 Queue 實現 BFS 返回節點訪問順序 圖的例子： A → B, C B → D C → E BFS 結果：A, B, C, D, E 完整代碼 + 測試。

🔍 Prompt 6：性能對比

比較 List vs Deque 的性能： 在 Queue 中： 1. 用 list 實現，pop(0) 做 dequeue 2. 用 deque 實現，popleft() 做 dequeue 對 100,000 個元素分別測試。 測量時間，說明為什麼 deque 快。

✅ 第 2-3 週結果： 理解 Queue，實現 3 個應用，理解性能差異

第 3-4 週：Hash Table（雜湊表）與會話系統

📚 Prompt 1：理解雜湊表

解釋雜湊表和雜湊函數： - 字典/電話簿的例子 - 為什麼查詢這麼快？O(1) - 雜湊函數的概念 - 碰撞是什麼？怎樣解決？ - Hash Table vs List 的性能對比 用例子，不要數學公式。

💻 Prompt 2：實現 HashTable

用 Python dict 實現一個簡單的 HashTable： 功能： - put(key, value) - get(key) - remove(key) - contains(key) - keys() - values() 要求： - 文檔字符串 - 邊界情況 - 時間複雜度 內部用 dict 實現。

🎯 Prompt 3：設計會話管理系統

設計一個會話管理系統： 需求： - 支持 1000 個並發用戶 - 快速查詢用戶會話 - 每個會話有獨立的數據 問題： 1. 用什麼資料結構存儲會話？ 2. 為什麼用 HashTable 而不是 List？ 3. 時間複雜度對比 畫出系統架構圖。

💻 Prompt 4：實現 SessionCache

用 HashTable（雜湊表）實現 SessionCache： 功能： - create_session(user_id) - get_session(user_id) - delete_session(user_id) - get_all_sessions() 每個 session 包含： - user_id - conversation_stack（之前做的 Stack） - task_queue（之前做的 Queue） - 元數據 完整代碼。

🚀 Prompt 5：性能測試

測試 SessionCache 的性能： 1. 建立 10,000 個會話 2. 隨機查詢 1000 次 3. 測量查詢時間 對比： - 用 list 線性搜尋：O(n) - 用 dict（hash）：O(1) 畫出性能曲線。

✅ 第 3-4 週結果： 理解雜湊表，實現會話系統，看到性能差異
