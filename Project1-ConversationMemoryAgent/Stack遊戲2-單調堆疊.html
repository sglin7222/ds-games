題目二：每日溫度（LeetCode 739）

給一個陣列 temperatures，第 i 個元素是第 i 天的氣溫。 請對每一天回答：還要等幾天，才會遇到比今天更暖的日子？如果之後都不會更暖，答 0。

輸入[73, 74, 75, 71, 69, 72, 76, 73] 輸出[ 1, 1, 4, 2, 1, 1, 0, 0]

第 0 天 73°，隔天就 74° → 等 1 天。
第 2 天 75°，要一路等到第 6 天的 76° → 等 4 天。
第 6 天 76° 是最高溫，之後再也沒更暖的 → 0。

這兩題其實是同一個問題

把兩題翻譯成同一句話：「對每個元素，找出它右邊第一個比它小（或比它大）的元素在哪裡。」

・每日溫度 → 直接就是在問「右邊第一個更大的元素」
・柱狀圖 → 以第 i 根為高的矩形，左界是「左邊第一個比它矮的」，右界是「右邊第一個比它矮的」
　　面積 = h[i] × (右界 − 左界 − 1)

這類問題有個共同名字：Next Greater / Next Smaller Element，而它們的共同解法就是單調堆疊。

為什麼這題重要：它是「暴力 O(n²) → 巧妙 O(n)」最漂亮的示範， 也是各大公司面試的高頻題。更重要的是，一旦看懂這個「等待 ↔ 結算」的模式， 接雨水、股票跨度、最大子矩形等一整族題目都會一起解開。

🧠 解法解說

第 0 步：先寫出暴力解，才知道浪費在哪

def brute(h): # O(n²) best = 0 for i in range(len(h)): lo = h[i] for j in range(i, len(h)): lo = min(lo, h[j]) # 區間最小值 = 矩形高度 best = max(best, lo * (j - i + 1)) return best

正確，但每個區間都重算一次最小值。n = 10 萬時要跑 50 億次 —— 面試直接掛。
浪費點：「第 3 根左邊第一個比它矮的是誰」這件事，被重複問了無數次。

第 1 步：換個角度枚舉

不要枚舉「所有區間」（有 n² 個），改成枚舉「誰當這個矩形的高度」（只有 n 個）。
對第 i 根柱子，答案就是：它能往左右延伸多遠而不被更矮的柱子擋住。
問題瞬間變成：找左邊第一個比它矮的、右邊第一個比它矮的。

第 2 步：關鍵洞察（整題只有這一個要想通）

我們從左往右掃。掃到第 i 根時，前面那些柱子的右邊界還不知道，所以它們只能先掛在那裡等。 問題是：這些「等待中」的柱子，要用什麼結構存？

洞察：如果 j < i 而且 h[j] ≥ h[i]，那 j 可以馬上結算，永遠不必再等。

為什麼？因為任何想要跨過第 i 根的矩形，高度都會被 h[i] 壓下去，不可能再用到 h[j] 這個高度。 第 i 根就是第 j 根的右邊界 —— 現在就能算出它的答案。

而「馬上結算並丟掉」的直接後果是：能留在容器裡的柱子，必定由下往上遞增。 這就是「單調」堆疊的由來 —— 單調不是我們刻意維護的，是規則的副產品。

第 3 步：左邊界是免費送的

彈出第 j 根時，Stack 裡緊接在它下面的那根，正好就是「左邊第一個比它矮的柱子」—— 因為中間所有比它高的都已經被彈掉了，比它矮的又不可能還留在下面。

left = stack[-1] + 1 if stack else 0 # 左界：下面那根的右邊一格；Stack 空代表能一路延伸到最左 right = i - 1 # 右界：現在這根的左邊一格 width = right - left + 1 = i - left area = h[j] * width

兩個邊界都是 O(1) 拿到的，這正是暴力解花 O(n) 去掃的東西。

第 4 步：哨兵 —— 處理「永遠等不到」的柱子

如果柱子一路遞增（例如 [1,2,3,4,5]），掃到最後 Stack 裡還塞著一整排沒結算的柱子。
解法很賴皮：在陣列尾巴補一根高度 0 的假柱子。它比誰都矮，會逼著 Stack 全部彈空， 於是不用再寫一段重複的收尾程式碼。

巢狀的 while 不代表 O(n²)：要看的是整趟下來的總操作次數，不是單次迴圈的最壞情況。 這個技巧叫攤還分析，你可以在互動區右下角的「總 push+pop」欄位親眼驗證它永遠 ≤ 2n。

❌ 五個最常見的錯誤
  1. Stack 存高度而不存索引 → 算寬度時沒有位置資訊，整題卡死。永遠存索引，高度用 h[idx] 查
  2. 左界寫成 stack[-1] → 少算一格。正確是 stack[-1] + 1，Stack 空時是 0
  3. 忘記哨兵 → 遞增陣列 [1,2,3] 直接回傳 0，因為沒有任何元素被結算
  4. 先 push 再檢查 → 順序反了，必須「先把該結算的彈完，才輪到自己進場」
  5. 每日溫度把 < 寫成 <= → 同溫度的日子被誤判成「更暖」，答案全錯

為什麼暴力解會慢，Stack 快在哪？

🐌 暴力解 O(n²)

  • 對每根柱子，往左掃到比它矮的、往右掃到比它矮的
  • 10 萬根柱子 → 100 億次比較，跑不完
  • 浪費在哪：同一段區間被重複掃了無數次

🚀 單調堆疊 O(n)

  • Stack 裡放「還在等右邊界的柱子」，且高度保持遞增
  • 來了一根更矮的 → 它就是右邊界，把比它高的通通結算
  • 省在哪：「誰比我矮」這個資訊被 Stack 順手記住了，不用重掃
為什麼 Stack 裡一定是遞增的？
因為只要來了一根比 top 矮的，我們就馬上把 top 結算掉並彈出， 所以能留在 Stack 裡的，必定一根比一根高。
這個「遞增」不是我們刻意維護的，是規則的副產品 —— 但它保證了： 彈出 top 時，它左邊的邊界就是「Stack 裡它下面那個」，右邊界就是「現在這根」， 兩個邊界都免費拿到，O(1)。

程式碼：兩題只差一個比較符號

# ① 柱狀圖最大矩形（LeetCode 84）—— Stack 遞增 def largest_rectangle(h): h = h + [0] # 哨兵！逼 Stack 在結束前清空 stack, best = [], 0 for i, cur in enumerate(h): while stack and h[stack[-1]] >= cur: # 來了更矮的 → 結算 top = stack.pop() height = h[top] left = stack[-1] + 1 if stack else 0 # 左界＝下面那根的右邊一格 width = i - left # 右界＝現在這根 best = max(best, height * width) stack.append(i) return best
# ② 每日溫度（LeetCode 739）—— Stack 遞減，比較符號反過來而已 def daily_temperatures(t): ans = [0] * len(t) stack = [] for i, cur in enumerate(t): while stack and t[stack[-1]] < cur: # 來了更暖的 → 結算 j = stack.pop() ans[j] = i - j # 等了幾天 stack.append(i) return ans # 留在 stack 裡的，答案就是預設的 0
哨兵（sentinel）的技巧要記起來：在陣列尾巴補一個 0， 就不用在迴圈結束後再寫一段「把 Stack 剩下的清乾淨」的重複程式碼。
