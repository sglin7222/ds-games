🗼 河內塔

Stack 的經典遞迴應用

用 Stack 解決古老的河內塔謎題
理解遞迴如何對應 Stack 的壓棧/出棧

什麼是河內塔？

初始狀態：所有盤子在左塔
盤 1
盤 2
盤 3
左塔（起始）
中塔（臨時）
右塔（目標）

規則

  1. 只能移動一個盤子 - 一次只能從一個塔移到另一個塔
  2. 大盤不能在小盤上 - 大的盤子永遠在小的下方
  3. 目標 - 把所有盤子從左塔移到右塔

為什麼是 Stack？

ℹ️ 每個塔都是一個 Stack！
  • 🔝 每個塔只能從頂部放/取盤子
  • ⬇️ 最上面的盤子最先被移走（LIFO）
  • 🔄 用遞迴時，函數調用棧也正好對應塔的移動

第 1 步：理解河內塔遞迴

📚 Prompt 1：解釋河內塔如何用遞迴解決
✂️ 複製下面的 Prompt：
解釋「河內塔」問題和它的遞迴解法。 不要講代碼，講思路： 1. 什麼是河內塔？用盤子和塔的例子 2. 3 個盤子的情況怎麼解？ 3. 把 3 個盤子的解法推廣到 n 個盤子 4. 這個解法為什麼是遞迴的？ 5. 需要多少步移動？（公式） 用日常語言和圖示。
✅ Claude 的解釋（部分）：
河內塔（Tower of Hanoi）： 【問題】 有 3 個塔（A、B、C）和 n 個盤子 初始時所有盤子在 A 塔，小的在大的上面 目標：把所有盤子移到 C 塔 【3 個盤子的解法】 1. 把上面 2 個盤子從 A 移到 B（用 C 幫助） 2. 把最大的盤子（第 3 個）從 A 移到 C 3. 把 2 個盤子從 B 移到 C（用 A 幫助） 【n 個盤子的遞迴解法】 hanoi(n, 起點, 目標, 臨時): if n == 1: 直接移動 1 個盤子 else: 1. hanoi(n-1, 起點, 臨時, 目標) // 移上面 n-1 個 2. 移最大的盤子從起點到目標 3. hanoi(n-1, 臨時, 目標, 起點) // 移上面 n-1 個 【需要多少步？】 T(n) = 2^n - 1 - 1 個盤子：1 步 - 2 個盤子：3 步 - 3 個盤子：7 步 - 4 個盤子：15 步 - 64 個盤子：18,446,744,073,709,551,615 步！
✅ 現在理解了： 河內塔的遞迴結構，為什麼需要 2^n - 1 步

第 2 步：用 Stack 實現河內塔

💻 Prompt 2：用 Stack 實現河內塔
✂️ 複製下面的 Prompt：
用 Stack 實現河內塔。 代碼結構： 1. 定義 Stack 類（或使用我之前的） 2. 創建 3 個 Stack（left, middle, right），代表 3 個塔 3. 初始化：left 塔有盤子 n, n-1, ..., 2, 1（盤子 1 在頂部） 4. 實現 hanoi(n, source, target, temp) 函數： - 如果 n == 1：直接從 source pop 到 target - 否則：遞迴調用 hanoi(n-1, source, temp, target) 5. 每次移動盤子時，打印過程：「盤 X：源塔 → 目標塔」 給我完整代碼，測試 3 個盤子的情況。
✅ Claude 給出的代碼：
class Stack: def __init__(self): self._items = [] def push(self, item): self._items.append(item) def pop(self): return self._items.pop() if not self.is_empty() else None def peek(self): return self._items[-1] if not self.is_empty() else None def is_empty(self): return len(self._items) == 0 def size(self): return len(self._items) def __str__(self): return str(self._items) def hanoi(n, source, target, temp, towers, source_name, target_name): """ 遞迴解決河內塔 n: 盤子數 source, target, temp: Stack 對象 source_name, target_name: 塔的名稱 """ if n == 1: # 基本情況：直接移動 1 個盤子 disk = source.pop() target.push(disk) print(f" 盤 {disk}: {source_name} → {target_name}") return # 遞迴情況 # 找到臨時塔的名稱 temp_name = [name for name in ['左', '中', '右'] if name != source_name and name != target_name][0] # 步驟 1: 把 n-1 個盤子從 source 移到 temp hanoi(n-1, source, temp, target, towers, source_name, temp_name) # 步驟 2: 把最大的盤子從 source 移到 target disk = source.pop() target.push(disk) print(f" 盤 {disk}: {source_name} → {target_name}") # 步驟 3: 把 n-1 個盤子從 temp 移到 target hanoi(n-1, temp, target, source, towers, temp_name, target_name) # 測試 print("===== 河內塔（3 個盤子）=====\n") left = Stack() middle = Stack() right = Stack() # 初始化：左塔有 3 個盤子 for disk in [3, 2, 1]: left.push(disk) print(f"初始狀態：") print(f" 左塔: {left}") print(f" 中塔: {middle}") print(f" 右塔: {right}") print() # 移動所有 3 個盤子從左塔到右塔 hanoi(3, left, right, middle, None, "左", "右") print() print(f"最終狀態：") print(f" 左塔: {left}") print(f" 中塔: {middle}") print(f" 右塔: {right}") print(f"✅ 完成！總共 {2**3 - 1} 步")

第 5 步：複雜度分析

📊 Prompt 4：分析河內塔的時間複雜度
✂️ 複製下面的 Prompt：
分析河內塔的時間複雜度。 問題： 1. 為什麼需要 2^n - 1 步？用遞迴關係推導 2. 時間複雜度是 O(2^n) 嗎？ 3. 空間複雜度是多少？（考慮遞迴調用棧） 4. 能優化嗎？為什麼不能更少步？ 用數學推導和例子說明。
✅ Claude 的分析（部分）：
【時間複雜度分析】 遞迴關係：T(n) = T(n-1) + 1 + T(n-1) = 2*T(n-1) + 1 邊界：T(1) = 1 展開： T(n) = 2*T(n-1) + 1 = 2*(2*T(n-2) + 1) + 1 = 4*T(n-2) + 2 + 1 = 2^(n-1)*T(1) + 2^(n-2) + ... + 1 = 2^(n-1) + 2^(n-2) + ... + 1 = 2^n - 1 時間複雜度：O(2^n) ⏱️ 指數級別！ 【空間複雜度】 遞迴調用棧深度：O(n) 3 個 Stack 存儲盤子：O(n) 總體：O(n) 【為什麼不能更優？】 每一步都是必要的。沒有任何盤子可以「跳過」。 根據國際象棋傳說，64 個盤子需要 2^64-1 步。 即使每秒移動 1 盤，也需要 5,850 億年！
ℹ️ 關鍵洞察： 河內塔展示了遞迴的威力和限制
  • ✅ 簡潔的遞迴代碼（只需要 15 行）
  • ❌ 指數級時間複雜度（n=64 時無法完成）
  • 🎯 必然的複雜度（問題本身就是指數級的）
