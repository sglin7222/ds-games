🥞 呼叫堆疊 Call Stack：遞迴的真面目

遞迴不是魔法。每呼叫一次函式，電腦就幫你 push 一個框架（frame）；每 return 一次就 pop 掉。
你其實一直在用 Stack —— 只是這個 Stack 由作業系統替你管理。

📋 題目解說

核心問題：遞迴到底是怎麼被執行的？

大部分人會寫遞迴，但講不出這三件事：

  • fact(5) 呼叫 fact(4) 時，原本的 n=5 跑去哪裡了？為什麼沒有被蓋掉？
  • fact(1) 回傳之後，電腦怎麼知道要跳回哪一行繼續執行？
  • 為什麼遞迴太深會 Stack Overflow，但迴圈跑一億次卻不會？

答案全都是同一個東西：呼叫堆疊（Call Stack）。這份教材就是要把它畫出來給你看。

子題目一：階乘 factorial(n)

定義：n! = n × (n−1) × … × 2 × 1，且 0! = 1! = 1。
遞迴式：fact(n) = n × fact(n−1)，基底 fact(1) = 1。

輸入n = 5 輸出120　（= 5×4×3×2×1）

為什麼拿它當第一個例子：每層只呼叫一次自己，Stack 是一條乾淨的直線，最適合觀察 push/pop 的節奏。

子題目二：費氏數列 fib(n)

定義：F(0)=0，F(1)=1，F(n)=F(n−1)+F(n−2)。

輸入n = 6 輸出8　（0,1,1,2,3,5,8 的第 6 項）

為什麼拿它當第二個例子：每層呼叫兩次自己 → 呼叫次數指數爆炸， 但 Stack 深度只有 n。這個對比是本教材最重要的觀念。

子題目三：河內塔 hanoi(n)

三根柱子 A、B、C，n 個大小不同的盤子一開始由大到小疊在 A 上。把它們全部搬到 C，規則：

  1. 一次只能搬一個盤子
  2. 只能搬每根柱子最上面的盤子（← 這句話就是在說「柱子是 Stack」）
  3. 任何時候都不能把大盤子壓在小盤子上面
輸入n = 3 輸出7 個步驟（最少步數 2³ − 1 = 7）

為什麼拿它當第三個例子：它同時出現兩種 Stack —— 三根柱子本身是 Stack（只能動最上面），解法的遞迴又靠呼叫堆疊。

🧠 解法解說

第 1 步：遞迴的三個要素（缺一個就會爆）

  1. 基底條件（Base case）：什麼時候可以不用再遞迴，直接給答案。
    缺了它 → 無限 push → Stack Overflow。
  2. 遞迴關係（Recursive case）：把大問題拆成同樣形狀但更小的問題。
    fact(n) 交給 fact(n−1)、hanoi(n) 交給兩個 hanoi(n−1)。
  3. 收斂性：每呼叫一次都必須更靠近基底。
    寫成 fact(n) 呼叫 fact(n) 就永遠到不了基底。

第 2 步：手算一次 fact(3) 的呼叫堆疊

步驟發生什麼事Stack（底 → 頂）深度
1呼叫 fact(3) → PUSHfact(3)1
2fact(3) 卡住：要等 fact(2)，於是呼叫 fact(2) → PUSHfact(3), fact(2)2
3fact(2) 卡住：要等 fact(1)，於是呼叫 fact(1) → PUSHfact(3), fact(2), fact(1)3 ← 最深
4fact(1) 碰到基底條件，回傳 1 → POPfact(3), fact(2)2
5fact(2) 拿到 1，算 2×1=2，回傳 → POPfact(3)1
6fact(3) 拿到 2，算 3×2=6，回傳 → POP，Stack 清空（空）→ 答案 60

看懂這張表，你就看懂遞迴了：前半段一路 push（問題不斷變小但沒有答案）， 直到碰到基底條件才出現第一個答案，然後後半段一路 pop，答案由下而上逐層被算出來。
每一層的 n 都住在自己的 frame 裡，所以 fact(3) 的 n 不會被 fact(2) 蓋掉。

第 3 步：費氏數列 —— 呼叫次數為什麼爆炸

fib(4) ┌─────┴─────┐ fib(3) fib(2) ★ ┌───┴───┐ ┌──┴──┐ fib(2)★ fib(1) fib(1) fib(0) ┌───┴───┐ fib(1) fib(0) ★ = 一模一樣的子問題被重算了一次
子問題fib(4)fib(3)fib(2)fib(1)fib(0)總呼叫
被呼叫幾次112329

呼叫次數公式是 2·F(n+1) − 1：n=4 時 9 次、n=10 時 177 次、 n=30 時 270 萬次、n=50 時要跑好幾年。
慢的原因不是遞迴本身，而是重複計算 —— 同一個 fib(2) 被算了很多次。 加上 memo（@lru_cache）記住算過的結果，呼叫次數立刻降到 2n−1，時間從 O(2ⁿ) 變 O(n)。

本教材最重要的一句話：呼叫次數 ≠ Stack 深度。
fib(30) 呼叫 270 萬次，但 Stack 最深只有 30 層 —— 因為左子樹整棵跑完就被 pop 光了，右子樹才開始，兩邊不會同時存在於 Stack 上。
所以 fib 的問題是時間爆炸（O(2ⁿ)），不是記憶體爆炸（空間只有 O(n)）。 你可以在上面的互動區把模式切到費氏，盯著「總呼叫次數」和「最大深度」兩個數字看它們的差距。

第 4 步：河內塔 —— 三步法與最少步數證明

不要試著去想「第一步該搬哪個盤子」，那會直接卡死。 假設 hanoi(n−1) 已經有人幫你做好了，那 n 個盤子的解法必然是這三步：

  1. 把上面 n−1 個從 A 搬到中繼柱 B（借用 C 當中繼）　→ hanoi(n−1, A, B, C)
  2. 把最大的第 n 個從 A 直接搬到 C　→ 一步，就是印出來的那一行
  3. 把 B 上的 n−1 個搬到 C（借用 A 當中繼）　→ hanoi(n−1, B, C, A)
為什麼這樣一定合法？因為第 2 步搬的是最大的盤子，此時 C 是空的， 而 A 上除了它以外也沒別的 —— 不可能違反「大不能壓小」。
為什麼可以假設 n−1 個已經會搬？這就是數學歸納法，也是遞迴的本質： 你只需要負責定義「這一層怎麼拆」，剩下的交給更小的自己。
# 最少步數 T(n)：三步法裡只有第 2 步真的搬盤子 T(n) = 2·T(n-1) + 1 # 兩次 n-1 的搬移，加上中間那一步 T(0) = 0 # 展開： T(n) = 2·T(n-1) + 1 = 4·T(n-2) + 2 + 1 = 8·T(n-3) + 4 + 2 + 1 = 2^k·T(n-k) + (2^k - 1) = 2^n·T(0) + 2^n - 1 = 2^n - 1 # 令 k = n

所以 n=3 是 7 步、n=10 是 1023 步。傳說中的 64 個金盤需要 2⁶⁴−1 ≈ 1.8×10¹⁹ 步， 就算一秒搬一個，也要 5850 億年 —— 這就是指數成長的威力。
注意呼叫次數（2ⁿ⁺¹−1）比搬移次數（2ⁿ−1）多，因為 hanoi(0) 那些「什麼都不做就 return」的空呼叫也佔一個 frame。

第 6 步：遞迴 → 迭代，其實是「自己接管那個 Stack」

# 遞迴版：電腦幫你管理 Stack def hanoi(n, a, c, b): if n == 0: return hanoi(n-1, a, b, c); move(n, a, c); hanoi(n-1, b, c, a) # 迭代版：你自己拿一個 list 當 Stack，把「還沒做的任務」推進去 def hanoi_iter(n, a, c, b): stack = [(n, a, c, b, False)] # False = 這個任務還沒展開 while stack: n, a, c, b, expanded = stack.pop() if n == 0: continue if expanded: move(n, a, c) # 已展開過 → 執行中間那一步 else: stack.append((n-1, b, c, a, False)) # 注意：順序要反過來 push stack.append((n, a, c, b, True)) # 因為 Stack 是後進先出 stack.append((n-1, a, b, c, False))

兩版做的事完全一樣，差別只在「Stack 由誰管理」。
自己管理的好處：不受遞迴深度上限限制、可以隨時暫停/存檔/繼續、除錯時能直接印出整個 Stack。
代價：程式碼變醜，而且 push 的順序必須反過來寫（因為 LIFO）—— 這一點最容易寫錯。

❌ 五個最常見的錯誤
  1. 忘記基底條件 → RecursionError: maximum recursion depth exceeded（Python 預設 1000 層）
  2. 參數沒有變小：寫成 fact(n) 呼叫 fact(n)，或 fib(n-1) 打成 fib(n)
  3. 以為每層共用同一個 n → 其實每個 frame 各有一份，改了不會互相影響
  4. 把呼叫次數當成 Stack 深度 → 誤以為 fib(30) 會 Stack Overflow（實際上只有 30 層，是「慢」不是「爆」）
  5. 迭代版 push 順序沒反過來 → 河內塔步驟順序整個顛倒

一個 Frame 裡到底裝了什麼？

┌──────────────────────────────┐ │ fact(3) ← 一個 Stack Frame │ ├──────────────────────────────┤ │ 參數：n = 3 │ ← 每一層都有自己的 n，互不干擾 │ 區域變數：（這題沒有） │ │ 回傳位址：回到 fact(4) 的第 5 行 │ ← 最關鍵！算完要知道回哪裡 └──────────────────────────────┘
為什麼每層的 n 不會互相蓋掉？因為 n 存在各自的 frame 裡，不是同一個變數。
為什麼算完知道要回哪？因為 frame 裡存了「回傳位址」。這就是 Stack 存在的理由 —— 後呼叫的函式一定先結束，完美的 LIFO。

📥 呼叫時（push）

  • 配置一塊新 frame
  • 把參數複製進去
  • 記下「回來時要跳到哪一行」
  • Stack 指標往上移

📤 return 時（pop）

  • 把回傳值交給下面那層
  • 整塊 frame 直接丟棄（區域變數瞬間消失）
  • 跳回記下的那一行繼續執行
  • Stack 指標往下移
💥 Stack Overflow 是怎麼發生的： Stack 的大小是固定的（CPython 預設遞迴上限 1000 層，C 的執行緒堆疊常見是 1 MB）。
忘了寫基底條件 → 一直 push 卻永遠不 pop → RecursionError / Segmentation fault
所以寫遞迴的第一件事永遠是：先寫終止條件，再寫遞迴呼叫。

三個範例的呼叫堆疊長相完全不同

範例Stack 形狀呼叫次數最大深度
階乘 fact(n)一條直線（每層只呼叫 1 次）nn
費氏 fib(n)樹狀爆炸（每層呼叫 2 次）≈ 2ⁿn
河內塔 hanoi(n)樹狀，但每個節點都做事2ⁿ⁺¹−1n+1（最底下那層 n=0 也算一個 frame）
重點：呼叫次數 ≠ 最大深度。
fib(30) 要呼叫 270 萬次，但 Stack 最深只有 30 層 —— 因為左邊那棵子樹算完就被 pop 掉了， 不會同時存在。
這也解釋了為什麼 fib 慢的原因是重複計算（時間），不是記憶體爆掉（空間）。

程式碼

# 階乘：一條直線的遞迴 def fact(n): if n <= 1: return 1 # 基底條件 —— 沒有它就 stack overflow return n * fact(n - 1) # 等下面算完，我才能乘 # 費氏：一次呼叫兩次 → 呼叫次數爆炸 def fib(n): if n < 2: return n return fib(n-1) + fib(n-2) # fib(n-1) 完全跑完並 pop 掉，才輪到 fib(n-2) # 河內塔：兩次遞迴中間夾一個動作 def hanoi(n, a, c, b): # 把 n 個盤子從 a 移到 c，b 當中繼 if n == 0: return hanoi(n-1, a, b, c) # 上面 n-1 個先搬去中繼柱 print(f"移動盤子 {n}: {a} → {c}") # 最大的盤子搬過去 hanoi(n-1, b, c, a) # 中繼柱那疊再搬回來蓋上
把遞迴改成迴圈，其實就是「自己拿一個 list 當 Stack」。 電腦本來替你做的事，你自己做一遍：
stack = [(n, a, c, b)] → while stack: 取出一個任務，展開成更小的任務再 push 回去
這正是你在 河內塔教材「非遞迴解法」那一節做的事，也是 DFS 迷宮把遞迴換成 list.pop() 的原因。
