📋 題目解說

運算式求值（Expression Evaluation）

給你一個字串形式的中序運算式，請算出它的值。

  • 可能出現：非負數（含小數、多位數）、+ - * / ^、小括號
  • 優先級：^ > * / > + -；^ 是右結合，其餘左結合
  • 括號可以任意巢狀，深度不限
  • 不可以用 Python 的 eval()（那等於沒寫）
輸入"3+4*2/(1-5)^2" 輸出3.5　　（= 3 + 8 / 16） 輸入"2^3^2" 輸出512　　（= 2^(3^2)，不是 (2^3)^2 = 64） 輸入"10-2-3" 輸出5　　　（= (10-2)-3，不是 10-(2-3) = 11）

邊界情況要考慮：括號不配對、運算子過多（1++2）、除以零、多位數 123 不能被拆成 1 2 3。

這題到底難在哪？

難點只有一個：你不能從左往右邊讀邊算。
讀到 3 + 4 的時候，還不能做加法 —— 因為下一個字元可能是 *， 那樣 4 就得先跟後面的數字相乘。
同理，讀到 ( 之後的所有運算，都得等到 ) 出現才知道能不能算。

換句話說：你手上會累積一堆「還沒輪到、正在等待」的運算子，而且一定是最後等的那個先被處理。
這就是 LIFO —— 題目本身在跟你要一個 Stack。
如果你硬要一次搞定…會遇到的麻煩
從左到右直接算3+4*2 會算成 14（錯，應該是 11）
用 if 判斷優先級括號一巢狀就爆炸，深度不限沒辦法寫死
用正規表示式巢狀括號不是正規語言，理論上就做不到
遞迴下降 parser可行，但那其實是用呼叫堆疊做同一件事（見 Stack遊戲3）

為什麼這題重要：編譯器、直譯器、Excel 公式、SQL 的 WHERE 條件、計算機 App， 骨子裡跑的都是這一段。它也是資料結構期中考出現率最高的 Stack 應用題。

🧠 解法解說

第 0 步：先承認暴力解不好寫

暴力想法是「找最內層的括號，算完把結果塞回字串，重複到沒有括號」。 能動，但要不斷做字串切割與拼接，一趟只解決一個運算子 → O(n²)，而且程式碼又臭又長、極難除錯。

第 1 步：關鍵洞察 —— 把「決定順序」和「實際計算」拆開

一次要同時處理「優先級 + 括號 + 計算」太難。
拆成兩趟，每一趟都變成小學生等級的簡單問題：
　① 中序 → 後序：只重排符號，完全不做算術
　② 後序求值：從左到右照著做，完全不管優先級
兩趟都是 O(n)，加起來還是 O(n)，而且各自都只有十幾行。

第 2 步：階段一的四條規則（只有四種 token）

  1. 遇到數字 → 直接輸出。
    理由：數字的位置在後序式裡不會變，它不用等任何人。
  2. 遇到 ( → 直接壓入 Stack。
    理由：它是一道牆。牆上面的運算子還沒結案前，牆下面的一律不准彈出。
  3. 遇到 ) → 一路彈出到碰見 (，再把這對括號丟掉。
    理由：括號內的帳現在可以結清了，而括號本身在後序式裡不需要存在。
  4. 遇到運算子 op → 先把 Stack 頂端「該比它先算」的通通彈出，再把 op 壓進去。
    「該比它先算」＝ 頂端優先級更高，或 一樣高且 op 是左結合。

讀完整串之後，把 Stack 剩下的全部倒出來 —— 這就是完整的演算法。

第 3 步：手算一次 3+4*2（階段一）

讀到判斷動作Stack（左→右＝底→頂）輸出
3數字直接輸出（空）3
+Stack 是空的push+3
4數字直接輸出+3 4
*top 是 +，1 < 2 不該先算不彈出，直接 push+ *3 4
2數字直接輸出+ *3 4 2
（讀完）收尾pop *+3 4 2 *
（讀完）收尾pop +（空）3 4 2 * +

注意第 4 列：* 比 + 晚進 Stack，卻會比 + 早出來 —— 「晚進早出」就是 LIFO 的定義，優先級規則被 Stack 天然地實現了。

第 4 步：手算一次 3 4 2 * +（階段二）

讀到動作Stack
3數字 → push3
4數字 → push3 4
2數字 → push3 4 2
*pop 出 2、再 pop 出 4 → 4 × 2 = 8 → push 83 8
+pop 出 8、再 pop 出 3 → 3 + 8 = 11 → push 1111 ← 答案

整段求值沒有出現任何一次優先級判斷，也沒有括號 —— 因為順序在階段一就決定好了。

第 5 步：右結合為什麼要特別處理

算式遇到第二個運算子時後序結果值
10-2-3同級 + 左結合 → 彈出前一個 −10 2 - 3 -5 ✅
2^3^2同級 + 右結合 → 不彈出，一起等2 3 2 ^ ^512 ✅

差別就在規則 4 那個 and t not in RIGHT。 拿掉它，2^3^2 會算成 64（錯）；多加它到 - 上，10-2-3 會算成 11（錯）。

第 6 步：複雜度

時間空間為什麼
階段一 轉後序O(n)O(n)每個 token 最多被 push 一次、pop 一次
階段二 求值O(n)O(n)同上，掃一遍不回頭
合計O(n)O(n)最壞情況（全是左括號）Stack 會存下整串

雖然規則 4 裡面有一個 while 迴圈長得像 O(n²)，但每個運算子一生只會被彈出一次， 所以總彈出次數 ≤ n —— 這叫攤還分析（amortized analysis）， 在 Stack遊戲2 的單調堆疊裡會再用到同一套論證。

❌ 五個最常見的錯誤（改作業實測排行）
  1. a = pop() 寫在 b = pop() 前面 → 減法、除法、次方全部左右顛倒
  2. 規則 4 忘了排除 ( → 左括號被優先級規則彈出，括號整個失效
  3. 條件寫成 >= 卻沒排除右結合 → 2^3^2 變 64
  4. 迴圈結束忘了把 Stack 倒空 → 最後幾個運算子憑空消失
  5. tokenize 一次只讀一個字元 → 12+3 被讀成 1、2、+、3

為什麼要脫褲子放屁，先轉成後序？

😵 中序（人看的）3 + 4 * 2

  • 要記「先乘除後加減」的優先級
  • 要處理括號
  • 眼睛得跳來跳去，不能從左讀到右一次算完
  • 電腦要邊讀邊回頭 → 很難寫

😎 後序（電腦看的）3 4 2 * +

  • 完全不需要括號，也不需要優先級規則
  • 從左讀到右一次就算完，永不回頭
  • 求值只要一個 Stack、10 行程式
  • JVM、Python 虛擬機、HP 計算機都是這樣算的
核心洞察：優先級高的運算子要「晚進早出」—— 這正是 LIFO。
看到 + 之後又來個 *，* 得先算 → 它比 + 晚進 Stack、卻比 + 早出來。
Stack 不是「用來存東西」，而是用來記住「還沒輪到的事情」。

優先級與結合律

運算子優先級結合律例子
^ 次方3（最高）右結合 →2^3^2 = 2^(3^2) = 512
* /2左結合 ←8/4/2 = (8/4)/2 = 1
+ -1（最低）左結合 ←10-2-3 = (10-2)-3 = 5
(進 Stack 後視為最低—像一道牆，擋住彈出

兩段程式碼

# ① 中序 → 後序（調度場演算法 Shunting-yard） PREC = {'+':1, '-':1, '*':2, '/':2, '^':3} RIGHT = {'^'} # 右結合的運算子 def to_postfix(tokens): out, stack = [], [] for t in tokens: if is_number(t): out.append(t) # 數字直接輸出 elif t == '(': stack.append(t) # 括號進場 elif t == ')': while stack[-1] != '(': # 一路彈到配對的 ( 為止 out.append(stack.pop()) stack.pop() # 丟掉 ( else: while (stack and stack[-1] != '(' and (PREC[stack[-1]] > PREC[t] or (PREC[stack[-1]] == PREC[t] and t not in RIGHT))): out.append(stack.pop()) # 比我大的先出去 stack.append(t) while stack: out.append(stack.pop()) # 收尾：全部倒出來 return out
# ② 後序求值 —— 只有 10 行，而且沒有任何優先級判斷 def eval_postfix(tokens): stack = [] for t in tokens: if is_number(t): stack.append(float(t)) else: b = stack.pop() # 注意順序！後彈出的是左運算元 a = stack.pop() stack.append(apply(a, b, t)) return stack[0] # 最後剩下的唯一一個就是答案
最容易錯的一行：b = pop() 要寫在 a = pop() 前面。
因為先進 Stack 的是左運算元，後彈出來的才是它。+ * 看不出差別， 但 10 3 - 寫反就變成 3-10 = -7。這是期中考最愛考的陷阱。
