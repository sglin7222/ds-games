    括號配對

    Stack 的 Hello World：驗證 {[()]} 有沒有配對。

    ⏱ 1 節課難度 ★Prompt執行教材-Stack.html（第 6 天）
    📘 開啟舊版教材第 6 天

    🎯 學習目標

    • 看出「配對」問題的共同結構：最近打開的，必須最先關閉
    • 能把演算法講成三句話：左括號 push、右括號 pop 比對、最後檢查是否為空
    🎮 課堂操作 — 先用人腦跑一次
    1. 黑板寫 { [ ( ] ) }，請學生逐字元判斷，並在旁邊畫出 Stack 內容
    2. 問：錯在第幾個字元？（第 4 個 ]，因為 top 是 (）
    3. 再寫 ( ( )，問：掃完都沒衝突，為什麼還是錯？（結束時 Stack 不空）
    兩個結束條件都要檢查，缺一不可：
    ・掃描中發現不匹配 → 錯（例：(]）
    ・掃完後 Stack 不是空的 → 錯（例：((）
    ・提早把 Stack 彈空又遇到右括號 → 錯（例：())）
    ✂️ 本站作業 Prompt
    用 Stack 寫一個括號檢查器 check(s)。 要求： 1. 支援三種括號 () [] {}，可任意巢狀 2. 回傳 (是否合法, 錯誤位置, 錯誤原因)，不要只回傳 True/False 3. 三種錯誤都要能分辨： - 類型不匹配："(]" - 右括號太多："())" - 左括號沒關："((" 4. 括號以外的字元一律忽略，例如 "if (a[0] > 1) { b = 2; }" 測完後請回答：為什麼這題非用 Stack 不可？用「巢狀」兩個字解釋。

    ✅ 檢核點

    1. "([)]" 為什麼不合法？請畫出當下的 Stack
    2. 如果只用一個計數器（左括號 +1、右括號 −1）取代 Stack，什麼情況會誤判？
    3. HTML 標籤 <div><p></div></p> 為什麼也是同一題？

    第一次遇到「非 Stack 不可」的題目：電腦其實看不懂 3+4*2。

    🎮 開啟遊戲：運算式計算機

    🎯 學習目標

    • 說得出為什麼不能從左往右邊讀邊算
    • 能手動把中序式轉成後序式（不看程式碼）
    • 知道優先級與結合律怎麼變成程式裡的一個 while 條件
    • 能解釋 2^3^2 = 512 而不是 64
    🎮 課堂操作（照順序按）

    2. 把速度拉到最慢，按 ▶ 開始，看完 3+4*2/(1-5)^2 一整輪

    本站最重要的一句話：Stack 不是拿來「存資料」的，是拿來記住「還沒輪到的事情」。
    + 讀到了卻不能馬上算，因為後面可能有 * —— 它只好在 Stack 裡排隊等。

    實作一個支援 + - * / ^ 和括號的運算式計算機，用兩個 Stack。 分三個函式： 1. tokenize(s) -> 把 "3+4*2/(1-5)^2" 切成 token 串列（支援多位數與小數） 2. to_postfix(toks) -> 調度場演算法轉後序 3. eval_postfix(p) -> 用 Stack 求值 要求： - 優先級 ^ > * / > + -，其中 ^ 是右結合 - 每一步印出「目前 token / Stack 內容 / 輸出內容」的表格 - 用這四個式子驗證： 3+4*2/(1-5)^2 → 3.5 (1+2)*(3+4) → 21 2^3^2 → 512（不是 64） 10-2-3 → 5 寫完後回答兩題： ① 為什麼 2^3^2 是 512？程式碼裡哪一行決定了這件事？ ② 求值時為什麼 b = pop() 要寫在 a = pop() 前面？

    2. 後序式為什麼不需要括號？
    3. 整個演算法為什麼是 O(n) 而不是 O(n²)？（提示：每個 token 進出幾次）
    ⚠️ 常見卡關
    • 學生會問「為什麼不直接用 eval()」→ 回答：資安（任意程式碼執行）＋ 你的計算機規則可以自訂
    • 分不清「Stack 存運算子」和「Stack 存數字」是兩個不同階段的兩個 Stack
    • 把左括號當成一般運算子去比優先級 → 括號整個失效

    呼叫堆疊：遞迴的真面目 新遊戲

    揭曉：你寫的每一次函式呼叫，電腦都在偷偷 push 一個 frame。

    ⏱ 2 節課難度 ★★★Stack遊戲3-呼叫堆疊.html
    🎮 開啟遊戲：呼叫堆疊

    🎯 學習目標

    • 知道一個 frame 裡裝了什麼（參數、區域變數、回傳位址）
    • 能解釋「為什麼每層的 n 不會互相蓋掉」
    • 分得清呼叫次數與Stack 深度——這是本站的核心
    • 知道 Stack Overflow 為什麼會發生
    🎮 課堂操作（三個模式依序玩）
    1. 階乘模式：n=5 單步跑完。請學生注意「前半段一路 push、碰到基底才開始 pop」
    2. 問全班：答案是在什麼時候第一次出現的？（答：最深那層碰到基底條件時）
    3. 費氏模式：n=6 跑完，記下右下角兩個數字：總呼叫 25 次、最大深度 6
    4. 把 n 調到 8 再跑一次，記錄數字 → 呼叫次數暴增，深度只 +2
    5. 河內塔模式：n=3，觀察「兩次遞迴中間夾一個搬盤子動作」的節奏

    🔍 觀察任務：填完這張表，本站就懂一半

    模式n總呼叫次數最大深度你的結論
    階乘5　　　
    費氏6　　　
    費氏8　　　
    河內塔3　　　
    本站最重要的一句話：呼叫次數 ≠ Stack 深度。
    fib(30) 要呼叫 270 萬次，但 Stack 最深只有 30 層 —— 因為左子樹跑完就被 pop 光了，右子樹才開始。
    所以 fib 的病是「慢」（時間 O(2ⁿ)，靠 memo 解決），不是「爆」（空間只有 O(n)）。
    ✂️ 本站作業 Prompt
    幫我把「呼叫堆疊」變成看得見的東西。 寫一個裝飾器 @trace，套在任何遞迴函式上都能印出呼叫過程（用縮排表示深度）： → fact(3) → fact(2) → fact(1) ← fact(1) 回傳 1 ← fact(2) 回傳 2 ← fact(3) 回傳 6 要求： 1. 用全域變數記錄目前深度 2. 同時統計「總呼叫次數」與「最大深度」，結束後印出 3. 分別套到 fact(5)、fib(10)、hanoi(3) 上，做一張三者的比較表 4. 用 sys.getrecursionlimit() 說明 Python 的遞迴上限 最後回答：為什麼 fib(10) 的呼叫次數遠大於最大深度？

    ✅ 檢核點

    1. 畫出 fact(3) 的完整 push/pop 過程（6 個步驟）
    2. 忘記寫基底條件會發生什麼事？錯誤訊息叫什麼？
    3. 為什麼迴圈跑一億次不會 Stack Overflow，但遞迴一萬層就會？
    ⚠️ 常見卡關
    • 以為所有遞迴呼叫「同時存在」於 Stack 上 → 用費氏模式單步走給他看，左邊算完就消失了
    • 以為每層共用同一個變數 n → 指著畫面上每個 frame 各自的參數
    • 把「慢」跟「爆記憶體」混為一談

    河內塔

    同時出現兩種 Stack：三根柱子是 Stack，解法又靠呼叫堆疊。

    ⏱ 2 節課難度 ★★★河內塔遊戲-可互動.htmlPrompt執行教材-Stack應用-河內塔.html
    🎮 開啟遊戲：河內塔（可互動） 📘 開啟河內塔教材

    🎯 學習目標

    • 能講出三步法：搬 n−1 上去 → 搬最大的 → 再搬 n−1 回來
    • 能推導 T(n) = 2T(n−1) + 1 → 2ⁿ − 1
    • 看出「柱子只能動最上面那個」＝ Stack 的定義
    🎮 課堂操作
    1. 先讓學生用手玩 n=3，計時、記步數。多數人第一次會超過 7 步
    2. 再玩 n=4，讓他們崩潰一次（15 步）→ 此時才引入「三步法」
    3. 回到第 5 站的遊戲，切到河內塔模式，單步觀察遞迴怎麼分解
    4. 對照兩邊：畫面上的 frame 一層，就是「把 n−1 個交給下一層」一次
    教學重點：不要試著想「第一步該搬哪個」，那會卡死。
    遞迴思維是：假設 n−1 個已經有人會搬了，我只負責定義這一層怎麼拆成三步。
    這就是數學歸納法，也是所有遞迴題的通關密語。
    ✂️ 本站作業 Prompt
    用兩種方式解河內塔，並比較它們。 1. 遞迴版 hanoi(n, a, c, b)：印出每一步「移動盤子 k：X → Y」 2. 迭代版 hanoi_iter(n, a, c, b)：不准用 recursion， 自己拿一個 list 當 Stack，裡面存「還沒展開的任務」 要求： - 兩版對 n = 1~8 的輸出必須完全一致（寫程式自動比對） - 驗證步數等於 2^n - 1 - 印出迭代版每一步的 Stack 內容，讓我看見「自己管理 Stack」長什麼樣 - 用三根真的 list 模擬柱子，檢查全程沒有「大盤壓小盤」 最後回答： ① 迭代版 push 三個子任務時，為什麼順序要反過來寫？ ② 什麼情況下「自己管理 Stack」比遞迴好？

    ✅ 檢核點

    1. n=4 時最少要幾步？用公式算，不要用數的
    2. 傳說中 64 個金盤要搬多久？（一秒一步 → 約 5850 億年）
    3. 為什麼「不能大壓小」這條規則，會讓每根柱子自動變成一個 Stack？

    把第 5 站接起來：DFS 的遞迴寫法，用的就是呼叫堆疊； DFS 的迭代寫法，是你自己拿一個 list 當 Stack。
    兩種寫法完全等價 —— 差別只在「Stack 由誰管理」。這正是第 6 站河內塔的同一個結論。
    ✂️ 本站作業 Prompt
    寫一份走迷宮程式，同時支援 BFS 和 DFS，兩者只差一行。 maze = [ "S.#.......", ".#.###.##.", ".#.....#..", ".####.##.#", "........#E", ] S=起點 E=終點 #=牆 .=可走 要求： 1. 寫 solve(maze, mode)，mode 是 "bfs" 或 "dfs" 2. 兩種模式共用同一份程式碼，只有取出元素那一行不同 （deque.popleft() vs list.pop()） 3. 回傳 (路徑長度, 走訪格數, 路徑座標) 4. 把路徑印在迷宮上（用 * 標記） 5. 額外寫一個「遞迴版 DFS」，證明它和迭代版走訪順序一致 最後回答： ① 為什麼 BFS 保證最短、DFS 不保證？ ② 什麼情況下我該選 DFS？（提示：記憶體、只想知道有沒有路）

    ✅ 檢核點

    1. 同一個迷宮，為什麼 DFS 找到的路比較長？
    2. 迷宮很大時，哪一個比較省記憶體？為什麼？
    3. 把 DFS 的 pop() 換成 popleft()，程式還會不會找到路？（會，但變 BFS）

    單調堆疊 新遊戲

    最後一關，也是面試最愛考的一關：O(n²) 用 Stack 壓成 O(n)。

    ⏱ 2 節課難度 ★★★★Stack遊戲2-單調堆疊.html
    🎮 開啟遊戲：單調堆疊

    🎯 學習目標

    • 看出「柱狀圖最大矩形」和「每日溫度」是同一題
    • 能講出核心洞察：來了更矮的，前面比它高的就可以結算並丟掉
    • 知道為什麼 Stack 會自動保持單調（不是刻意維護的）
    • 能用攤還分析解釋「有 while 迴圈但仍是 O(n)」
    🎮 課堂操作（先溫度、後柱狀圖 —— 溫度比較好懂）
    1. 切到 🌡️ 每日溫度，跑經典測資，看答案格子一格一格被填滿
    2. 特別停在第 5 天（72°）：一次連續彈出兩個，問學生為什麼
    3. 切到 📊 柱狀圖最大矩形，跑 2,1,5,6,2,3，看紅色矩形怎麼被算出來
    4. 盯住右下角「總 push+pop」欄位：無論資料多長，它永遠 ≤ 2n
    5. 試 1,2,3,4,5（全遞增）→ 觀察哨兵 0 出場時把 Stack 一次清空

    🔍 觀察任務

    測資答案總 push+pop2n 是多少有沒有超過
    2,1,5,6,2,3　　12　
    1,2,3,4,5　　10　
    5,4,3,2,1　　10　
    4,4,4,4　　8　
    本站最重要的一句話：如果 j < i 而且 h[j] ≥ h[i]，那 j 永遠不可能再變成答案的候選 —— 既然如此，現在就把它結算掉、丟出 Stack。
    「單調」是這條規則的副產品，不是我們刻意維護的性質。這句話聽懂，整題就通了。
    ✂️ 本站作業 Prompt
    先用暴力解，再用單調堆疊優化「柱狀圖中最大的矩形」。 步驟： 1. 寫 O(n²) 暴力解 brute(h) 2. 寫 O(n) 單調堆疊解 fast(h)（用哨兵 0 收尾） 3. 隨機測試 1000 組陣列，驗證兩者答案完全相同 4. 用 n = 10000 實測兩者耗時，印出加速倍數 測資要包含：[2,1,5,6,2,3]（答案 10）、全部一樣高、遞增、遞減、只有一根 接著用同一個模板解「每日溫度」，並做一張表比較兩題的四個空格： (a) Stack 存什麼 (b) 單調方向 (c) 彈出條件 (d) 彈出時做什麼 最後回答： ① Stack 為什麼存索引而不是存高度？ ② 有 while 巢狀迴圈，為什麼整體還是 O(n)？

    ✅ 檢核點

    1. 手算 [2,1,5,6,2,3]，寫出彈出第 2 根（高 5）時的左界、右界、面積
    2. 沒有哨兵的話，[1,2,3] 會回傳什麼？為什麼錯？
    3. 「每個元素最多 push 一次 pop 一次」這句話，為什麼能證明是 O(n)？
    ⚠️ 常見卡關（這站掉隊最多，慢慢來）
    • 存高度不存索引 → 算不出寬度。一律存索引
    • 左界寫成 stack[-1] 而不是 stack[-1] + 1
    • 看到 while 就以為是 O(n²) → 請他打開遊戲盯著 push+pop 計數器
    • 如果全班卡住，退回第 4 站的比喻：Stack 裝的是「還沒結案的東西」
